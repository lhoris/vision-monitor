# 관리형 데이터 그리드 UX 설계 원칙

## 1. 기본 철학

Vision Monitor의 관리형 데이터 그리드는 최대한 Excel 친화적으로 설계한다. 사용자는 그리드를 단순 목록이 아니라 대량 데이터를 빠르게 훑고, 선택하고, 복사하고, 필요한 셀만 수정하는 작업 표면으로 인식해야 한다.

이 원칙은 사용자 관리, 카메라 관리, 권한 정책 관리처럼 행과 열 중심으로 데이터를 다루는 관리 화면에 우선 적용한다. 영상 타일 배치처럼 공간 배치가 핵심인 라이브 대시보드 그리드는 이 문서의 적용 대상이 아니다.

사용자 관리 화면에서 구현한 `frontend/src/components/UserManagement/UserManagementGrid.tsx`는 관리형 데이터 그리드의 기준 구현으로 간주한다. 이후 행/열 기반 관리 화면을 만들 때는 사용자 관리 그리드의 구조, 상호작용, footer bar, 컬럼 필터 행, 셀 선택/편집/복사 방식을 먼저 따른다. 화면별 특수 요구가 있더라도 이 기준과 다른 동작을 도입할 때는 명세에 차이와 이유를 기록해야 한다.

## 2. 상호작용 원칙

- 단일 클릭은 셀 선택에 사용한다.
- 마우스 좌클릭 드래그는 셀 범위 선택에 사용한다.
- `Shift+클릭`은 기존 선택 시작점에서 클릭한 셀까지 범위를 확장한다.
- `Ctrl+C` 또는 `Cmd+C`는 선택한 셀 범위를 TSV 형식으로 복사한다.
- 복사한 데이터는 Excel, Google Sheets, 텍스트 편집기에 행과 열 구조를 유지한 채 붙여넣을 수 있어야 한다.
- 텍스트 셀은 더블클릭, `Enter`, `F2`로 기존 값을 편집한다.
- 텍스트 셀이 선택된 상태에서 문자를 입력하면 해당 문자로 편집을 시작한다.
- `Escape`는 편집 취소 또는 편집 모드 종료에 사용한다.
- `Enter`는 편집 확정 또는 다음 편집 흐름 진입에 사용한다.
- 빈 셀은 `-` 같은 placeholder를 표시하지 않고 비워 둔다.

## 3. 편집 원칙

- 평상시 셀은 입력 컨트롤이 아니라 값처럼 보여야 한다.
- 편집 모드에 들어갈 때만 `input`, `select`, date picker 같은 editor를 표시한다.
- 표시 모드와 편집 모드는 같은 셀 높이, padding, border model을 사용해 행 높이와 컬럼 폭이 흔들리지 않아야 한다.
- 선택형 셀은 화면 성격에 따라 단일 클릭 편집을 허용할 수 있지만, 셀 범위 선택과 충돌하면 더블클릭 또는 `Enter/F2` 편집을 우선한다.
- 필수값 오류, 형식 오류, 중복 오류는 문제가 있는 셀 또는 행에서 확인 가능해야 한다.
- 저장 실패 시 사용자가 입력한 변경분은 유지되어야 한다.

## 4. 필터와 검색 원칙

- 컬럼별 필터는 그리드 헤더 바로 아래 필터 행으로 제공한다.
- 필터 행은 기본 노출이 아니라 우클릭 메뉴, 그리드 옵션, 또는 화면 정책으로 표시/숨김을 제어할 수 있어야 한다.
- 텍스트 컬럼은 텍스트 필터를 기본으로 사용한다.
- 상태, 역할, 사용 여부처럼 값 후보가 제한된 컬럼은 select 필터를 사용한다.
- 별도 상단 검색/필터 바는 화면별 특수 목적이 있을 때만 둔다.

## 5. 툴바와 푸터 원칙

- 행 추가, 행 복제, 행 삭제, 새로고침 같은 행 단위 조작은 그리드 footer 왼쪽에 배치한다.
- 건수, 선택 건수, 변경 건수, 표시 건수, 페이지 이동은 그리드 footer 오른쪽에 배치한다.
- 저장, 변경 취소, 잠금, 잠금 해제 같은 업무 액션은 footer 기본 버튼으로 두지 않는다. 화면 정책상 필요할 때 별도 액션 영역 또는 context menu에서 제공한다.
- footer 버튼은 그리드 생성 옵션으로 표시/숨김을 제어할 수 있어야 한다.

## 6. 시각 설계 원칙

- 셀 경계는 가로선과 세로선을 모두 명확히 표시한다.
- 헤더와 필터 행은 본문과 구분되되, 같은 그리드의 일부로 보여야 한다.
- 선택 셀과 선택 범위는 배경색과 안쪽 테두리로 명확히 표시한다.
- 편집 중인 셀은 선택 범위보다 우선적으로 식별되어야 한다.
- 셀 안의 editor는 과도하게 둥근 form control처럼 보이지 않아야 하며, 셀 안에 자연스럽게 들어간 형태여야 한다.
- 긴 텍스트는 셀 폭을 깨지 않으며, 화면 정책에 따라 말줄임 또는 가로 스크롤로 처리한다.

## 7. 구현 기준

- Tabulator를 사용하는 화면은 `selectableRange`, `selectableRangeRows`, `selectableRangeColumns`, `clipboard` 관련 옵션을 우선 검토한다.
- 직접 HTML table로 구현하는 화면도 이 문서의 Excel 친화 상호작용을 동일하게 제공해야 한다.
- 새 관리형 그리드를 만들 때는 사용자 관리 그리드를 기준 구현으로 삼고, 이 문서를 먼저 확인한다. 화면별 명세에는 이 원칙에서 벗어나는 부분만 별도로 기록한다.
- 그리드 공통 컴포넌트는 사용자 관리 그리드의 동작을 기준으로 추출하며, 선택, 편집, 필터, 복사, footer action bar를 옵션화해 화면별 중복 구현을 줄여야 한다.

## 8. 기준 구현 체크리스트

새 관리형 그리드는 최소한 다음 기준을 만족해야 한다.

- 사용자 관리 그리드와 동일한 셀 선택, 범위 선택, `Shift+클릭`, 복사 동작을 제공한다.
- 사용자 관리 그리드와 동일한 더블클릭, `Enter/F2`, 문자 입력 편집 진입 규칙을 제공한다.
- 컬럼 필터 행은 헤더 아래에 붙고, 표시 여부는 그리드 옵션 또는 context menu로 제어한다.
- 행 추가, 행 복제, 행 삭제, 새로고침은 footer 왼쪽에 배치한다.
- 선택 건수, 변경 건수, 총 건수, 표시 건수, 페이징은 footer 오른쪽에 배치한다.
- 표시 모드와 편집 모드 사이에서 행 높이와 컬럼 폭이 흔들리지 않는다.
- 빈 셀은 공백으로 표시한다.
- 화면 특화 동작은 기준 구현을 확장하되, 기준 상호작용을 깨지 않아야 한다.
