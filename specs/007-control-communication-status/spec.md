# 기능 명세서: 제어 연동 통신 현황

**기능 브랜치**: `007-control-communication-status`

**작성일**: 2026-08-17

**상태**: 초안

**변경 추적**: 문서 변경 이력은 Git 커밋 이력을 기준으로 한다.

**입력**: 왼쪽 사이드바 관리자 메뉴 순서에 따라 "제어 연동 통신 현황" 기능명세서 작성

> **기능 개요 - Agent 요약**
>
> 제어 연동 통신 현황은 관리자 권한 사용자가 Vision Monitor와 외부 제어 시스템 사이의 연동 상태를 점검하는 화면이다. 관리자는 제어 명령 전달, 응답 수신, 자동 대응 가능 여부처럼 설비 제어와 연결된 통신 상태를 확인하고 장애 또는 지연 대상을 빠르게 찾을 수 있어야 한다. 이 기능은 상태 조회와 점검에 집중하며, 실제 제어 명령 실행이나 제어 정책 편집은 포함하지 않는다.

## 2. 기능 요구사항 *(필수)*

### 기능 요구사항

- **FR-001**: 관리자 권한 사용자는 관리자 메뉴에서 제어 연동 통신 현황 화면에 진입할 수 있어야 한다.
- **FR-002**: 관리자 권한이 없는 사용자는 해당 메뉴와 화면에 접근할 수 없어야 한다.
- **FR-003**: 시스템은 제어 연동 대상 목록과 현재 통신 상태를 표시해야 한다.
- **FR-004**: 시스템은 각 대상의 상태를 정상, 지연, 장애, 확인 불가로 구분해야 한다.
- **FR-005**: 시스템은 연동 대상명, 연동 구분, 관련 공정/설비, 마지막 정상 응답 시각, 최근 점검 결과를 표시해야 한다.
- **FR-006**: 사용자는 상태, 공정, 연동 구분 조건으로 목록을 필터링할 수 있어야 한다.
- **FR-007**: 사용자는 특정 연동 대상을 선택해 상세 상태와 최근 점검 이력을 확인할 수 있어야 한다.
- **FR-008**: 시스템은 장애 또는 지연 상태의 제어 연동 대상 수를 요약해 표시해야 한다.
- **FR-009**: 사용자는 선택한 대상의 상태를 수동으로 다시 확인할 수 있어야 한다.
- **FR-010**: 시스템은 제어 명령 실행 가능 여부와 통신 상태를 혼동하지 않도록 구분해 표시해야 한다.
- **FR-011**: 시스템은 목록 없음, 필터 결과 없음, 상태 조회 실패를 서로 구분해 표시해야 한다.
- **FR-012**: 시스템은 이 화면에서 실제 설비 제어 명령을 실행하지 않아야 한다.

## 3. 제외 범위 *(필수)*

- 실제 설비 제어 명령 실행은 제외한다.
- 제어 정책 생성/수정/삭제는 제외한다.
- 외부 제어 시스템과의 실제 연동 구현은 제외한다.
- 제어 이력 장기 저장과 감사 리포트는 제외한다.
- 알람 정책 설정과 자동 조치 규칙 관리는 제외한다.

## 4. UI/UX 요구사항

- **UX-001**: 정상/지연/장애 상태는 색상과 텍스트를 함께 사용해 구분해야 한다.
- **UX-002**: 제어 가능 여부와 통신 정상 여부는 별도 정보로 표시되어야 한다.
- **UX-003**: 목록, 필터, 상세 영역의 관계가 명확해야 한다.
- **UX-004**: 수동 재확인 중과 완료 상태가 명확해야 한다.
- **UX-005**: theme1, theme2, theme3에서 상태와 상세 텍스트가 읽을 수 있어야 한다.

## 5. 필요한 정보

- 관리자 권한 여부

## 6. 사용자 시나리오 및 테스트 *(필수)*

### 사용자 스토리 1 - 제어 연동 상태 확인 (우선순위: P1)

관리자는 제어 연동 통신 현황 화면에서 전체 제어 연동 상태를 확인한다.

**관련 기능 요구사항**: FR-001, FR-002, FR-003, FR-004, FR-008

**이 우선순위의 이유**: 제어 연동 장애는 자동 대응과 설비 운영 판단에 직접 영향을 준다.

**독립 테스트**: 관리자 계정은 화면과 상태 요약을 볼 수 있고 비관리자 계정은 접근할 수 없는지 확인한다.

**허용 시나리오**:

1. **Given** 관리자 권한 사용자가 로그인되어 있다, **When** 제어 연동 통신 현황 메뉴를 선택한다, **Then** 상태 요약과 연동 대상 목록이 표시된다.
2. **Given** 장애 대상이 존재한다, **When** 화면 상단 요약을 확인한다, **Then** 장애 수가 목록과 일치한다.

### 사용자 스토리 2 - 장애 대상 필터링 (우선순위: P1)

관리자는 장애 또는 지연 상태인 제어 연동 대상만 좁혀 본다.

**관련 기능 요구사항**: FR-005, FR-006, FR-011

**이 우선순위의 이유**: 운영 중에는 정상 대상보다 이상 대상을 빠르게 찾는 것이 중요하다.

**독립 테스트**: 상태/공정 필터 적용과 초기화가 목록에 반영되는지 확인한다.

**허용 시나리오**:

1. **Given** 여러 연동 대상이 표시되어 있다, **When** 장애 필터를 선택한다, **Then** 장애 대상만 표시된다.
2. **Given** 필터 결과가 없다, **When** 목록을 확인한다, **Then** 필터 결과 없음 메시지가 표시된다.

### 사용자 스토리 3 - 상세 점검과 재확인 (우선순위: P2)

관리자는 특정 연동 대상을 선택해 상세 상태를 확인하고 수동 재확인을 실행한다.

**관련 기능 요구사항**: FR-007, FR-009, FR-010, FR-012

**이 우선순위의 이유**: 상태 이상 확인 후 실제 조치 전에 상세 근거가 필요하다.

**독립 테스트**: 상세 선택, 수동 재확인, 제어 명령 미실행 경계가 확인되는지 검증한다.

**허용 시나리오**:

1. **Given** 목록이 표시되어 있다, **When** 사용자가 연동 대상을 선택한다, **Then** 상세 상태와 최근 점검 이력이 표시된다.
2. **Given** 상세 상태가 표시되어 있다, **When** 사용자가 수동 재확인을 실행한다, **Then** 확인 중 상태와 완료 결과가 표시된다.

### 엣지 케이스

- 비관리자가 직접 route에 접근하면 화면 내용을 볼 수 없어야 한다.
- 상태 조회가 실패해도 화면은 실패 상태와 재시도 가능성을 보여야 한다.
- 제어 가능 여부가 불명확한 대상은 확인 불가로 표시되어야 한다.

## 7. 성공 기준 *(필수)*

### 측정 가능한 결과

- **SC-001**: 관리자는 2번 이하의 조작으로 화면에 진입할 수 있다.
- **SC-002**: 관리자는 3초 이내에 장애 또는 지연 존재 여부를 판단할 수 있다.
- **SC-003**: 관리자는 3개 이하의 필터 조작으로 원하는 대상을 찾을 수 있다.
- **SC-004**: 상세 선택 후 1초 이내에 점검 정보가 표시된다.
- **SC-005**: 비관리자는 메뉴와 화면 내용을 볼 수 없다.

## 8. 가정 및 미정 사항

### 가정

- MVP는 mock 데이터 기준으로 진행한다.
- tester 계정은 관리자, tester1 계정은 비관리자 기준으로 검증한다.
- 실제 설비 제어는 안전상 별도 기능으로 분리한다.

### 미정 사항

- 실제 제어 연동 대상 분류와 명칭은 운영 시스템 계약 확정 후 조정한다.
