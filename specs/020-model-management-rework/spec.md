# 모델 관리 대개편 명세

## 문서 상태

핵심 목표와 화면 방향을 정의한 초기 명세입니다. 상세 데이터 모델, API 계약, 상태 전이, 권한, 오류 처리 및 구현 작업은 후속 요구사항 정리 후 확정합니다.

## 핵심 목표

모델 관리 화면은 관리자가 AI 모델 프로세스가 실행 중인 VM과 해당 VM에서 동작하는 Python 프로세스를 한눈에 모니터링하고 제어하기 위한 운영 화면입니다.

관리자는 다음 업무를 수행할 수 있어야 합니다.

- AI 모델 프로세스가 실행 중인 VM의 상태 확인
- VM별 Python AI 모델 프로세스 목록과 실행 상태 확인
- Python 프로세스의 실행, 중지, 재시작 제어
- 모델 프로세스 설정값 확인 및 변경
- VM 또는 프로세스 장애 상황의 빠른 식별

## 화면 방향

### 기본 화면: 운영 대시보드

모델 관리 화면에 진입하면 관리자가 별도 조작 없이도 현재 운영 상태를 직관적으로 파악할 수 있도록 대시보드 형태로 보여줍니다.

- VM 1개를 하나의 시각적 컨테이너 또는 카드로 표현합니다.
- VM 컨테이너 안에 해당 VM에서 실행되는 AI 모델 프로세스를 배치합니다.
- VM 상태와 프로세스 상태를 구분하여 표시합니다.
- 프로세스별로 모델명, 공정 또는 업무 영역, 실행 상태, 최근 상태 갱신 시각을 표시합니다.
- 상태는 색상만으로 구분하지 않고 텍스트와 아이콘을 함께 사용합니다.
- VM 1개에 여러 Python 프로세스가 실행되는 운영 구조를 기본 사용 사례로 지원합니다.

### 대시보드 시각화 방향

대시보드는 일반 카드 목록이 아니라 **VM 컨테이너 안에 AI 모델 프로세스를 Honeycomb 형태로 배치하는 구조**를 기본 표현 방식으로 사용합니다.

- VM은 별도 사각형 박스로 감싸지 않고, VM 이름·주소·연결 상태를 Honeycomb 군집 상단의 그룹 라벨로 표시합니다.
- 같은 VM에 속한 프로세스 셀은 동일한 색상군으로 표시하여 별도 박스 없이 영역을 식별할 수 있게 합니다.
- VM 내부의 각 AI 모델 프로세스는 육각형 셀로 배치합니다.
- 육각형 셀에는 짧은 모델명 또는 공정명과 현재 프로세스 상태를 표시합니다.
- 상태는 실행 중, 중지, 처리 중, 오류를 색상·텍스트·아이콘으로 함께 표현합니다.
- 셀 hover 시 Python 경로, 최근 갱신 시각, 모니터링 상태, 제어 연동 상태를 툴팁으로 표시합니다.
- 셀 클릭 시 선택 상태를 유지하고 해당 프로세스의 상세 정보와 제어 영역을 표시합니다.
- 프로세스 수가 많아 최소 셀 크기를 유지할 수 없는 경우 `+ N개` 요약 셀을 표시합니다.
- VM이 여러 개인 경우 각 Honeycomb 군집을 화면 너비에 맞춰 반응형으로 배치하고, 군집 사이에는 최소한의 구분선과 여백만 둡니다.

이 방향은 Zabbix Honeycomb 위젯의 상태 셀, hover 상세, 선택 강조 패턴을 참고하되, VM별 사각 컨테이너 없이 색상과 라벨로 프로세스 군집을 표현합니다.

### 상세 정보 및 모달 사용 규칙

- 프로세스 셀 클릭: 대시보드 우측 또는 하단에 상세 패널을 표시합니다.
- 시작·중지·재시작: 공통 확인 모달을 먼저 표시하고 요청 이후 처리 상태를 셀과 상세 영역에 표시합니다.
- 모델 설정: 설정 편집 모달에서 서버 주소, Python 프로젝트 경로, 실행 관련 설정값을 수정합니다.
- 모니터링 이벤트 로그: 읽기 전용 로그 조회 모달로 표시합니다.
- VM 상세: VM 상태, 마지막 heartbeat, 하위 프로세스 요약을 상세 패널 또는 모달로 표시합니다.
- 모달을 닫아도 현재 VM 선택, 프로세스 선택, 필터, 보기 모드는 유지합니다.
- 선택 대상이 삭제되거나 필터 결과에서 제외되면 상세 패널을 닫고 선택 상태를 초기화합니다.

### 편집 화면: 그리드 기반 관리

모델 프로세스를 신규 입력하거나 기존 설정을 수정할 때는 그리드 형태를 사용합니다.

- VM 정보와 AI 모델 프로세스 정보를 행 단위로 확인하고 편집할 수 있어야 합니다.
- 반복 입력과 일괄 확인에 적합한 구조를 우선합니다.
- 신규 등록, 설정 수정, 활성화 또는 비활성화의 업무 흐름을 지원합니다.
- 대시보드에서 프로세스 또는 VM을 선택하면 해당 대상의 편집 화면으로 이동하거나 편집 모달을 열 수 있어야 합니다.
- 저장되지 않은 변경과 저장 완료 상태를 명확히 구분합니다.

대시보드와 그리드는 서로 대체되는 화면이 아니라 역할이 다른 두 가지 보기입니다. 대시보드는 운영 상태 확인과 제어를 위한 기본 보기이고, 그리드는 입력과 설정 관리용 보기입니다.

## 상태 및 제어

### VM 상태

VM의 연결 가능 여부와 상태 갱신 시점을 기준으로 VM 상태를 표시합니다. 구체적인 상태 코드와 장애 판정 기준은 Agent 및 백엔드 계약을 정의할 때 확정합니다.

### AI 모델 프로세스 상태

각 Python 프로세스는 최소한 다음 상태를 표현할 수 있어야 합니다.

- 실행 중
- 중지됨
- 시작 중
- 중지 중
- 재시작 중
- 오류 또는 확인 필요
- 상태 확인 불가

실제 상태는 VM Agent가 수집한 상태를 기준으로 하며, 관리자의 시작·중지·재시작 요청 상태와 구분합니다.

### 프로세스 제어

관리자는 프로세스 단위로 다음 제어를 요청할 수 있어야 합니다.

- 시작
- 중지
- 재시작

제어 요청은 즉시 실행 완료로 표시하지 않고 요청 중, 성공, 실패 또는 시간 초과 상태를 구분해야 합니다. 실제 원격 실행 방식은 Agent 연동 계약에서 정의합니다.

## 설정 관리

모델 프로세스 운영에 필요한 설정값을 확인하고 수정할 수 있어야 합니다. 기본 관리 대상은 다음과 같습니다.

- VM 식별 정보
- VM 주소 또는 접속 대상 정보
- Python 프로젝트 경로
- 실행 대상 모델 또는 프로세스 식별 정보
- 공정 또는 업무 영역
- 프로세스 활성화 여부
- 프로세스 실행에 필요한 추가 설정값

추가 설정값의 형식과 보안이 필요한 값의 저장 방식은 상세 설계에서 확정합니다.

## 데이터 및 연동 원칙

- VM Agent가 수집한 VM 및 Python 프로세스 상태를 DB에 저장하고 화면은 저장된 상태를 조회합니다.
- 관리자의 제어 요청과 Agent의 실제 처리 결과를 구분하여 저장합니다.
- 모델 설정과 상태 이력은 논리적 관계로 연결하며 물리적 FK 제약조건은 추가하지 않습니다.
- 모든 신규 테이블은 프로젝트 표준 Audit 컬럼 규칙을 따릅니다.
- 기존 `specs/009-model-management`의 구현 및 API는 호환 범위를 검토한 뒤 단계적으로 전환합니다.

## 사용자 스토리

### US1. VM 및 모델 프로세스 운영 현황 확인 (P1)

관리자는 모델 관리 화면에 진입하자마자 VM별 운영 상태와 VM 내부 AI 모델 프로세스의 현재 상태를 한눈에 확인할 수 있어야 합니다.

**독립 검증**: VM 1개와 여러 프로세스가 포함된 fixture를 로드했을 때 VM 컨테이너와 프로세스 상태가 대시보드에 표시되고, 실행·중지·오류·상태 확인 불가 상태가 텍스트와 시각 요소로 구분됩니다.

### US2. AI 모델 프로세스 제어 (P1)

관리자는 대시보드에서 특정 Python 프로세스를 선택해 시작, 중지, 재시작을 요청하고 요청 진행 상태와 처리 결과를 확인할 수 있어야 합니다.

**독립 검증**: 각 제어 버튼을 실행했을 때 확인 절차가 동작하고, 요청 중·성공·실패·시간 초과 상태가 fixture 또는 mock contract에 따라 표시됩니다.

### US3. VM 및 모델 프로세스 설정 관리 (P2)

관리자는 그리드 기반 편집 화면에서 VM과 모델 프로세스의 등록 정보를 입력·수정하고 저장 결과를 확인할 수 있어야 합니다.

**독립 검증**: 신규 등록과 기존 설정 수정 시 필수값 검증, 저장 성공, 저장 실패, 저장되지 않은 변경 상태가 독립적으로 확인됩니다.

### US4. 운영 대상 검색 및 상세 확인 (P2)

관리자는 VM 또는 모델 프로세스를 검색·필터링하고, 선택한 대상의 상세 설정과 최근 상태 갱신 정보를 확인할 수 있어야 합니다.

**독립 검증**: VM, 공정, 프로세스 상태 조건으로 필터링했을 때 대시보드와 그리드의 대상 목록이 일관되게 갱신되고, 결과 없음 상태가 표시됩니다.

## 작업 원칙

- 기존 `009-model-management` 문서는 비교 기준으로 보존합니다.
- 요구사항 확정 전에는 기존 구현을 임의로 삭제하거나 대규모 코드 변경을 시작하지 않습니다.
- 화면은 대시보드 우선으로 설계하고, 그리드는 관리 입력과 설정 수정에 집중합니다.
- 프로젝트의 감사 컬럼 규칙과 논리적 참조 규칙을 유지합니다.
