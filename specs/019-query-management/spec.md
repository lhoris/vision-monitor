# 쿼리 관리 메뉴 기능 명세

**기능 브랜치**: `019-query-management`

**작성일**: 2026-09-30

**상태**: 초안

**관련 기능**: [화면 확대 보기 메타데이터 Query 구성](../017-camera-focus-metadata-query/spec.md)

## 1. 기능 개요

관리자는 화면 확대 보기의 메타데이터 섹션에서 주기적으로 조회할 Query를 등록하고 관리한다. 등록된 Query는 Query ID로 메타데이터 섹션에 연결되며, 섹션은 설정된 주기에 따라 Query 결과를 조회해 텍스트, 그리드 또는 차트 형태로 표시한다.

Query 관리 메뉴는 Query 정의의 목록 조회, 신규 등록, 수정, 사용 여부 변경, 논리 삭제를 제공한다. 이 기능은 기존 메타데이터 기능이 사용하는 Query 정의 저장 구조를 관리하기 위한 운영자 화면이며, 별도의 Query 테이블을 추가하지 않는다.

## 2. 사용자 및 권한

- 관리자 또는 Query 관리 권한을 가진 사용자만 Query 관리 메뉴에 접근할 수 있어야 한다.
- 일반 사용자는 화면 확대 보기에서 활성 Query의 결과만 조회할 수 있고 Query SQL과 관리 기능에는 접근할 수 없어야 한다.
- 권한이 없는 사용자가 URL로 직접 접근해도 목록, 등록, 수정, 삭제 API가 실행되지 않아야 한다.

## 3. 범위

### 포함 범위

- Query 관리 메뉴 및 다국어 화면 문구
- Query 목록 조회와 검색
- Query 신규 등록
- Query 정보 수정
- Query 사용 여부 활성화/비활성화
- Query 논리 삭제 및 삭제 전 참조 확인
- 메타데이터 섹션에서 사용하는 Query ID 목록 제공
- Audit 정보 기록 및 조회

### 제외 범위

- Query를 자동으로 생성하거나 SQL을 AI로 작성하는 기능
- INSERT, UPDATE, DELETE, MERGE, DDL 등 데이터 변경 SQL 실행
- 사용자가 임의의 데이터베이스 연결을 추가하는 기능
- Query 결과를 별도 저장하거나 이력 화면에서 분석하는 기능
- 메타데이터 섹션의 추가·삭제·순서 변경 기능
- 실제 Query 실행 주기 자체를 Query 관리 메뉴에서 설정하는 기능

## 4. 핵심 용어

| 용어 | 정의 |
|---|---|
| Query ID | 메타데이터 섹션이 Query를 참조하기 위한 시스템 내 고유 식별자 |
| Query 명칭 | 관리자가 목록에서 Query를 식별하기 위한 표시명 |
| Query SQL | 메타데이터 조회에 사용하는 조회 전용 SQL 문장 |
| Query 파라미터 | 영상 소스 ID 등 실행 시 서비스가 허용된 값만 전달하는 입력값 |
| 활성 Query | 신규 메타데이터 섹션에서 선택하고 실행할 수 있는 Query |
| 논리 삭제 | 데이터를 물리 삭제하지 않고 `DATA_END_STATUS = 'Y'`로 종료하는 처리 |

## 5. 기능 요구사항

### 5.1 메뉴 및 목록

- **FR-001**: 시스템은 권한이 있는 사용자에게 관리자 메뉴의 Query 관리 메뉴를 제공해야 한다.
- **FR-002**: Query 관리 화면은 Query ID, Query 명칭, 설명, 사용 여부, 수정일시, 참조 상태를 목록으로 표시해야 한다.
- **FR-003**: 사용자는 Query ID 또는 Query 명칭으로 목록을 검색할 수 있어야 한다.
- **FR-004**: 사용자는 활성, 비활성, 전체 상태를 선택해 목록을 필터링할 수 있어야 한다.
- **FR-005**: 목록 기본 조회에는 논리 삭제된 Query가 포함되지 않아야 한다.
- **FR-006**: 목록이 비어 있거나 조회에 실패한 경우 사용자가 원인을 이해할 수 있는 빈 상태와 오류 상태를 표시해야 한다.

### 5.2 Query 등록 및 수정

- **FR-007**: 사용자는 Query ID, Query 명칭, 설명, Query SQL, 파라미터 정의, 조회 제한시간, 사용 여부를 입력해 Query를 등록할 수 있어야 한다.
- **FR-008**: Query ID는 저장된 활성 또는 비활성 Query와 중복될 수 없어야 하며, 중복 시 저장하지 않고 원인을 안내해야 한다.
- **FR-009**: Query ID는 공백을 포함하지 않는 영문 대소문자, 숫자, 점, 밑줄, 하이픈 조합으로 제한해야 한다.
- **FR-010**: Query 명칭과 Query SQL은 필수 입력이며, 입력값이 없거나 허용 길이를 초과하면 저장할 수 없어야 한다.
- **FR-011**: 등록 및 수정 화면은 SQL을 여러 줄로 입력하고 확인할 수 있는 편집 영역을 제공해야 한다.
- **FR-012**: 수정 시 Query ID는 변경할 수 없어야 한다. Query 식별자를 변경해야 하는 경우 신규 Query로 등록해야 한다.
- **FR-013**: 저장하지 않은 변경사항이 있는 상태에서 화면을 벗어나려 하면 변경사항 유실 여부를 확인해야 한다.

### 5.3 조회 전용 SQL 검증

- **FR-014**: 시스템은 Query SQL이 `SELECT` 또는 조회 목적의 `WITH` 문으로 시작하는지 검증해야 한다.
- **FR-015**: 시스템은 INSERT, UPDATE, DELETE, MERGE, DDL, 저장 프로시저 호출 및 다중 문장을 거부해야 한다.
- **FR-016**: Query 파라미터는 사전에 정의된 이름과 허용된 입력값만 사용할 수 있어야 하며, 임의 문자열 치환 방식으로 실행해서는 안 된다.
- **FR-017**: Query SQL 검증에 실패하면 저장하지 않고 실패 사유를 입력 영역 가까이에 표시해야 한다.
- **FR-018**: 조회 제한시간은 양수이며 시스템이 허용하는 최대값을 초과하지 않아야 한다. 기본값은 5초로 한다.
- **FR-019**: Query 관리 화면은 저장된 SQL 전문을 권한 있는 관리자에게만 표시해야 하며 일반 사용자의 Query 목록 응답에는 SQL 전문을 포함하지 않아야 한다.

### 5.4 활성화, 비활성화 및 논리 삭제

- **FR-020**: 사용자는 Query를 활성화하거나 비활성화할 수 있어야 한다.
- **FR-021**: 비활성 Query는 신규 메타데이터 섹션에서 선택할 수 없어야 한다.
- **FR-022**: 이미 메타데이터 섹션에서 참조 중인 Query를 비활성화할 수는 있어야 하며, 해당 섹션은 다음 조회 시 Query 비활성 상태를 표시해야 한다.
- **FR-023**: 사용자가 삭제를 요청하면 공통 확인 모달을 먼저 표시해야 한다.
- **FR-024**: 삭제는 물리 삭제가 아닌 논리 삭제로 처리해야 하며, 삭제된 Query는 일반 목록과 Query 선택 목록에서 제외해야 한다.
- **FR-025**: 메타데이터 섹션에서 현재 참조 중인 Query는 삭제할 수 없어야 하며, 먼저 참조를 해제해야 한다는 안내를 표시해야 한다.
- **FR-026**: 삭제된 Query ID는 과거 Audit 및 참조 이력 확인을 위해 데이터베이스에 남아 있어야 한다.

### 5.5 메타데이터 기능 연계

- **FR-027**: 화면 확대 보기 메타데이터 섹션의 Query 선택 목록은 삭제되지 않은 활성 Query만 제공해야 한다.
- **FR-028**: Query ID를 참조한 섹션은 Query 명칭과 실행 결과 계약을 유지해야 하며, Query 관리 화면에서 Query SQL을 수정해도 섹션의 Query ID 연결은 유지되어야 한다.
- **FR-029**: Query가 비활성화되거나 삭제되어 실행할 수 없는 경우 메타데이터 섹션은 다른 섹션의 표시를 중단하지 않고 해당 섹션에 오류 또는 이전 결과 상태를 표시해야 한다.
- **FR-030**: Query 관리 화면의 저장 성공은 메타데이터 섹션의 Query 선택 목록에 반영되어야 하며, 사용자는 새로고침 없이 확인할 수 있어야 한다.

### 5.6 Audit 및 데이터 규칙

- **FR-031**: Query 데이터는 기존 프로젝트의 Audit 항목을 테이블 최우선 컬럼 순서로 적용해야 한다.
- **FR-032**: Query 데이터의 논리적 참조는 허용하되 데이터베이스 물리 `FOREIGN KEY` 제약조건은 생성하지 않아야 한다.
- **FR-033**: Query 등록, 수정, 활성화, 비활성화, 논리 삭제 시 생성자·수정자·프로그램·시각 및 데이터 종료 상태를 기록해야 한다.
- **FR-034**: Query ID 중복, 참조 중 삭제, 권한 없음, SQL 검증 실패, 저장 실패를 서로 구분되는 사용자 메시지로 안내해야 한다.

## 6. 데이터 요구사항

Query 관리 기능은 기존 `TB_M26_METADATA_QUERY` 논리 테이블을 사용한다. 신규 테이블을 추가하지 않는다.

### 6.1 Query 정의 필드

- Query 식별자: 내부 PK
- Query ID: 논리적 고유 식별자
- Query 명칭
- Query 설명
- Query SQL Text
- Query 파라미터 정의
- Query 결과 Schema 또는 결과 필드 정의
- 조회 제한시간
- 사용 여부
- 프로젝트 표준 Audit 항목

### 6.2 데이터 처리 규칙

- Query ID의 중복과 참조 가능 여부는 서비스에서 검증한다.
- 물리 FK는 생성하지 않고 Query ID 참조는 논리적으로 관리한다.
- 논리 삭제된 Query는 기본 조회와 신규 참조 대상에서 제외한다.
- 기존 메타데이터 섹션이 참조하는 Query의 식별자는 유지한다.

## 7. 사용자 시나리오 및 테스트

### 시나리오 1 - Query 목록 확인 (P1)

관리자는 Query 관리 메뉴에 진입해 현재 등록된 Query와 사용 상태를 확인한다.

1. **Given** 등록된 활성, 비활성 Query가 존재한다.
2. **When** 관리자가 Query 관리 메뉴를 연다.
3. **Then** Query ID, 명칭, 사용 여부, 참조 상태가 목록에 표시된다.
4. **And** 논리 삭제된 Query는 기본 목록에 표시되지 않는다.

### 시나리오 2 - 조회 전용 Query 등록 (P1)

관리자는 메타데이터에서 사용할 새로운 조회 Query를 등록한다.

1. **Given** 관리자가 유효한 Query ID와 조회 전용 SQL을 입력한다.
2. **When** 저장을 실행한다.
3. **Then** Query가 활성 상태로 저장되고 Query 목록에 표시된다.
4. **And** 화면 확대 보기의 Query 선택 목록에서 해당 Query를 선택할 수 있다.

### 시나리오 3 - 위험 SQL 차단 (P1)

관리자가 데이터 변경 SQL 또는 여러 문장을 등록하려고 한다.

1. **Given** SQL에 INSERT, UPDATE, DELETE, DDL 또는 다중 문장이 포함되어 있다.
2. **When** 관리자가 저장을 실행한다.
3. **Then** 시스템은 저장을 거부하고 SQL이 조회 전용이어야 한다는 사유를 표시한다.

### 시나리오 4 - 참조 Query 삭제 방지 (P1)

관리자가 메타데이터 섹션에서 사용 중인 Query를 삭제하려고 한다.

1. **Given** 하나 이상의 메타데이터 섹션이 Query를 참조하고 있다.
2. **When** 관리자가 삭제를 요청하고 확인한다.
3. **Then** 삭제하지 않고 참조 중인 섹션을 먼저 해제해야 한다고 안내한다.

### 시나리오 5 - Query 비활성화 (P2)

관리자는 당장은 사용하지 않을 Query를 비활성화한다.

1. **Given** Query가 메타데이터 섹션에서 참조 중이다.
2. **When** 관리자가 Query를 비활성화한다.
3. **Then** 기존 연결 정보는 유지된다.
4. **And** 신규 섹션에서는 해당 Query를 선택할 수 없다.
5. **And** 기존 섹션에는 Query 비활성 상태가 표시된다.

## 8. 예외 및 경계 조건

- Query ID가 비어 있거나 형식에 맞지 않는 경우
- 이미 등록된 Query ID를 다시 등록하는 경우
- SQL이 비어 있거나 공백만 있는 경우
- SQL에 주석, 세미콜론, 다중 문장 또는 허용되지 않은 명령이 포함된 경우
- 정의되지 않은 파라미터가 SQL에 포함된 경우
- 제한시간이 0 또는 허용 최대값을 초과하는 경우
- 다른 관리자가 먼저 수정하거나 삭제한 경우
- 현재 메타데이터 섹션에서 참조 중인 Query를 삭제하는 경우
- 권한이 만료되거나 없는 사용자가 메뉴/API에 접근하는 경우
- 저장 중 네트워크 또는 서버 오류가 발생하는 경우

## 9. 성공 기준

- **SC-001**: 권한 있는 관리자는 3회 이내의 화면 조작으로 Query 등록 화면에 진입할 수 있다.
- **SC-002**: 유효한 Query 등록은 저장 후 2초 이내 목록과 메타데이터 Query 선택 목록에 반영된다.
- **SC-003**: 조회 전용이 아닌 SQL 등록 시도는 100% 저장 전에 차단된다.
- **SC-004**: 참조 중인 Query 삭제 시도는 100% 데이터 손실 없이 거부된다.
- **SC-005**: 일반 사용자는 Query SQL 전문이나 등록·수정·삭제 기능에 접근할 수 없다.
- **SC-006**: Query 오류 또는 비활성 상태가 다른 메타데이터 섹션의 표시와 조회를 중단시키지 않는다.

## 10. 가정 및 결정 사항

- Query 관리 메뉴는 관리자 메뉴의 통신 및 모델 설정 또는 기타 관리 영역에 배치한다. 최종 메뉴 위치는 기존 관리자 메뉴 체계와 함께 결정한다.
- Query 실행은 화면 확대 보기 메타데이터 기능에서 담당하며, Query 관리 화면은 정의 관리에 집중한다.
- Query SQL은 서버에서 검증하고 실행하며 브라우저는 관리 권한이 있는 경우에만 관리 화면에서 SQL을 입력·수정할 수 있다.
- 기존 `017-camera-focus-metadata-query`의 Query 결과 계약과 섹션 연계 규칙을 따른다.
- MVP에서는 조회 전용 검증과 관리 흐름을 우선하고, Query 실행 이력 및 성능 통계는 후속 범위로 둔다.
