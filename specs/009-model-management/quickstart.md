# Quickstart: 모델 관리

## 사전 조건

- 의존성 설치가 완료되어 있어야 한다.
- 로컬 실행은 프로젝트 원칙에 따라 `scripts\develop.bat`로 backend/frontend를 함께 실행한다.
- 빠른 정적 검증은 `frontend` 디렉토리에서 `npm run build`로 수행한다.

## 실행

```powershell
scripts\develop.bat
```

기대 응답:

- Frontend: `http://localhost:3000`
- Backend: `http://localhost:8080`
- Swagger: `http://localhost:8080/swagger-ui.html`

## 검증 시나리오

### 1. 관리자 접근과 화면 진입

1. `tester / tester123`으로 로그인한다.
2. 왼쪽 사이드바에서 `모델 관리`를 선택한다.
3. 공정 다중 선택 필터와 모델 관리 그리드가 표시되는지 확인한다.

직접 접근 기준 URL은 `http://localhost:3000/admin/model-management`이다. 기존 `http://localhost:3000/admin/model-restart`도 호환된다.

기대 결과:

- 비관리자 계정에서는 메뉴 또는 직접 route 접근이 차단된다.
- 화면 제목은 `모델 관리`로 표시된다.

### 2. 공정 다중 선택 필터

1. `ALL`을 선택한다.
2. 전체 모델 프로세스가 표시되는지 확인한다.
3. `가열`, `압연`을 선택한다.
4. 두 공정에 해당하는 모델만 표시되는지 확인한다.
5. `ALL`을 다시 선택한 뒤 개별 공정을 클릭한다.

기대 결과:

- 공정 UI는 탭처럼 화면을 전환하지 않는다.
- `ALL` 상태에서는 개별 공정을 눌러도 전체 조회 상태가 유지된다.

### 3. 모니터링/제어 연동 상태 확인

1. 그리드에서 모니터링 현황과 제어 연동 컬럼을 확인한다.
2. 정상, 실패, 확인 중 상태가 텍스트와 indicator로 구분되는지 확인한다.

기대 결과:

- Python 프로세스 alive 의미의 모니터링 현황이 표시된다.
- AI 추론 결과 전달 통신 의미의 제어 연동 상태가 표시된다.

### 4. 서버 IP와 Python 프로젝트 경로 수정

1. 특정 모델의 설정 수정 UI를 연다.
2. 서버 IP와 Python 프로젝트 경로를 변경한다.
3. 저장한다.

기대 결과:

- mock 목록에 변경된 값이 반영된다.
- 빈 IP 또는 빈 경로는 오류로 표시된다.

### 5. 프로세스 시작/정지/재시작

1. 중지 상태 모델에서 시작을 선택한다.
2. 실행 중 모델에서 정지를 선택한다.
3. 실행 중 또는 오류 상태 모델에서 재시작을 선택한다.

기대 결과:

- 각 조작 전 대상 확인 절차가 표시된다.
- 실제 프로세스 제어 없이 mock 상태만 변경된다.
- 조작 중 중복 조작은 차단된다.

### 6. 이벤트 로그 팝업

1. 특정 모델의 이벤트 로그 버튼을 선택한다.
2. 팝업에서 로그 목록을 확인한다.
3. 로그가 없는 모델도 확인한다.

기대 결과:

- 팝업이 현재 화면 위에 표시된다.
- 로그가 없으면 빈 상태가 표시된다.

### 7. 신규 모델 추가

1. 모델 추가 UI를 연다.
2. 공정, 모델명, 조업 자동화 기술명, 서버 IP, Python 프로젝트 경로를 입력한다.
3. 저장한다.

기대 결과:

- 신규 모델이 mock 그리드에 추가된다.
- 필수값이 비어 있으면 저장 전 오류가 표시된다.

## 검증 명령

```powershell
cd frontend
npm test -- --run src/pages/__tests__/ModelManagement.test.tsx
npm run build
```

최종 화면 검증이 필요한 경우:

```powershell

```
