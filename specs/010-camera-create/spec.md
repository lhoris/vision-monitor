# 기능 명세서: 카메라 목록 관리

**기능 브랜치**: `010-camera-create`

**작성일**: 2026-08-17

**상태**: 초안

**변경 추적**: 문서 변경 이력은 Git 커밋 이력을 기준으로 한다.

**입력**: 관리자 메뉴의 카메라 추가 기능은 별도 입력 폼이 아니라 카메라 목록 그리드에서 행 추가, 셀 수정, 저장, 삭제만으로 관리한다. 이 카메라 목록은 라이브 대시보드에서 카메라 선택 시 불러오는 기준 데이터가 된다.

> **기능 개요 - Agent 요약**
>
> 카메라 목록 관리는 관리자 권한 사용자가 라이브 대시보드에서 사용할 카메라 기준 데이터를 그리드로 관리하는 기능이다. 관리자는 별도 상세 폼으로 이동하지 않고 그리드 안에서 행을 추가하고 셀 값을 수정한 뒤 저장하거나 삭제할 수 있어야 한다. 일반 사용자는 이 관리 화면에 접근할 수 없으며, 라이브 대시보드에서는 관리자가 저장한 사용 가능 카메라만 선택 목록으로 제공된다. 카메라 등록은 카메라 기준 데이터 저장을 의미하며, 실제 스트림 연결 검증, 영상 수집 서버 반영, AI 분석 모델 연결은 후속 범위로 둔다.

## 1. 참고 이미지 및 원문 자료

| 상태 | 자료 | 설명 | 비고 |
|------|------|------|------|
| active | 제공된 원문 자료 없음 | 카메라 목록 관리 전용 화면 스케치는 아직 제공되지 않음 | 사용자 요구와 라이브 대시보드 운영 맥락 기준 |

## 2. 기능 요구사항

### 기능 요구사항

- **FR-001**: 관리자 권한 사용자는 관리자 메뉴에서 카메라 목록 관리 화면에 진입할 수 있어야 한다.
- **FR-002**: 관리자 권한이 없는 사용자는 카메라 목록 관리 메뉴와 화면에 접근할 수 없어야 한다.
- **FR-003**: 시스템은 카메라 기준 데이터를 그리드 목록으로 표시해야 한다.
- **FR-004**: 관리자는 그리드에서 새 행을 추가해 신규 카메라를 입력할 수 있어야 한다.
- **FR-005**: 관리자는 그리드 셀을 직접 수정해 카메라 정보를 변경할 수 있어야 한다.
- **FR-006**: 관리자는 그리드에서 선택한 카메라 행을 삭제 대상으로 표시하거나 삭제할 수 있어야 한다.
- **FR-007**: 시스템은 저장 전 추가, 수정, 삭제된 행을 사용자가 구분할 수 있게 표시해야 한다.
- **FR-008**: 시스템은 카메라명, 스트림 주소, 사용 여부, 정렬 순서 등 라이브 대시보드 선택 목록에 필요한 값을 저장해야 한다.
- **FR-009**: 시스템은 필수값 누락, 잘못된 스트림 주소 형식, 중복 카메라명, 중복 스트림 주소를 저장 전에 사용자에게 알려야 한다.
- **FR-010**: 관리자는 변경사항을 한 번의 저장 동작으로 반영할 수 있어야 한다.
- **FR-011**: 관리자는 저장하지 않은 변경사항을 취소하고 마지막 저장 상태로 되돌릴 수 있어야 한다.
- **FR-012**: 시스템은 저장 성공, 실패, 처리 중 상태를 명확히 표시해야 한다.
- **FR-013**: 시스템은 사용 안 함으로 지정된 카메라를 라이브 대시보드의 카메라 선택 목록에서 제외해야 한다.
- **FR-014**: 시스템은 삭제된 카메라가 기존 라이브 대시보드 레이아웃에서 사용 중인 경우 사용자에게 영향 범위를 알려야 한다.
- **FR-015**: 시스템은 카메라 등록이 실제 스트림 연결 성공이나 영상 수집 서버 반영을 보장하지 않음을 표시해야 한다.
- **FR-016**: 시스템은 카메라 관리 화면에 별도 상세 등록 폼, 마법사, 카드형 편집 화면을 제공하지 않아야 한다.
- **FR-017**: 관리자는 그리드의 오버레이 모드 셀에서 'none' | 'server-side' | 'client-svg' 중 선택할 수 있어야 한다.
- **FR-018**: 오버레이 모드가 'client-svg'로 선택된 경우, 시스템은 해당 카메라의 정적 오버레이 설정(ROI/Zone 좌표)을 JSON으로 저장할 수 있어야 한다.
- **FR-019**: 오버레이 모드 'client-svg' 선택 시 관리자는 영상 원본 해상도(폭x높이)를 입력해야 하며, 이를 기준으로 모든 오버레이 좌표가 정규화된다.
- **FR-020**: 시스템은 오버레이 설정 검증 실패(필수값 누락, 잘못된 해상도) 시 저장 전에 사용자에게 알려야 한다.

## 3. 제외 범위

- 별도 카메라 등록 폼, 상세 편집 폼, 단계형 마법사는 제외한다.
- 실제 RTSP/HTTP/WebRTC 스트림 연결 검증은 제외한다.
- 실제 영상 수집 서버 반영, 미디어 서버 배포, AI 분석 모델 연결은 제외한다.
- 카메라 펌웨어 설정, 장비 인증 정보 저장, 네트워크 장비 설정은 제외한다.
- 승인 워크플로, 배포 예약, 변경 이력 상세 감사 화면은 제외한다.
- 라이브 대시보드의 그리드 레이아웃 편집 권한 재설계는 별도 기능으로 다룬다.

## 4. UI/UX 요구사항

- **UX-001**: 카메라 관리 화면의 주 작업 영역은 그리드여야 하며, 추가/수정/삭제/저장 흐름은 그리드 안에서 완료되어야 한다.
- **UX-002**: 새 카메라는 빈 행 또는 행 추가 버튼으로 그리드에 추가되어야 한다.
- **UX-003**: 셀 수정은 사용자가 목록 맥락을 잃지 않도록 인라인으로 동작해야 한다.
- **UX-004**: 필수값 오류와 중복 오류는 문제가 있는 행과 셀에서 확인할 수 있어야 한다.
- **UX-005**: 삭제는 실수 방지를 위해 저장 전 삭제 표시 상태를 제공하거나 삭제 확인을 거쳐야 한다.
- **UX-006**: 저장하지 않은 변경사항이 있으면 화면 이동 또는 새로고침 전에 사용자에게 알려야 한다.
- **UX-007**: 그리드는 검색, 정렬, 상태 필터를 제공해 많은 카메라에서도 원하는 항목을 찾을 수 있어야 한다.
- **UX-008**: 그리드 컬럼은 카메라명, 공정, 위치, 스트림 주소, 프로토콜, 상태, 사용 여부, 정렬 순서를 확인할 수 있어야 한다.
- **UX-009**: theme1, theme2, theme3에서 그리드 텍스트, 편집 상태, 오류 상태가 읽을 수 있어야 한다.

## 6. 주요 엔티티

### 카메라

라이브 대시보드에서 선택할 수 있는 영상 소스의 기준 데이터다.

필수 속성:
- 카메라명
- 스트림 주소
- 스트림 프로토콜
- 사용 여부

권장 속성:
- 대상 공정
- 설치 위치
- 구역 또는 라인
- 운영 상태
- 해상도
- FPS
- 설명
- 정렬 순서
- 마지막 확인 시각
- 생성 시각
- 수정 시각
- 오버레이 모드 (기본값: 'none')
- 오버레이 설정 (JSON: 원본 해상도, 정적 ROI/Zone 좌표)

무결성 규칙:
- 카메라명은 중복될 수 없다.
- 스트림 주소는 중복될 수 없다.
- 사용 중인 카메라만 라이브 대시보드 선택 목록에 표시된다.
- 삭제 대상 카메라가 저장된 레이아웃에서 사용 중이면 삭제 전 영향 안내가 필요하다.

### 카메라 변경 묶음

관리자가 그리드에서 수행한 추가, 수정, 삭제 변경사항을 저장 전까지 묶어서 보여주는 작업 단위다.

필수 속성:
- 추가된 행 목록
- 수정된 행 목록
- 삭제 대상 행 목록
- 행별 검증 결과
- 전체 저장 가능 여부

## 7. 사용자 시나리오 및 테스트

### 사용자 스토리 1 - 카메라 목록 확인과 검색 (우선순위: P1)

관리자는 등록된 카메라 기준 데이터를 그리드에서 확인하고 필요한 카메라를 찾는다.

**관련 기능 요구사항**: FR-001, FR-002, FR-003, UX-007, UX-008

**이 우선순위의 이유**: 목록 확인이 되어야 추가, 수정, 삭제 작업을 안전하게 수행할 수 있다.

**독립 테스트**: 관리자 계정으로 메뉴에 진입해 카메라 목록이 그리드로 표시되고 검색/정렬/필터로 항목을 찾을 수 있는지 확인한다.

**수용 시나리오**:

1. **Given** 관리자 권한 사용자가 로그인되어 있다, **When** 카메라 추가 메뉴를 선택한다, **Then** 카메라 목록 그리드가 표시된다.
2. **Given** 카메라 목록이 표시되어 있다, **When** 사용자가 카메라명 또는 위치로 검색한다, **Then** 조건에 맞는 행만 표시된다.
3. **Given** 관리자 권한이 없는 사용자가 로그인되어 있다, **When** 메뉴 목록을 확인한다, **Then** 카메라 관리 메뉴가 표시되지 않는다.

### 사용자 스토리 2 - 그리드에서 카메라 추가와 수정 (우선순위: P1)

관리자는 별도 폼 없이 그리드 안에서 신규 카메라 행을 추가하고 셀 값을 수정한다.

**관련 기능 요구사항**: FR-004, FR-005, FR-007, FR-008, FR-009, FR-010, FR-016

**이 우선순위의 이유**: 사용자가 요구한 핵심 방식은 그리드 기반 인라인 관리다.

**독립 테스트**: 새 행을 추가하고 필수 셀을 입력한 뒤 저장했을 때 목록에 반영되는지 확인한다.

**수용 시나리오**:

1. **Given** 카메라 목록 그리드가 표시되어 있다, **When** 관리자가 행 추가를 선택한다, **Then** 그리드에 편집 가능한 신규 행이 추가된다.
2. **Given** 신규 행 또는 기존 행이 편집 중이다, **When** 관리자가 셀 값을 수정한다, **Then** 해당 행은 미저장 변경 상태로 표시된다.
3. **Given** 필수값이 누락되었거나 중복값이 있다, **When** 관리자가 저장을 시도한다, **Then** 문제가 있는 행과 셀에 오류가 표시되고 저장되지 않는다.
4. **Given** 모든 변경값이 유효하다, **When** 관리자가 저장한다, **Then** 추가와 수정 내용이 저장되고 미저장 표시가 사라진다.

### 사용자 스토리 3 - 그리드에서 카메라 삭제 (우선순위: P2)

관리자는 그리드에서 카메라 행을 삭제 대상으로 표시하고 저장해 삭제를 반영한다.

**관련 기능 요구사항**: FR-006, FR-007, FR-010, FR-014, UX-005

**이 우선순위의 이유**: 등록 오류나 운영 종료 카메라를 제거할 수 있어야 기준 데이터 품질이 유지된다.

**독립 테스트**: 행 삭제 표시 후 저장했을 때 목록에서 제거되고, 레이아웃 사용 중인 카메라는 영향 안내가 표시되는지 확인한다.

**수용 시나리오**:

1. **Given** 기존 카메라 행이 표시되어 있다, **When** 관리자가 삭제를 선택한다, **Then** 해당 행은 삭제 예정 상태로 표시된다.
2. **Given** 삭제 예정 카메라가 라이브 대시보드 레이아웃에서 사용 중이다, **When** 관리자가 저장을 시도한다, **Then** 영향 안내가 표시된다.
3. **Given** 관리자가 삭제 영향을 확인했다, **When** 저장을 완료한다, **Then** 해당 카메라는 관리 목록과 라이브 대시보드 선택 목록에서 제거된다.

### 사용자 스토리 4 - 변경 취소와 이탈 보호 (우선순위: P3)

관리자는 저장하지 않은 변경사항을 취소하거나 실수로 화면을 벗어나는 일을 방지한다.

**관련 기능 요구사항**: FR-011, UX-006

**이 우선순위의 이유**: 그리드 인라인 편집은 여러 셀을 연속 수정하므로 변경 손실 방지가 필요하다.

**독립 테스트**: 여러 행을 수정한 뒤 취소하면 마지막 저장 상태로 돌아가고, 화면 이탈 시 경고가 표시되는지 확인한다.

**수용 시나리오**:

1. **Given** 미저장 변경사항이 있다, **When** 관리자가 변경 취소를 선택한다, **Then** 그리드는 마지막 저장 상태로 복원된다.
2. **Given** 미저장 변경사항이 있다, **When** 관리자가 다른 화면으로 이동하려 한다, **Then** 변경 손실 가능성이 안내된다.

### 엣지 케이스

- 긴 카메라명, 긴 위치명, 긴 스트림 주소는 그리드 레이아웃을 깨지 않아야 한다.
- 새 행을 여러 개 추가한 뒤 일부 행만 오류가 있어도 정상 행과 오류 행을 구분할 수 있어야 한다.
- 삭제 예정 행은 저장 전까지 복구할 수 있어야 한다.
- 사용 안 함 상태의 카메라는 삭제하지 않아도 라이브 대시보드 선택 목록에서 제외되어야 한다.
- 이미 레이아웃에 배치된 카메라를 사용 안 함으로 바꾸는 경우 영향 안내가 필요하다.
- 저장 실패 후 사용자가 입력한 변경사항은 유지되어야 한다.
- 동시 편집으로 중복값이 뒤늦게 발생하면 저장 실패 사유가 행 단위로 표시되어야 한다.

## 8. 성공 기준

### 측정 가능한 결과

- **SC-001**: 관리자는 2번 이하의 조작으로 카메라 목록 관리 화면에 진입할 수 있다.
- **SC-002**: 관리자는 별도 상세 폼 없이 그리드 안에서 카메라 추가, 수정, 삭제를 완료할 수 있다.
- **SC-003**: 필수값 누락, 중복값, 잘못된 스트림 주소는 저장 전에 문제가 있는 행과 셀에서 확인할 수 있다.
- **SC-004**: 100개 이상의 카메라가 있어도 관리자는 검색 또는 필터로 원하는 카메라를 5초 이내 찾을 수 있다.
- **SC-005**: 저장 성공, 실패, 처리 중 상태가 모든 테마에서 명확히 구분된다.
- **SC-006**: 비관리자는 카메라 관리 메뉴와 화면 내용을 볼 수 없다.
- **SC-007**: 사용 안 함 또는 삭제된 카메라는 라이브 대시보드의 새 카메라 선택 목록에 표시되지 않는다.

## 9. 가정 및 미정 사항

### 가정

- 카메라 기준 데이터는 서버에 저장되어 모든 사용자가 같은 목록을 사용한다.
- 라이브 대시보드의 카메라 선택 목록은 사용 가능 상태의 카메라만 조회한다.
- 카메라 추가 메뉴의 실제 화면은 그리드 기반 관리 화면이며, 별도 신규 등록 폼은 만들지 않는다.
- MVP에서는 실제 스트림 연결 검증 없이 주소 형식과 필수값만 검증한다.
- 카메라 추가는 AI 영상 분석 모델 등록과 별도 기능이다.

### 미정 사항

- 대상 공정, 구역, 라인의 최종 코드 체계는 운영 정책 확정 후 조정한다.
- 레이아웃에서 사용 중인 카메라를 삭제할 때 삭제 차단으로 할지, 영향 안내 후 허용할지는 planning 단계에서 확정한다.
