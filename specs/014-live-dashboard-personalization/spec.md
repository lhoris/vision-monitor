# 기능 명세: 라이브 대시보드 개인화

**기능 브랜치**: `014-live-dashboard-personalization`

**작성일**: 2026-08-25

**최종 갱신일**: 2026-09-10

**상태**: 초안

**변경 추적**: 문서 변경 이력은 Git 커밋 이력을 기준으로 한다.

**입력**: 사용자 설명: "개인화 테이블에 테마와 그리드 레이아웃 정보를 함께 저장해야 한다. 사용자가 테마를 지정하면 로그인할 때 해당 테마가 자동 적용되어야 하고, 그리드 대시보드 화면에서 레이아웃을 수정할 때마다 개인화 정보가 계속 갱신되어야 한다. 테마도 변경 즉시 저장되어야 한다."

> 이 문서는 한국어로 작성한다. 기술 용어, API 이름, 파일 경로, 코드 식별자는 원문 또는 영문 표기를 유지할 수 있다.
> 기능 명세는 "무엇을 제공해야 하는가"를 정의한다. 구체적인 저장 방식, API 모양, 파일 변경 위치는 plan.md 또는 contracts/에서 다룬다.

> **기능 개요 - Agent 요약**
>
> 라이브 대시보드 개인화는 로그인한 사용자별로 테마와 그리드 대시보드 구성을 저장하고 복원하는 기능이다. 사용자는 테마를 변경하면 다음 로그인과 새로고침 이후에도 같은 테마를 이어서 사용해야 한다. 사용자가 공정/세부공정 탭, 그리드 크기, 카메라 배치, 표시명, 직접 입력한 영상 소스를 변경하면 해당 변경이 사용자 개인화 정보로 자동 저장되어야 한다. 개인화 저장이나 복원에 실패해도 사용자는 현재 화면 조작을 계속할 수 있어야 하며, 다른 사용자의 개인화 정보가 섞여 보이면 안 된다.

## 2. 기능 요구사항 *(필수)*

### 기능 요구사항

- **FR-001**: 시스템은 로그인한 사용자별로 라이브 대시보드 개인화 정보를 독립적으로 유지해야 한다.
- **FR-002**: 개인화 정보는 사용자의 테마 설정과 라이브 대시보드 레이아웃 설정을 함께 표현해야 한다.
- **FR-003**: 사용자가 로그인하면 시스템은 해당 사용자의 마지막 개인화 정보를 복원해야 한다.
- **FR-004**: 저장된 개인화 정보가 없는 사용자는 업무를 시작할 수 있는 기본 테마와 기본 라이브 대시보드 구성을 제공받아야 한다.
- **FR-005**: 사용자가 테마를 변경하면 변경된 테마는 현재 화면에 즉시 적용되고 사용자 개인화 정보에 저장되어야 한다.
- **FR-006**: 사용자가 다시 로그인하거나 화면을 새로고침하면 마지막으로 저장된 테마가 자동 적용되어야 한다.
- **FR-007**: 사용자가 공정 탭 또는 세부공정 탭을 추가, 삭제, 이름 변경, 순서 변경, 선택 변경하면 해당 구성이 사용자 개인화 정보에 반영되어야 한다.
- **FR-008**: 사용자가 세부공정별 그리드 크기나 배치 방식을 변경하면 해당 구성이 사용자 개인화 정보에 반영되어야 한다.
- **FR-009**: 사용자가 카메라를 추가, 제거, 이동, 위치 교환하면 해당 배치가 사용자 개인화 정보에 반영되어야 한다.
- **FR-010**: 사용자가 카메라 표시명을 변경하면 변경된 이름이 같은 사용자의 해당 대시보드 구성에서 유지되어야 한다.
- **FR-011**: 사용자가 직접 영상 주소를 입력해 그리드에 배치하면 해당 영상 소스와 표시 정보가 사용자 개인화 정보에 반영되어야 한다.
- **FR-012**: 레이아웃 변경은 사용자가 별도 저장 버튼을 누르지 않아도 자동 저장되어야 한다.
- **FR-013**: 빠르게 연속된 레이아웃 변경은 최종 상태 중심으로 저장되어야 하며, 중간 상태 저장 때문에 화면 조작이 지연되면 안 된다.
- **FR-014**: 테마 변경은 사용자가 변경을 확정한 시점에 즉시 저장되어야 한다.
- **FR-015**: 개인화 저장 실패가 발생해도 현재 화면의 변경 내용은 즉시 되돌아가지 않아야 한다.
- **FR-016**: 개인화 복원 실패가 발생하면 시스템은 기본 구성을 제공하고 사용자가 실패 상태를 인지할 수 있게 해야 한다.
- **FR-017**: 시스템은 잘못되었거나 더 이상 유효하지 않은 개인화 정보가 있어도 가능한 범위에서 정상 구성을 복원해야 한다.
- **FR-018**: 사용자 A의 개인화 정보는 사용자 B에게 노출되거나 적용되면 안 된다.
- **FR-019**: 사용자가 로그아웃하거나 다른 계정으로 전환하면 이전 사용자의 테마와 레이아웃이 다음 사용자 화면에 남아 있으면 안 된다.
- **FR-020**: 개인화 정보는 향후 항목이 추가되어도 기존 사용자의 테마와 레이아웃 복원이 깨지지 않도록 버전 식별이 가능해야 한다.

## 3. 제외 범위 *(필수)*

- 카메라 마스터 등록, 삭제, 상태 수집, 실제 장비 연동은 이 기능에서 다루지 않는다.
- RTSP ingest, transcoding, media distribution, WebRTC relay 같은 영상 전달 구현은 이 기능에서 다루지 않는다.
- AI inference, 영상 분석 결과 생성, server-side overlay 생성은 이 기능에서 다루지 않는다.
- 여러 사용자가 하나의 대시보드 구성을 공동 편집하거나 공유하는 기능은 이 기능에서 다루지 않는다.
- 관리자에 의한 타 사용자 개인화 조회, 강제 수정, 초기화 기능은 이 기능에서 다루지 않는다.
- 개인화 변경 이력, 감사 로그, 이전 버전 복구 화면은 이 기능에서 다루지 않는다.
- 테마 자체의 신규 디자인 제작은 이 기능에서 다루지 않는다. 기존에 제공되는 테마 선택과 저장/복원을 대상으로 한다.

## 4. UI/UX 요구사항

- **UX-001**: 사용자는 로그인 후 별도 조작 없이 자신의 마지막 테마와 라이브 대시보드 구성을 확인할 수 있어야 한다.
- **UX-002**: 테마 변경은 화면 전체에 즉시 반영되어야 하며, 다음 화면 이동이나 새로고침을 기다리게 하면 안 된다.
- **UX-003**: 레이아웃 자동 저장 상태는 업무 화면을 과도하게 방해하지 않는 방식으로 표시되어야 한다.
- **UX-004**: 저장 실패 상태에서도 사용자는 탭, 그리드, 카메라 배치 편집을 계속할 수 있어야 한다.
- **UX-005**: 복원 실패 시 기본 구성이 표시되어야 하며, 사용자는 개인화가 적용되지 않았음을 이해할 수 있어야 한다.
- **UX-006**: 사용자 전환 또는 로그아웃 직후 이전 사용자의 테마가 잠시라도 다음 사용자에게 잘못 적용되어 보이면 안 된다.
- **UX-007**: 개인화 복원은 기존 라이브 대시보드의 카메라 추가, 제거, 이동, Rename, 직접 영상 주소 추가 흐름을 바꾸지 않아야 한다.

## 5. 필요한 정보

- 현재 로그인한 사용자 식별 정보
- 사용자가 선택한 테마
- 마지막으로 활성화된 공정 탭과 세부공정 탭
- 공정 탭 목록, 세부공정 탭 목록, 각 탭의 표시명과 순서
- 세부공정별 그리드 크기와 배치 설정
- 세부공정별 카메라 배치 위치, span, 사용자 지정 표시명
- 사용자가 직접 추가한 영상 소스의 유형, 주소, 표시명
- 개인화 저장/복원 상태와 마지막 성공 시점
- 개인화 데이터의 버전

## 6. 사용자 시나리오 및 테스트 *(필수)*

### 사용자 스토리 1 - 내 개인화 복원 (우선순위: P1)

운영자는 로그인 후 라이브 대시보드에 들어가면 자신이 마지막으로 사용하던 테마와 그리드 구성을 그대로 확인한다.

**관련 기능 요구사항**: FR-001, FR-002, FR-003, FR-004, FR-006, FR-016, FR-017

**우선순위 이유**: 복원이 되지 않으면 개인화 저장의 사용자 가치가 사라진다.

**독립 테스트**: 사용자가 테마와 레이아웃을 저장한 뒤 로그아웃/로그인 또는 새로고침을 수행하면 마지막 상태가 복원되는지 확인한다.

**허용 시나리오**:

1. **Given** 사용자가 이전에 테마와 대시보드 구성을 저장했다, **When** 같은 계정으로 로그인해 라이브 대시보드에 진입한다, **Then** 마지막 테마와 마지막 대시보드 구성이 표시된다.
2. **Given** 저장된 개인화 정보가 없는 사용자가 있다, **When** 사용자가 라이브 대시보드에 처음 진입한다, **Then** 기본 테마와 기본 대시보드 구성이 표시된다.
3. **Given** 저장된 개인화 정보 일부가 유효하지 않다, **When** 사용자가 라이브 대시보드에 진입한다, **Then** 시스템은 가능한 범위의 구성을 복원하고 나머지는 기본값으로 보정한다.

---

### 사용자 스토리 2 - 테마 변경 즉시 저장 (우선순위: P1)

사용자는 원하는 테마를 선택하면 현재 화면에 즉시 적용되고, 다음 로그인에서도 같은 테마가 유지되기를 기대한다.

**관련 기능 요구사항**: FR-002, FR-005, FR-006, FR-014, FR-015, FR-018, FR-019

**우선순위 이유**: 테마는 사용자가 가장 즉시 체감하는 개인화 항목이며 로그인 경험과 직접 연결된다.

**독립 테스트**: 사용자가 테마를 변경한 뒤 새로고침하거나 재로그인했을 때 변경한 테마가 적용되는지 확인한다.

**허용 시나리오**:

1. **Given** 사용자가 라이브 대시보드를 보고 있다, **When** 테마를 다른 값으로 변경한다, **Then** 화면 테마가 즉시 변경되고 개인화 저장 대상에 반영된다.
2. **Given** 사용자가 테마를 변경했다, **When** 같은 계정으로 다시 로그인한다, **Then** 변경된 테마가 자동 적용된다.
3. **Given** 사용자 A가 테마를 변경했다, **When** 사용자 B가 로그인한다, **Then** 사용자 B에게 사용자 A의 테마가 적용되지 않는다.

---

### 사용자 스토리 3 - 레이아웃 자동 저장 (우선순위: P1)

운영자는 라이브 대시보드에서 탭, 그리드 크기, 카메라 배치, 표시명, 직접 영상 주소를 바꾸면 별도 저장 버튼 없이 변경 결과가 유지되기를 기대한다.

**관련 기능 요구사항**: FR-007, FR-008, FR-009, FR-010, FR-011, FR-012, FR-013, FR-015

**우선순위 이유**: 라이브 대시보드는 반복적으로 조정되는 업무 화면이므로 사용자의 마지막 작업 상태를 잃지 않는 것이 핵심이다.

**독립 테스트**: 사용자가 레이아웃을 변경한 뒤 새로고침하거나 재로그인했을 때 최종 변경 상태가 유지되는지 확인한다.

**허용 시나리오**:

1. **Given** 사용자가 특정 세부공정 탭의 그리드를 보고 있다, **When** 그리드 크기를 변경한다, **Then** 변경된 그리드 구성이 사용자 개인화 정보에 반영된다.
2. **Given** 사용자가 카메라를 다른 셀로 이동했다, **When** 새로고침한다, **Then** 카메라가 마지막 위치에 표시된다.
3. **Given** 사용자가 직접 영상 주소를 입력해 셀에 추가했다, **When** 같은 계정으로 다시 로그인한다, **Then** 직접 추가한 영상 소스가 같은 세부공정 탭에 표시된다.
4. **Given** 사용자가 빠르게 여러 번 배치를 변경했다, **When** 자동 저장이 완료된다, **Then** 마지막으로 확정된 화면 상태가 저장된다.

---

### 사용자 스토리 4 - 사용자별 개인화 분리 (우선순위: P2)

같은 장비를 보는 사용자라도 각자 다른 테마와 대시보드 구성을 사용할 수 있어야 한다.

**관련 기능 요구사항**: FR-001, FR-018, FR-019

**우선순위 이유**: 개인화 기능은 사용자 간 격리가 보장되어야 신뢰할 수 있다.

**독립 테스트**: 서로 다른 두 계정이 서로 다른 테마와 레이아웃을 저장한 뒤 계정을 전환해도 각자의 설정만 보이는지 확인한다.

**허용 시나리오**:

1. **Given** 사용자 A가 theme1과 2x2 그리드를 저장했다, **When** 사용자 B가 로그인한다, **Then** 사용자 B는 사용자 A의 theme1과 2x2 그리드를 보지 않는다.
2. **Given** 사용자 B가 theme3과 3x3 그리드를 저장했다, **When** 사용자 A가 다시 로그인한다, **Then** 사용자 A의 기존 theme1과 2x2 그리드가 유지된다.

---

### 사용자 스토리 5 - 실패 시 업무 지속 (우선순위: P3)

개인화 저장이나 복원이 실패해도 운영자는 라이브 감시 업무를 계속할 수 있어야 한다.

**관련 기능 요구사항**: FR-015, FR-016, FR-017

**우선순위 이유**: 개인화 실패가 감시 화면 전체 사용을 막으면 안 된다.

**독립 테스트**: 저장 실패와 복원 실패 상황에서 화면 조작이 유지되고 기본 구성이 제공되는지 확인한다.

**허용 시나리오**:

1. **Given** 개인화 복원에 실패했다, **When** 사용자가 라이브 대시보드에 진입한다, **Then** 기본 구성으로 화면이 표시되고 실패 상태가 안내된다.
2. **Given** 레이아웃 자동 저장에 실패했다, **When** 사용자가 계속 카메라 배치를 수정한다, **Then** 현재 화면 변경은 유지되고 사용자는 다시 저장 가능한 상태를 확인할 수 있다.
3. **Given** 테마 저장에 실패했다, **When** 사용자가 현재 화면을 계속 사용한다, **Then** 즉시 적용된 테마는 화면에 유지되고 실패 상태가 안내된다.

### 엣지 케이스

- 저장된 활성 탭이 현재 탭 목록에 없으면 사용 가능한 첫 번째 탭이 활성화되어야 한다.
- 저장된 활성 세부공정 탭이 현재 세부공정 목록에 없으면 사용 가능한 첫 번째 세부공정 탭이 활성화되어야 한다.
- 저장된 카메라 배치가 현재 그리드 범위를 벗어나면 사용 가능한 범위로 보정되거나 사용자에게 문제 상태가 표시되어야 한다.
- 같은 세부공정 안에 같은 카메라 또는 같은 직접 영상 소스가 중복 배치되어 있으면 충돌이 해소되거나 사용자에게 문제 상태가 표시되어야 한다.
- 저장된 테마가 더 이상 제공되지 않으면 기본 테마가 적용되어야 한다.
- 사용자가 로그아웃한 직후 진행 중이던 자동 저장 결과가 다음 로그인 사용자의 개인화 정보에 반영되면 안 된다.
- 네트워크가 불안정한 상태에서 여러 번 변경해도 사용자가 보는 최종 화면 상태가 갑자기 이전 상태로 되돌아가면 안 된다.
- 직접 영상 주소에 민감한 인증 정보가 포함될 수 있으므로 화면 표시에서는 불필요하게 전체 주소가 노출되지 않아야 한다.

## 7. 성공 기준 *(필수)*

### 측정 가능한 결과

- **SC-001**: 저장된 개인화 정보가 있는 사용자는 로그인 후 3초 이내에 마지막 테마와 대시보드 구성을 확인할 수 있다.
- **SC-002**: 사용자는 테마 변경 직후 1초 이내에 화면 테마 변경을 확인할 수 있다.
- **SC-003**: 사용자가 테마를 변경한 뒤 새로고침하거나 재로그인하면 100% 동일한 테마가 복원된다.
- **SC-004**: 사용자가 그리드 크기, 탭, 카메라 배치 중 하나를 변경한 뒤 새로고침하면 마지막 변경 상태가 복원된다.
- **SC-005**: 서로 다른 두 사용자의 개인화 정보는 계정 전환 테스트에서 100% 분리되어 표시된다.
- **SC-006**: 저장된 개인화 정보가 없는 신규 사용자는 추가 설정 없이 기본 라이브 대시보드를 사용할 수 있다.
- **SC-007**: 저장 또는 복원 실패 상황에서도 사용자는 라이브 대시보드 화면을 계속 조작할 수 있다.
- **SC-008**: 연속 변경 저장 테스트에서 최종 화면 상태가 중간 상태보다 우선하여 저장된다.

## 8. 가정 및 미정 사항

### 가정

- 사용자는 로그인 상태에서만 개인화 기능을 사용한다.
- 현재 제공되는 테마 선택지는 `theme1`, `theme2`, `theme3`이며, 신규 테마 디자인 추가는 별도 기능으로 다룬다.
- 개인화 정보는 사용자별 최신 상태 1개를 우선 복원 대상으로 본다.
- 라이브 대시보드의 기존 탭, 세부공정, 카메라 배치, 직접 영상 주소 입력 흐름은 유지된다.
- 직접 영상 주소는 사용자가 입력한 표시 목적의 소스로 취급하며, 실제 영상 전달 안정성은 별도 기능에서 다룬다.
- 개인화 저장 실패 시 화면 상태를 되돌리지 않고 사용자에게 저장 실패 상태를 알려주는 것을 기본 동작으로 한다.

### 미정 사항

- 없음. 현재 대화에서 확인된 요구사항을 기준으로 theme와 layout을 통합 개인화 범위로 확정한다.
