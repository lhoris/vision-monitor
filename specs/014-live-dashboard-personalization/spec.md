# 기능 명세서: 라이브 대시보드 개인화

**기능 브랜치**: `014-live-dashboard-personalization`

**작성일**: 2026-08-25

**상태**: 초안

**변경 추적**: 문서 변경 이력은 Git 커밋 이력을 기준으로 한다.

**입력**: 사용자 설명: "라이브 대시보드는 현재 기본 설정된 카메라로 채워지지만, 로그인한 사용자별 개인화 기능을 제공해야 한다. 014 기능으로 분리한다."

> 이 문서는 한국어로 작성한다. 기술 용어, API 이름, 파일 경로, 코드 식별자는 원문 또는 영문 표기를 유지할 수 있다.
> 기능 명세서는 "무엇을 제공해야 하는가"를 정의한다. 구현 방식, 컴포넌트 구조, DTO/API 세부사항, 파일 경로는 plan.md 또는 contracts/에서 다룬다.

> **기능 개요 - Agent 요약**
>
> 라이브 대시보드 개인화는 사용자가 로그인한 계정별로 공정탭, 세부공정탭, 그리드 크기, 카메라 배치, 카메라 표시명, 직접 추가한 영상 구성을 저장하고 다시 복원하는 기능이다. 현재 라이브 대시보드는 기본 layout 또는 mock layout으로 화면을 채우지만, 이 기능 이후에는 `admin`, `tester`, `tester1` 같은 사용자마다 서로 다른 라이브 대시보드 구성을 유지해야 한다. 사용자가 새로고침하거나 다시 로그인해도 마지막으로 저장된 구성이 복원되어야 하며, 저장 실패 시에도 현재 화면 조작이 불필요하게 중단되지 않아야 한다. 이 기능은 002 라이브 메인 화면의 기존 편집 기능을 사용자별 지속 상태로 확장하되, 영상 재생·AI 분석·카메라 장비 연동 자체는 다루지 않는다.

## 2. 기능 요구사항 *(필수)*

### 기능 요구사항

- **FR-001**: 시스템은 로그인한 사용자별로 라이브 대시보드 구성을 구분해서 유지해야 한다.
- **FR-002**: 시스템은 사용자가 라이브 대시보드에 진입할 때 해당 사용자의 마지막 저장 구성을 복원해야 한다.
- **FR-003**: 저장된 구성이 없는 사용자는 업무를 시작할 수 있는 기본 구성을 제공받아야 한다.
- **FR-004**: 사용자가 공정탭 또는 세부공정탭을 추가, 삭제, 이름 변경, 순서 변경하면 해당 사용자 구성에 반영되어야 한다.
- **FR-005**: 사용자가 세부공정탭별 그리드 크기를 변경하면 해당 세부공정탭의 구성에 반영되어야 한다.
- **FR-006**: 사용자가 카메라를 추가, 제거, 이동, 위치 교환하면 현재 세부공정탭의 구성에 반영되어야 한다.
- **FR-007**: 사용자가 카메라 표시명을 변경하면 같은 사용자의 해당 대시보드 구성에서 변경된 이름이 유지되어야 한다.
- **FR-008**: 사용자가 직접 영상 주소로 추가한 임시 영상 타일은 같은 사용자의 해당 세부공정탭 구성에서 유지되어야 한다.
- **FR-009**: 사용자 A의 대시보드 변경은 사용자 B의 대시보드 구성에 영향을 주지 않아야 한다.
- **FR-010**: 사용자가 로그아웃 후 같은 계정으로 다시 로그인하면 마지막 저장 구성을 확인할 수 있어야 한다.
- **FR-011**: 사용자가 다른 계정으로 로그인하면 해당 계정의 별도 구성을 확인해야 한다.
- **FR-012**: 시스템은 저장 또는 복원 실패를 사용자가 이해할 수 있는 상태로 표시해야 한다.
- **FR-013**: 저장 실패가 발생해도 사용자의 현재 화면 조작 상태를 즉시 잃지 않아야 한다.
- **FR-014**: 시스템은 잘못되었거나 더 이상 사용할 수 없는 구성 일부가 있어도 가능한 나머지 구성을 복원해야 한다.
- **FR-015**: 개인화 기능은 기존 mock 로그인 계정과 실제 backend 로그인 계정 모두에서 검증 가능해야 한다.

## 3. 제외 범위 *(필수)*

- 카메라 장비 등록, 삭제, 상태 수집 정책은 이 기능에서 다루지 않는다.
- RTSP ingest, transcoding, media distribution, WebRTC relay 같은 영상 전달 구현은 제외한다.
- AI inference, 영상 분석 결과, server-side overlay 생성은 제외한다.
- 사용자 권한 정책 자체의 신규 정의는 제외하고, 로그인된 사용자 식별 정보가 있다는 전제에서 동작한다.
- 여러 사용자가 같은 대시보드를 공동 편집하거나 공유하는 기능은 제외한다.
- layout 변경 이력, 감사 로그, 복구 버전 목록은 제외한다.
- 관리자에 의한 타 사용자 layout 대리 편집은 제외한다.

## 4. UI/UX 요구사항

- **UX-001**: 사용자는 라이브 대시보드 진입 시 개인 구성이 적용되었는지 별도 설명 없이 화면 상태로 확인할 수 있어야 한다.
- **UX-002**: 저장 중, 저장 완료, 저장 실패 상태는 업무 화면을 과도하게 방해하지 않는 방식으로 표시되어야 한다.
- **UX-003**: 저장 실패 상태에서는 사용자가 현재 편집 내용을 유지한 채 다시 시도할 수 있어야 한다.
- **UX-004**: 기본 구성이 제공되는 경우에도 사용자는 개인 구성이 없는 신규 상태임을 혼동하지 않아야 한다.
- **UX-005**: 사용자 전환 또는 로그아웃 후 이전 사용자의 layout이 잠깐이라도 잘못 표시되지 않아야 한다.
- **UX-006**: theme1, theme2, theme3에서 저장 상태와 오류 안내 문구가 명확하게 읽혀야 한다.
- **UX-007**: 개인화 저장/복원은 기존 라이브 대시보드의 탭, 그리드, 카메라 타일 조작 흐름을 크게 바꾸지 않아야 한다.

## 5. 필요한 정보

- 사용자는 현재 로그인한 계정을 식별할 수 있어야 한다.
- 사용자는 현재 공정탭과 세부공정탭 구성을 확인할 수 있어야 한다.
- 사용자는 현재 세부공정탭의 그리드 크기와 카메라 배치를 확인할 수 있어야 한다.
- 사용자는 저장 상태, 저장 실패 여부, 마지막으로 반영된 구성 상태를 이해할 수 있어야 한다.
- 시스템은 사용자별 공정탭 목록, 세부공정탭 목록, 활성 탭, 그리드 크기, 카메라 위치, 표시명, 직접 영상 주소 타일 정보를 유지해야 한다.
- 시스템은 신규 사용자 또는 저장 구성이 없는 사용자에게 제공할 기본 구성 기준을 알고 있어야 한다.

## 6. 사용자 시나리오 및 테스트 *(필수)*

### 사용자 스토리 1 - 내 대시보드 복원 (우선순위: P1)

운영자는 로그인 후 라이브 대시보드에 들어갔을 때 이전에 자신이 구성한 공정탭, 세부공정탭, 카메라 배치를 그대로 확인한다.

**관련 기능 요구사항**: FR-001, FR-002, FR-003, FR-010, FR-014

**이 우선순위인 이유**: 개인화 기능의 핵심 가치는 사용자가 매번 같은 화면을 다시 구성하지 않아도 되는 것이다.

**독립 테스트**: 사용자가 대시보드 구성을 변경하고 다시 로그인했을 때 변경한 구성이 복원되는지 확인한다.

**수용 시나리오**:

1. **Given** 사용자가 이전에 라이브 대시보드 구성을 저장했다, **When** 같은 계정으로 로그인해 라이브 대시보드에 진입한다, **Then** 마지막 저장 구성이 표시된다.
2. **Given** 사용자의 저장 구성이 없다, **When** 라이브 대시보드에 처음 진입한다, **Then** 기본 구성이 표시되고 사용자는 즉시 편집을 시작할 수 있다.
3. **Given** 저장 구성 중 일부 카메라 또는 영상 정보가 더 이상 유효하지 않다, **When** 라이브 대시보드가 복원된다, **Then** 유효한 구성은 유지되고 문제가 있는 항목은 이해 가능한 상태로 표시된다.

---

### 사용자 스토리 2 - 내 구성 저장 (우선순위: P1)

운영자는 공정탭, 세부공정탭, 그리드 크기, 카메라 배치를 바꾸면 자신의 라이브 대시보드 구성으로 저장되기를 기대한다.

**관련 기능 요구사항**: FR-004, FR-005, FR-006, FR-007, FR-008, FR-012, FR-013

**이 우선순위인 이유**: 편집 결과가 저장되지 않으면 개인화 복원이 의미가 없으며, 사용자는 화면을 다시 구성해야 한다.

**독립 테스트**: 사용자가 탭과 카메라 배치를 변경한 뒤 화면을 새로고침해도 변경 결과가 유지되는지 확인한다.

**수용 시나리오**:

1. **Given** 사용자가 라이브 대시보드에서 세부공정탭을 보고 있다, **When** 그리드 크기와 카메라 위치를 변경한다, **Then** 해당 변경이 사용자의 구성에 저장된다.
2. **Given** 사용자가 카메라 표시명을 변경했다, **When** 새로고침하거나 다시 로그인한다, **Then** 변경된 표시명이 유지된다.
3. **Given** 사용자가 직접 영상 주소 타일을 추가했다, **When** 같은 계정으로 다시 라이브 대시보드에 진입한다, **Then** 직접 추가한 영상 타일이 같은 세부공정탭에 표시된다.
4. **Given** 저장 중 오류가 발생했다, **When** 사용자가 계속 편집한다, **Then** 현재 화면 변경 내용은 즉시 사라지지 않고 저장 실패 상태와 재시도 가능 상태가 표시된다.

---

### 사용자 스토리 3 - 사용자별 구성 분리 (우선순위: P2)

관리자와 운영자는 같은 장비를 보더라도 각자 다른 공정탭 순서, 그리드 크기, 카메라 배치를 사용할 수 있다.

**관련 기능 요구사항**: FR-001, FR-009, FR-011, FR-015

**이 우선순위인 이유**: 개인화 기능은 사용자 간 격리가 보장되어야 하며, 한 사용자의 작업이 다른 사용자의 감시 화면을 변경하면 안 된다.

**독립 테스트**: 사용자 A와 사용자 B가 서로 다른 구성을 저장한 뒤 계정을 바꿔 로그인해 각자의 구성이 독립적으로 복원되는지 확인한다.

**수용 시나리오**:

1. **Given** 사용자 A가 2x2 그리드와 특정 카메라 배치를 저장했다, **When** 사용자 B가 로그인한다, **Then** 사용자 B는 사용자 A의 구성을 보지 않는다.
2. **Given** 사용자 B가 자신의 구성을 변경했다, **When** 사용자 A가 다시 로그인한다, **Then** 사용자 A의 기존 구성이 유지된다.
3. **Given** mock 계정과 실제 계정이 모두 존재한다, **When** 각 계정으로 라이브 대시보드를 편집한다, **Then** 계정별 구성이 서로 분리되어 유지된다.

---

### 사용자 스토리 4 - 안전한 실패와 기본값 복구 (우선순위: P3)

사용자는 저장된 구성을 불러오지 못하거나 저장하지 못하는 상황에서도 라이브 대시보드 업무를 계속할 수 있어야 한다.

**관련 기능 요구사항**: FR-003, FR-012, FR-013, FR-014

**이 우선순위인 이유**: 모니터링 화면은 장애 상황에서도 최소한의 확인이 가능해야 하며, 개인화 저장 실패가 업무 화면 자체를 막으면 안 된다.

**독립 테스트**: 저장 또는 복원 실패 상황에서 기본 구성이나 현재 화면 상태가 유지되고 사용자가 실패 원인을 인지할 수 있는지 확인한다.

**수용 시나리오**:

1. **Given** 사용자의 구성을 불러오지 못했다, **When** 라이브 대시보드에 진입한다, **Then** 기본 구성이 표시되고 복원 실패 상태가 안내된다.
2. **Given** 저장 중 오류가 발생했다, **When** 사용자가 화면을 계속 사용한다, **Then** 현재 편집 상태는 유지되고 저장 실패가 표시된다.
3. **Given** 저장된 구성에 빈 탭, 잘못된 위치, 중복 카메라 같은 문제가 있다, **When** 구성이 복원된다, **Then** 시스템은 가능한 정상 상태로 정리해 표시하고 사용자가 업무를 계속할 수 있어야 한다.

### 엣지 케이스

- 마지막 공정탭 또는 마지막 세부공정탭이 삭제된 저장 구성이 발견되면 기본 탭을 제공해야 한다.
- 저장된 활성 탭이 더 이상 존재하지 않으면 사용 가능한 첫 번째 탭을 활성화해야 한다.
- 저장된 카메라 위치가 현재 그리드 범위를 벗어나면 사용자가 이해할 수 있는 방식으로 정리되어야 한다.
- 같은 세부공정탭에 중복 카메라 또는 중복 직접 영상 주소가 저장되어 있으면 중복을 제거하거나 충돌 상태를 안내해야 한다.
- 로그아웃 직후에는 이전 사용자의 개인화 구성이 다음 로그인 사용자에게 노출되지 않아야 한다.
- 사용자가 빠르게 여러 번 변경해도 최종 화면 상태가 사용자의 기대와 다르게 되돌아가지 않아야 한다.
- 저장 실패 후 새로고침하면 마지막으로 성공한 저장 구성 또는 기본 구성이 표시되어야 한다.
- 직접 영상 주소에 민감한 인증 정보가 포함된 경우 화면 표시에서 불필요하게 노출되지 않아야 한다.

## 7. 성공 기준 *(필수)*

### 측정 가능한 결과

- **SC-001**: 저장 구성이 있는 사용자는 로그인 후 라이브 대시보드 진입 3초 이내에 자신의 마지막 구성을 확인할 수 있다.
- **SC-002**: 사용자는 탭, 그리드, 카메라 배치 중 하나를 변경한 뒤 새로고침해도 변경 결과가 유지됨을 확인할 수 있다.
- **SC-003**: 서로 다른 두 사용자가 각각 저장한 구성이 계정 전환 후에도 100% 분리되어 표시된다.
- **SC-004**: 저장 구성이 없는 신규 사용자는 별도 설정 없이 기본 라이브 대시보드를 볼 수 있다.
- **SC-005**: 저장 또는 복원 실패 상황에서도 사용자는 라이브 대시보드 화면에서 업무를 계속할 수 있다.
- **SC-006**: 사용자는 저장 실패 상태를 1개 이상의 명확한 화면 신호로 인지할 수 있다.
- **SC-007**: 기존 라이브 대시보드의 카메라 추가, 제거, 이동, Rename, 직접 영상 주소 추가 흐름은 개인화 적용 후에도 유지된다.

## 8. 가정 및 미정 사항

### 가정

- 로그인 기능은 이미 제공되며, 시스템은 현재 사용자를 구분할 수 있다.
- 002 라이브 메인 화면의 공정탭, 세부공정탭, 그리드, 카메라 배치 편집 흐름은 개인화 저장 대상이다.
- 기본 구성은 현재 라이브 대시보드에서 제공하는 development default 또는 mock layout과 동등한 업무 시작 상태로 본다.
- 개인화 구성은 사용자별 하나의 기본 라이브 대시보드 구성을 우선 대상으로 한다.
- mock 계정도 사용자별 개인화 검증 대상으로 포함한다.

### 미정 사항

- 없음. 현재 대화와 기존 001/002 산출물을 기준으로 기본 동작을 확정한다.
