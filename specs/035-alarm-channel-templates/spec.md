# 알람 채널별 메시지 템플릿 관리

**기능 브랜치**: `035-alarm-channel-templates`

**작성일**: 2026-11-26

**상태**: 초안

## 1. 기능 개요

관리자는 알람 기준 관리 화면에서 알람 유형별 앱 알람, 이메일, 팀즈 알림봇의 메시지 형식을 설정할 수 있어야 한다. 알람 발생 주체는 알람 코드와 발생 데이터만 전달하고, 각 채널의 제목·본문·메시지는 저장된 기준에 따라 생성한다.

## 2. 기능 요구사항

- **FR-001**: 관리자는 알람 기준별 앱 알람 메시지 템플릿을 입력·수정할 수 있어야 한다.
- **FR-002**: 관리자는 알람 기준별 이메일 제목과 본문 템플릿을 입력·수정할 수 있어야 한다.
- **FR-003**: 관리자는 알람 기준별 팀즈 알림봇 메시지 템플릿을 입력·수정할 수 있어야 한다.
- **FR-004**: 템플릿은 기본 변수와 함께 알람 요청의 metadata에 포함된 임의의 키를 `{{변수명}}` 형식으로 치환할 수 있어야 한다.
- **FR-005**: 템플릿이 비어 있으면 기존 알람 메시지 또는 채널 기본 형식을 사용해야 한다.
- **FR-006**: 알람 요청은 템플릿 자체가 아니라 발생 메시지와 치환용 문맥 데이터를 저장해야 한다.
- **FR-007**: 수신자별 알람 로그는 발생 시점의 템플릿 결과를 보존해야 한다.
- **FR-008**: 템플릿 저장 시 지원하지 않는 변수는 오류로 거부하지 않고 그대로 보존하되, 미리보기에서는 경고해야 한다.
- **FR-009**: 기존 알람 기준과 기존 알람 요청은 템플릿 컬럼 추가 후에도 정상 조회되어야 한다.

## 3. 범위

### 포함

- 알람 기준 마스터의 채널별 템플릿 저장
- 알람 기준 관리 화면의 템플릿 편집 영역
- 알람 요청 문맥의 JSON 보존
- 알람 로그의 앱 메시지·이메일 제목·이메일 본문·팀즈 메시지 보존
- 가입신청 및 모델 알람 fan-out에서 템플릿 치환

### 제외

- 이메일 SMTP 발송 인프라 구축
- 팀즈 Webhook/Adaptive Card 연동 구축
- 별도 템플릿 테이블 생성
- 템플릿 버전 관리

## 4. 사용자 시나리오

### US1 - 알람 기준별 채널 템플릿 설정 (P1)

관리자는 알람 기준을 선택하고 채널별 템플릿을 입력한 뒤 저장한다. 다시 조회했을 때 저장한 템플릿이 유지되어야 한다.

### US2 - 동적 알람 메시지 생성 (P1)

모델 서버 또는 회원가입 기능이 알람을 발생시키면 시스템은 알람 기준 템플릿의 변수를 실제 발생 데이터로 치환하여 수신자별 로그에 저장한다.

### US3 - 기본값 및 오류 처리 (P2)

템플릿이 비어 있거나 문맥 값이 없는 경우에도 기존 메시지를 사용해 알람 처리가 중단되지 않아야 한다.

## 5. 성공 기준

- 관리자가 알람 기준 하나의 채널별 템플릿을 저장하고 재조회할 수 있다.
- 기본 변수와 모델별 임의 metadata 변수가 실제 발생 데이터로 치환된다.
- 가입신청 알람 발생 후 수신자별 로그에 치환된 앱 메시지가 저장된다.
- 기존 템플릿이 없는 알람은 기존과 동일한 메시지로 처리된다.
- 템플릿 저장 및 조회 후 기존 수신자 설정 기능이 정상 동작한다.

## 6. 가정

- 앱 알람은 일반 텍스트를 사용한다.
- 이메일 본문은 HTML 문자열을 저장할 수 있지만 실제 발송 어댑터는 별도 범위다.
- 팀즈 메시지는 우선 일반 텍스트/Markdown 호환 문자열을 사용한다.
- 템플릿은 알람 기준에 저장하며 새 테이블은 만들지 않는다.
