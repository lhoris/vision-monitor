# 기능 명세서: 앱 기본 뼈대

**기능 브랜치**: `000-app-shell`

**작성일**: 2026-08-16

**상태**: 초안

**변경 추적**: 문서 변경 이력은 Git 커밋 이력을 기준으로 한다.

**입력**: 현재 구현된 로그인 후 공통 화면 구조, 관리자 메뉴 원문 이미지, 사용자 대화에서 정리된 상단바/사이드바/관리자 메뉴 구성 요구사항

> 이 문서는 한국어로 작성한다. 기술 용어, API 이름, 파일 경로, 코드 식별자는 원문 또는 영문 표기를 유지할 수 있다.
> 기능 명세서는 "무엇을 제공해야 하는가"를 정의한다. 구현 방식, 컴포넌트 구조, DTO/API 세부사항, 파일 경로는 plan.md 또는 contracts/에서 다룬다.

> **기능 개요 - Agent 요약**
>
> 앱 기본 뼈대는 사용자가 로그인한 뒤 모든 주요 업무 화면을 동일한 구조 안에서 사용할 수 있게 하는 공통 화면 프레임이다. 상단바는 제품 식별, 사이드바 토글, 테마 전환, 언어 전환, 알림 진입점, 사용자 메뉴와 로그아웃을 제공한다. 왼쪽 사이드바는 일반 모니터링 화면 이동뿐 아니라 관리자 메뉴 진입을 제공하며, 관리자 메뉴에는 통신 및 모델 수정과 접속 권한 관리에 필요한 메뉴가 포함되어야 한다. 단, 화면 수정 계열 메뉴는 사이드바에서 제공하지 않고 002 라이브 대시보드 내부 편집 기능으로 분리한다.

## 2. 기능 요구사항 *(필수)*

### 기능 요구사항

- **FR-001**: 인증된 사용자는 모든 보호 화면에서 공통 앱 레이아웃을 통해 화면을 사용해야 한다.
- **FR-002**: 공통 앱 레이아웃은 상단바, 왼쪽 사이드바, 본문 콘텐츠 영역을 제공해야 한다.
- **FR-003**: 상단바는 제품명 또는 서비스명을 표시해야 한다.
- **FR-004**: 상단바는 왼쪽 사이드바를 열고 닫는 동작을 제공해야 한다.
- **FR-005**: 상단바는 현재 사용자 정보를 확인할 수 있는 사용자 메뉴 진입점을 제공해야 한다.
- **FR-006**: 사용자는 사용자 메뉴에서 로그아웃을 실행할 수 있어야 한다.
- **FR-007**: 상단바는 theme1, theme2, theme3 중 현재 테마를 확인하고 변경할 수 있어야 한다.
- **FR-008**: 상단바는 한국어/영어 언어 전환 진입점을 제공해야 한다.
- **FR-009**: 상단바는 알림 상태를 확인할 수 있는 진입점을 제공해야 한다.
- **FR-010**: 왼쪽 사이드바는 라이브 대시보드, 녹화, 이벤트, 관리자 메뉴 진입점을 제공해야 한다.
- **FR-011**: 사이드바 메뉴는 현재 route와 일치하는 메뉴를 활성 상태로 표시해야 한다.
- **FR-012**: 사이드바는 overlay 형태로 열리고, 바깥 영역 클릭으로 닫힐 수 있어야 한다.
- **FR-013**: 작은 화면에서 사이드바 메뉴를 선택하면 사이드바가 자동으로 닫혀야 한다.
- **FR-014**: 인증되지 않은 사용자는 공통 앱 레이아웃이 아니라 로그인 화면으로 이동해야 한다.
- **FR-015**: 존재하지 않는 보호 route는 기본 업무 화면으로 이동해야 한다.
- **FR-016**: 사이드바는 화면 수정 계열 메뉴를 제공하지 않아야 한다.
- **FR-017**: 화면 수정 계열 작업인 공정 추가, 세부공정 추가/수정, 세부공정별 화면 배치 수정은 라이브 대시보드 내부 편집 기능으로 분리되어야 한다.
- **FR-018**: 관리자 메뉴는 통신 및 모델 수정 영역을 제공해야 한다.
- **FR-019**: 통신 및 모델 수정 영역은 모니터링 통신 현황, 제어 연동 통신 현황, 기타 주소 설정 현황, 모델 재가동, 영상 모델 추가 메뉴를 제공해야 한다.
- **FR-020**: 관리자 메뉴는 접속 권한 관리 영역을 제공해야 한다.
- **FR-021**: 접속 권한 관리 영역은 사용자 관리, 역할 관리, 권한 정책 관리, 메뉴 접근 권한 관리 메뉴를 제공해야 한다.
- **FR-022**: 권한 관리 결과는 후속 라이브 대시보드의 영상그리드 개인화 기능과 관리자 메뉴 접근 가능 여부에 영향을 줄 수 있어야 한다.
- **FR-023**: 관리자 권한이 있는 사용자에게만 관리자 메뉴가 표시되어야 한다.
- **FR-024**: 관리자 권한이 없는 사용자에게는 관리자 메뉴와 관리자 하위 메뉴가 표시되지 않아야 한다.

## 3. 제외 범위 *(필수)*

- 001 로그인 form과 인증 API 세부 동작은 이 기능 범위에서 제외한다.
- 002 라이브 메인 화면의 공정탭, 세부공정탭, 영상 그리드 상세 동작은 제외한다.
- 003 화면 확대 보기의 영상/메타데이터/녹화/알람 상세 동작은 제외한다.
- 알림 목록, 알림 상세, 알림 실시간 수신은 이 기능에서 진입점만 정의하고 상세 구현은 제외한다.
- 접속 권한 관리의 세부 CRUD 구현과 DB 설계는 후속 기능으로 분리한다.
- 통신/모델 수정 메뉴의 각 상세 화면 구현은 후속 관리자 기능으로 분리한다.
- 화면 수정 메뉴를 사이드바에 추가하는 것은 제외한다.

## 4. UI/UX 요구사항

- **UX-001**: 상단바는 모든 보호 화면에서 같은 높이와 위치를 유지해야 한다.
- **UX-002**: 본문 콘텐츠 영역은 상단바 아래 남은 영역을 사용하고, 각 업무 화면이 자체 스크롤을 가질 수 있어야 한다.
- **UX-003**: 사이드바가 열리면 본문 위에 overlay가 표시되어 사용자가 열린 상태를 인지할 수 있어야 한다.
- **UX-004**: 사이드바 메뉴는 icon과 label을 함께 제공해 빠르게 식별 가능해야 한다.
- **UX-005**: 활성 메뉴는 비활성 메뉴와 명확히 구분되어야 한다.
- **UX-006**: 테마 메뉴는 색상 swatch와 이름을 함께 제공해야 한다.
- **UX-007**: 언어/테마/사용자 메뉴는 바깥 클릭 시 닫혀야 한다.
- **UX-008**: theme1, theme2, theme3에서 상단바, 사이드바, 메뉴 텍스트, 사용자 메뉴가 읽기 쉬워야 한다.
- **UX-009**: 관리자 메뉴는 일반 모니터링 메뉴와 구분되는 그룹으로 표시되어야 한다.
- **UX-010**: 통신 및 모델 수정, 접속 권한 관리는 서로 다른 관리 영역으로 인지되어야 한다.
- **UX-011**: 원문 이미지의 화면 수정 메뉴는 최신 화면에서는 sidebar에 노출되지 않아야 한다.

## 5. 필요한 정보

- 시스템은 사용자의 인증 상태를 알아야 한다.
- 시스템은 현재 route를 기준으로 활성 사이드바 메뉴를 판단해야 한다.
- 시스템은 현재 theme mode를 알고 문서 루트에 반영해야 한다.
- 시스템은 현재 언어 설정을 알고 메뉴 label을 표시해야 한다.
- 시스템은 현재 사용자 username을 사용자 메뉴에 표시해야 한다.
- 시스템은 알림 개수 또는 알림 상태 표시 정보를 상단바에서 사용할 수 있어야 한다.
- 시스템은 관리자 메뉴 그룹과 하위 메뉴 구조를 알아야 한다.
- 시스템은 사용자의 역할 또는 권한에 따라 관리자 메뉴 노출 가능 여부를 판단해야 한다.
- 시스템은 관리자 권한이 없는 사용자에게 관리자 메뉴 데이터를 화면에 표시하지 않아야 한다.
- 시스템은 영상그리드 개인화 기능과 권한 관리의 연관성을 후속 기능에서 연결할 수 있어야 한다.

## 6. 사용자 시나리오 및 테스트 *(필수)*

### 사용자 스토리 1 - 로그인 후 공통 앱 레이아웃 보기 (우선순위: P1)

사용자는 로그인 후 상단바와 본문 영역이 있는 공통 앱 레이아웃 안에서 기본 업무 화면을 본다.

**관련 기능 요구사항**: FR-001, FR-002, FR-003, FR-014, FR-015

**이 우선순위인 이유**: 모든 로그인 후 기능이 올라가는 기반 화면이며, 이 구조가 없으면 002/003 화면 흐름도 안정적으로 제공할 수 없다.

**독립 테스트**: 인증 상태에서 `/live`에 접근하면 Header와 본문이 표시되고, 인증되지 않은 상태에서는 `/login`으로 이동하는지 확인한다.

**수용 시나리오**:

1. **Given** 사용자가 로그인되어 있다, **When** `/live`에 접근한다, **Then** 공통 상단바와 라이브 화면 본문이 표시된다.
2. **Given** 사용자가 로그인되어 있지 않다, **When** 보호 화면에 접근한다, **Then** 로그인 화면으로 이동한다.
3. **Given** 사용자가 존재하지 않는 보호 route에 접근했다, **When** route가 해석된다, **Then** 기본 업무 화면으로 이동한다.

---

### 사용자 스토리 2 - 사이드바 일반 메뉴로 주요 화면 이동 (우선순위: P2)

사용자는 왼쪽 사이드바를 열고 주요 업무 메뉴를 선택해 라이브 대시보드, 녹화, 이벤트 화면으로 이동한다.

**관련 기능 요구사항**: FR-004, FR-010, FR-011, FR-012, FR-013, FR-016, FR-017

**이 우선순위인 이유**: 로그인 후 주요 기능 간 이동을 담당하는 navigation이며, 업무 화면 확장 시 계속 재사용된다.

**독립 테스트**: 사이드바를 열어 메뉴를 선택하면 해당 route로 이동하고 현재 메뉴가 활성 상태로 표시되는지 확인한다.

**수용 시나리오**:

1. **Given** 사용자가 보호 화면을 보고 있다, **When** 상단바의 사이드바 버튼을 누른다, **Then** 사이드바와 overlay가 열린다.
2. **Given** 사이드바가 열려 있다, **When** 사용자가 Events 메뉴를 선택한다, **Then** `/events`로 이동하고 Events 메뉴가 활성 표시된다.
3. **Given** 사이드바가 열려 있다, **When** 사용자가 overlay를 클릭한다, **Then** 사이드바가 닫힌다.
4. **Given** 사이드바가 열려 있다, **When** 사용자가 메뉴 목록을 확인한다, **Then** 화면 수정, 공정 추가, 세부공정 수정, 화면 배치 수정 메뉴는 표시되지 않는다.

---

### 사용자 스토리 3 - 관리자 메뉴 구조 확인 (우선순위: P2)

관리자는 사이드바에서 관리자 메뉴를 열어 통신/모델 수정과 접속 권한 관리에 필요한 메뉴를 확인한다.

**관련 기능 요구사항**: FR-018, FR-019, FR-020, FR-021, FR-022, FR-023, FR-024

**이 우선순위인 이유**: 통신/모델 관리와 권한 관리는 후속 기능과 라이브 대시보드 개인화에 영향을 주는 공통 관리 기반이다.

**독립 테스트**: 관리자 메뉴 그룹에 통신/모델 수정 하위 메뉴와 접속 권한 관리 하위 메뉴가 표시되고, 화면 수정 계열 메뉴가 없는지 확인한다.

**수용 시나리오**:

1. **Given** 관리자가 사이드바를 열었다, **When** 관리자 메뉴를 확인한다, **Then** 통신 및 모델 수정 영역이 표시된다.
2. **Given** 통신 및 모델 수정 영역이 표시되어 있다, **When** 사용자가 하위 메뉴를 확인한다, **Then** 모니터링 통신 현황, 제어 연동 통신 현황, 기타 주소 설정 현황, 모델 재가동, 영상 모델 추가가 표시된다.
3. **Given** 관리자가 사이드바를 열었다, **When** 접속 권한 관리 영역을 확인한다, **Then** 사용자 관리, 역할 관리, 권한 정책 관리, 메뉴 접근 권한 관리가 표시된다.
4. **Given** 관리자 권한이 없는 사용자가 사이드바를 열었다, **When** 메뉴 목록을 확인한다, **Then** 관리자 메뉴와 관리자 하위 메뉴는 표시되지 않는다.

---

### 사용자 스토리 4 - 상단바의 공통 도구 사용 (우선순위: P3)

사용자는 상단바에서 테마, 언어, 사용자 메뉴, 로그아웃 같은 공통 도구를 사용한다.

**관련 기능 요구사항**: FR-005, FR-006, FR-007, FR-008, FR-009

**이 우선순위인 이유**: 기본 navigation 이후 사용자 환경과 세션 제어를 담당하는 공통 기능이다.

**독립 테스트**: 상단바에서 테마를 바꾸면 화면 테마가 바뀌고, 사용자 메뉴에서 로그아웃하면 로그인 화면으로 이동하는지 확인한다.

**수용 시나리오**:

1. **Given** 사용자가 보호 화면에 있다, **When** 테마 메뉴에서 theme1을 선택한다, **Then** 화면이 theme1 상태로 표시된다.
2. **Given** 사용자가 보호 화면에 있다, **When** 언어 메뉴에서 한국어 또는 영어를 선택한다, **Then** navigation label 언어가 변경된다.
3. **Given** 사용자가 사용자 메뉴를 열었다, **When** 로그아웃을 선택한다, **Then** 인증 상태가 해제되고 로그인 화면으로 이동한다.

### 엣지 케이스

- 메뉴 popover가 열린 상태에서 바깥을 클릭하면 열린 메뉴가 닫혀야 한다.
- 여러 메뉴 popover가 동시에 열린 경우 바깥 클릭으로 모두 닫혀야 한다.
- 작은 화면에서 사이드바 메뉴 선택 후 overlay가 남아 있으면 안 된다.
- 현재 route와 정확히 일치하지 않는 메뉴는 활성 표시되지 않아야 한다.
- 인증 상태가 바뀌면 보호 route와 로그인 route가 즉시 다시 평가되어야 한다.
- 관리자 권한이 없는 사용자는 관리자 메뉴와 관리자 하위 메뉴를 볼 수 없어야 한다.
- 관리자 권한이 없는 사용자가 관리자 route에 직접 접근하면 접근 제한 또는 기본 업무 화면 이동으로 처리되어야 한다.
- 원문 이미지에 남아 있는 화면 수정 메뉴가 최신 sidebar 요구사항으로 되살아나면 안 된다.

## 7. 성공 기준 *(필수)*

### 측정 가능한 결과

- **SC-001**: 인증된 사용자는 로그인 후 1초 이내에 상단바, 사이드바 진입점, 본문 영역을 식별할 수 있다.
- **SC-002**: 사용자는 2번 이하의 조작으로 주요 메뉴 화면으로 이동할 수 있다.
- **SC-003**: 사용자는 2번 이하의 조작으로 테마를 변경할 수 있다.
- **SC-004**: 사용자는 2번 이하의 조작으로 로그아웃할 수 있다.
- **SC-005**: theme1, theme2, theme3에서 상단바와 사이드바 메뉴 텍스트가 육안으로 명확하게 구분된다.
- **SC-006**: 관리자는 2번 이하의 조작으로 통신 및 모델 수정 메뉴 그룹을 확인할 수 있다.
- **SC-007**: 관리자는 2번 이하의 조작으로 접속 권한 관리 메뉴 그룹을 확인할 수 있다.
- **SC-008**: 사이드바에서 화면 수정 계열 메뉴가 표시되지 않음을 확인할 수 있다.
- **SC-009**: 관리자 권한이 없는 사용자는 사이드바에서 관리자 메뉴가 표시되지 않음을 확인할 수 있다.

## 8. 가정 및 미정 사항

### 가정

- 000 앱 기본 뼈대는 001 로그인 성공 이후의 보호 화면 공통 구조를 정의한다.
- 현재 일반 메뉴 구성은 라이브 대시보드, 녹화, 이벤트를 기본으로 한다.
- 설정은 일반 메뉴보다 관리자 메뉴 또는 후속 시스템 설정 구조로 편입될 수 있다.
- 알림 기능은 상단바 진입점과 카운트 표시까지만 공통 뼈대 범위에 포함한다.
- 권한별 메뉴 제어의 상세 CRUD/API 구현은 후속 기능으로 분리하되, 000에서는 관리자 메뉴 표시 여부가 관리자 권한에 의해 결정되어야 함을 정의한다.

### 미정 사항

- 실제 운영 메뉴 명칭, route, 순서는 현업 확정에 따라 후속 조정될 수 있다.
