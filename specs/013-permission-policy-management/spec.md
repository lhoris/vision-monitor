# 기능 명세서: 권한 정책 관리

**기능 브랜치**: `013-permission-policy-management`

**작성일**: 2026-08-17

**상태**: 초안

**변경 추적**: 문서 변경 이력은 Git 커밋 이력을 기준으로 한다.

**입력**: 왼쪽 사이드바 관리자 메뉴 순서에 따라 "권한 정책 관리"까지 기능명세서 작성

> **기능 개요 - Agent 요약**
>
> 권한 정책 관리는 관리자 권한 사용자가 역할별로 어떤 화면과 기능을 사용할 수 있는지 정의하는 기능이다. 관리자는 라이브 대시보드, 녹화, 이벤트, 관리자 메뉴, 영상그리드 개인화 같은 기능 영역에 대해 조회, 편집, 실행 가능 여부를 정책으로 관리할 수 있어야 한다. 이 기능은 사용자 관리와 역할 관리의 결과가 실제 화면 접근과 기능 사용에 반영되도록 하는 중심 정책 화면이며, MVP에서는 mock 정책 편집과 영향 확인 흐름을 정의한다.

## 2. 기능 요구사항 *(필수)*

### 기능 요구사항

- **FR-001**: 관리자 권한 사용자는 권한 정책 관리 화면에 진입할 수 있어야 한다.
- **FR-002**: 관리자 권한이 없는 사용자는 해당 메뉴와 화면에 접근할 수 없어야 한다.
- **FR-003**: 시스템은 역할별 권한 정책 목록을 표시해야 한다.
- **FR-004**: 시스템은 정책명, 대상 역할, 적용 범위, 사용 여부, 마지막 수정 정보를 표시해야 한다.
- **FR-005**: 사용자는 역할, 기능 영역, 사용 여부 조건으로 정책 목록을 필터링할 수 있어야 한다.
- **FR-006**: 관리자는 특정 정책의 상세 권한 항목을 확인할 수 있어야 한다.
- **FR-007**: 관리자는 역할별 화면 접근 권한을 설정할 수 있어야 한다.
- **FR-008**: 관리자는 역할별 기능 실행 권한을 설정할 수 있어야 한다.
- **FR-009**: 관리자는 라이브 대시보드 영상그리드 개인화 가능 여부를 정책으로 설정할 수 있어야 한다.
- **FR-010**: 시스템은 관리자 메뉴 접근 권한과 일반 업무 화면 권한을 구분해 표시해야 한다.
- **FR-011**: 시스템은 모든 관리자 접근 권한을 제거하는 위험한 정책 변경을 경고하거나 차단해야 한다.
- **FR-012**: 시스템은 정책 변경 전 영향 받는 역할과 사용자 수를 표시해야 한다.
- **FR-013**: 시스템은 정책 저장 성공, 실패, 처리 중 상태를 구분해 표시해야 한다.
- **FR-014**: 시스템은 정책 충돌 또는 누락으로 사용자가 기본 업무 화면에 접근할 수 없는 상태를 경고해야 한다.

## 3. 제외 범위 *(필수)*

- 실제 인증/인가 엔진 반영은 제외한다.
- 메뉴 접근 권한 전용 상세 관리 화면은 별도 메뉴 범위로 분리한다.
- 감사 로그, 승인 워크플로우, 정책 버전 비교는 제외한다.
- 데이터 행 단위 권한과 현장 조직별 상속 정책은 제외한다.
- 실제 backend 권한 검증 구현은 제외한다.

## 4. UI/UX 요구사항

- **UX-001**: 역할, 화면 접근, 기능 실행 권한의 관계가 한눈에 이해되어야 한다.
- **UX-002**: 관리자 메뉴 권한과 일반 업무 화면 권한은 명확히 구분되어야 한다.
- **UX-003**: 위험한 권한 변경은 저장 전 영향 범위와 경고가 표시되어야 한다.
- **UX-004**: 권한 항목은 체크박스나 토글처럼 빠르게 비교 가능한 방식으로 표현되어야 한다.
- **UX-005**: 정책 충돌과 누락은 저장 전에 사용자가 이해할 수 있어야 한다.
- **UX-006**: theme1, theme2, theme3에서 권한 상태, 경고, 정책명이 읽을 수 있어야 한다.

## 5. 필요한 정보

- 정책명, 대상 역할, 적용 기능 영역
- 화면 접근 가능 여부와 기능 실행 가능 여부
- 영상그리드 개인화 가능 여부
- 영향 받는 사용자 수와 역할
- 정책 충돌 또는 위험 변경 여부
- 관리자 권한 여부

## 6. 사용자 시나리오 및 테스트 *(필수)*

### 사용자 스토리 1 - 역할별 권한 정책 조회 (우선순위: P1)

관리자는 역할별 권한 정책을 목록으로 확인한다.

**관련 기능 요구사항**: FR-001, FR-002, FR-003, FR-004, FR-005

**이 우선순위의 이유**: 정책 변경 전 현재 권한 구조를 이해해야 한다.

**독립 테스트**: 관리자만 정책 목록을 볼 수 있고 역할/기능 영역 필터가 동작하는지 확인한다.

**허용 시나리오**:

1. **Given** 관리자 권한 사용자가 로그인되어 있다, **When** 권한 정책 관리 메뉴를 선택한다, **Then** 역할별 정책 목록이 표시된다.
2. **Given** 정책 목록이 표시되어 있다, **When** 사용자가 역할 필터를 선택한다, **Then** 해당 역할 정책만 표시된다.

### 사용자 스토리 2 - 권한 정책 상세 편집 (우선순위: P1)

관리자는 특정 역할의 화면 접근과 기능 실행 권한을 수정한다.

**관련 기능 요구사항**: FR-006, FR-007, FR-008, FR-009, FR-010, FR-013

**이 우선순위의 이유**: 권한 정책 관리는 실제 화면과 기능 사용 범위를 결정한다.

**독립 테스트**: 정책 상세, 권한 변경, 저장 상태가 표시되는지 확인한다.

**허용 시나리오**:

1. **Given** 정책 목록이 표시되어 있다, **When** 관리자가 특정 정책을 선택한다, **Then** 화면 접근과 기능 실행 권한 상세가 표시된다.
2. **Given** 정책 상세가 표시되어 있다, **When** 관리자가 영상그리드 개인화 권한을 변경하고 저장한다, **Then** 저장 상태가 표시된다.

### 사용자 스토리 3 - 위험 변경 방지 (우선순위: P1)

관리자는 권한 변경의 영향 범위를 확인하고 위험한 변경을 방지한다.

**관련 기능 요구사항**: FR-011, FR-012, FR-014

**이 우선순위의 이유**: 잘못된 권한 정책은 운영자가 시스템을 사용할 수 없는 상태를 만들 수 있다.

**독립 테스트**: 모든 관리자 권한 제거, 기본 업무 접근 누락, 영향 사용자 수 표시를 확인한다.

**허용 시나리오**:

1. **Given** 관리자 역할 정책이 선택되어 있다, **When** 모든 관리자 메뉴 접근 권한을 제거하려 한다, **Then** 위험 변경 경고 또는 차단이 표시된다.
2. **Given** 정책 변경으로 특정 역할의 기본 업무 화면 접근이 사라진다, **When** 저장을 시도한다, **Then** 접근 누락 경고가 표시된다.

### 엣지 케이스

- 정책 변경 후 관리자가 자기 자신을 잠그는 상황은 경고되어야 한다.
- 권한 항목 수가 많아도 화면 비교가 어려워지지 않아야 한다.
- 역할이 비활성 상태이면 정책 편집 가능 여부가 명확해야 한다.
- 정책 충돌이 있으면 저장 전에 사용자에게 설명되어야 한다.

## 7. 성공 기준 *(필수)*

### 측정 가능한 결과

- **SC-001**: 관리자는 2번 이하의 조작으로 권한 정책 관리 화면에 진입할 수 있다.
- **SC-002**: 관리자는 3초 이내에 특정 역할의 주요 권한 상태를 파악할 수 있다.
- **SC-003**: 권한 변경 전 영향 받는 역할과 사용자 수가 표시된다.
- **SC-004**: 모든 관리자 접근 권한 제거 같은 위험 변경은 확인 없이 저장되지 않는다.
- **SC-005**: 비관리자는 메뉴와 화면 내용을 볼 수 없다.
- **SC-006**: 영상그리드 개인화 권한은 일반 화면 접근 권한과 구분되어 확인된다.

## 8. 가정 및 미정 사항

### 가정

- MVP는 mock 정책 목록과 mock 저장 흐름으로 진행한다.
- 실제 권한 적용은 후속 구현에서 frontend guard와 backend 검증 계약으로 확장한다.
- 메뉴 접근 권한 관리는 다음 별도 기능에서 더 세분화될 수 있다.

### 미정 사항

- 최종 권한 항목 체계와 정책 충돌 규칙은 운영 권한 모델 확정 후 조정한다.
