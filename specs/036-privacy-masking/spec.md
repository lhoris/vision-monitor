# 기능 명세: 개인정보 표시 마스킹

## 배경

사용자 이름, 전화번호, 이메일 주소가 여러 목록과 알람·회원가입 화면에서 반복적으로 표시되고 있다. 화면마다 제각각 표시하면 개인정보가 불필요하게 노출되거나, 사용자가 연락처 정보를 혼동할 수 있다. 시스템 전체에서 동일한 표시 기준을 적용하고, 본인 및 승인 업무 담당자처럼 업무상 원문이 필요한 경우만 예외로 허용한다.

## 사용자 시나리오

### US1. 목록에서 개인정보를 안전하게 확인한다

운영자는 사용자 관리, 알람 기준 수신자, 알람 이력 등 목록 화면에서 개인정보가 일정한 형식으로 마스킹된 것을 확인한다. 연락처는 이메일과 전화번호를 동시에 노출하지 않고, 화면의 목적에 맞는 하나만 확인한다.

### US2. 본인 정보를 확인한다

로그인한 사용자는 프로필과 연락처 설정에서 자신의 이름·전화번호·이메일을 원문으로 확인하고 수정할 수 있다.

### US3. 승인 업무 담당자를 확인한다

가입 신청자는 승인 담당자의 이름과 업무 연락처를 안내받을 수 있다. 일반 사용자 목록의 개인정보 표시 기준과 달리, 실제 승인 업무에 필요한 담당자 정보는 원문으로 표시한다.

### US4. 상세 업무 화면에서 권한에 맞게 확인한다

관리자는 승인·결재 또는 업무 연락이 필요한 상세 화면에서 권한이 있는 대상의 원문을 확인하고, 권한이 없는 대상은 마스킹된 값만 확인한다.

## 기능 요구사항

- FR-001: 이름은 3글자 이상이면 첫 글자와 마지막 글자만 남기고 가운데를 `*`로 표시한다. 2글자는 첫 글자만 남기고 나머지를 마스킹한다.
- FR-002: 전화번호는 앞 3자리와 뒤 4자리를 남기고 중간을 `****`로 표시하며, 하이픈 표시 형식을 유지한다.
- FR-003: 이메일은 로컬파트의 앞 2자리만 남기고 나머지를 `*`로 표시하며 도메인은 유지한다.
- FR-004: 목록 화면은 이름을 마스킹하고, 전화번호와 이메일을 동시에 표시하지 않는다.
- FR-005: 사용자 관리 목록은 이메일을 기본 연락처로 표시하고 전화번호는 목록에서 표시하지 않는다.
- FR-006: 본인 프로필 및 본인이 수정하는 연락처 입력 화면은 원문을 표시한다.
- FR-007: 가입 승인·결재 담당자처럼 업무상 연락이 필요한 권한 있는 담당자는 이름과 연락처 원문 표시를 허용한다.
- FR-008: 권한이 없는 상세 화면과 알람 수신자 목록은 마스킹된 개인정보만 반환·표시한다.
- FR-009: 저장·수정 요청에는 마스킹된 표시값이 아닌 원문 입력값만 사용한다.
- FR-010: 개인정보가 없는 값, 빈 값, 이미 짧은 값은 오류 없이 원래 값 또는 최소 마스킹 형태로 처리한다.
- FR-011: 한국어 화면은 한국어 라벨과 마스킹 결과를 우선 표시하고 영어 화면에서도 동일한 보호 수준을 유지한다.
- FR-012: 앱 알람, SSE 알람 토스트·벨 목록, 알람 이력, 이메일, Teams 메시지에 포함된 이름·전화번호·이메일도 동일한 마스킹 규칙을 적용한다.
- FR-013: 알람 요청 원문은 감사·업무 처리를 위해 보존하되, 사용자에게 전달되는 렌더링 결과에는 원문 개인정보를 포함하지 않는다.

## 성공 기준

- 모든 대상 목록 화면에서 이름이 원문으로 노출되는 사례가 0건이다.
- 목록 화면에서 전화번호와 이메일이 동시에 노출되는 사례가 0건이다.
- 본인 프로필과 승인 담당자 화면에서 업무에 필요한 원문 연락처 확인이 가능하다.
- 이름·전화번호·이메일 마스킹 규칙에 대한 자동 테스트가 통과한다.
- 기존 사용자 수정·회원가입·알람 수신자 설정 기능이 마스킹 적용 전과 동일하게 저장된다.

## 범위 및 가정

- 계정 ID, 알람 코드, 카메라 ID처럼 개인정보가 아닌 식별자는 마스킹하지 않는다.
- 비밀번호·비밀번호 해시는 어떤 화면이나 API에서도 원문을 반환하지 않는다.
- 사용자 관리 목록은 운영자가 수정할 원문을 별도 편집 컨텍스트에서 유지하고, 표시는 마스킹 기준을 따른다.
- 업무상 원문 표시 권한은 로그인한 본인 또는 승인·결재 담당자 권한으로 판단한다.

## 제외 범위

- 데이터베이스에 저장된 개인정보 자체를 변경하거나 암호화하는 작업
- 기존 감사 로그의 과거 원문 데이터를 일괄 변환하는 작업
- 외부 메일·Teams 수신 시스템의 개인정보 마스킹 정책
