# 구현 계획: 개인정보 표시 마스킹

## 기술 방향

표시 전용 마스킹 규칙을 백엔드와 프론트엔드에 각각 공통 유틸리티로 둔다. 백엔드는 목록·알람 수신자·승인 담당자 응답을 만들 때 정책을 적용하고, 프론트엔드는 편집 모델의 원문과 화면 표시값을 분리한다. 저장 요청은 항상 원문 편집 모델을 사용한다.

## 구성

- 백엔드 `PrivacyMasking` 유틸리티: 이름·전화번호·이메일 규칙, null/짧은 값 처리
- 백엔드 DTO 매핑: 알람 관리 수신자, 가입 승인 담당자, 사용자 목록 표시 응답의 정책 적용
- 프론트엔드 `privacyMasking.ts`: 동일 규칙의 표시 보정 및 목록용 연락처 선택
- 사용자 관리 그리드: 이메일만 표시하고 전화번호는 목록에서 제외, 표시값과 편집값 분리
- 알람 관리 그리드: 수신자 이름·식별 연락처 표시 시 공통 마스킹 적용
- 본인 프로필/연락처 설정: 원문 유지
- 테스트: 백엔드 규칙 단위 테스트, 프론트 유틸리티·핵심 화면 회귀 테스트

## 보안 및 호환성

마스킹은 데이터 저장값을 변경하지 않는다. API 계약의 필드명은 유지하되 표시 목적 응답은 마스킹된 값을 사용한다. 수정 API에는 편집 화면이 보유한 원문만 전송한다.

## 검증
