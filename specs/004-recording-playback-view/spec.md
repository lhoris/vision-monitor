# 기능 명세서: 녹화영상 보기

**기능 브랜치**: `004-recording-playback-view`

**작성일**: 2026-08-17

**상태**: 초안

**변경 추적**: 문서 변경 이력은 Git 커밋 이력을 기준으로 한다.

**입력**: 왼쪽 사이드바의 녹화 메뉴를 별도 화면으로 구성하되, 003 화면 확대 보기의 녹화 기능과 유사하지만 녹화영상 탐색과 재생에 집중한다는 사용자 설명

> 이 문서는 한국어로 작성한다. 기술 용어, API 이름, 파일 경로, 코드 식별자는 원문 또는 영문 표기를 유지할 수 있다.
> 기능 명세서는 "무엇을 제공해야 하는가"를 정의한다. 구현 방식, 컴포넌트 구조, DTO/API 세부사항, 파일 경로는 plan.md 또는 contracts/에서 다룬다.

> **기능 개요 - Agent 요약**
>
> 녹화영상 보기는 운영자가 왼쪽 사이드바의 녹화 메뉴에서 특정 카메라의 과거 영상을 찾아 재생하는 독립 업무 화면이다. 003 화면 확대 보기 안의 녹화 모드는 특정 카메라를 집중 감시하다가 관련 녹화 구간을 확인하는 흐름이고, 이 기능은 녹화영상 자체를 먼저 검색하고 비교적 넓은 범위에서 탐색하는 흐름에 집중한다. 사용자는 카메라, 기간, 이벤트 조건을 기준으로 녹화 구간을 찾고, 선택한 구간을 큰 재생 영역과 타임라인 중심으로 확인할 수 있어야 한다. MVP는 mock 데이터를 기준으로 하며, 실제 영상 저장소, Media Server, RTSP ingest, server-side overlay 구현은 후속 범위로 분리한다.

## 2. 기능 요구사항 *(필수)*

### 기능 요구사항

- **FR-001**: 사용자는 왼쪽 사이드바의 녹화 메뉴에서 녹화영상 보기 화면에 진입할 수 있어야 한다.
- **FR-002**: 사용자는 녹화영상을 조회할 카메라를 선택할 수 있어야 한다.
- **FR-003**: 사용자는 조회 기간 또는 기준 시각을 선택해 녹화영상 범위를 좁힐 수 있어야 한다.
- **FR-004**: 시스템은 선택한 카메라와 기간에 해당하는 녹화 구간 또는 빈 상태를 표시해야 한다.
- **FR-005**: 사용자는 선택한 녹화 구간을 큰 재생 영역에서 재생, 일시정지, 구간 이동할 수 있어야 한다.
- **FR-006**: 시스템은 녹화 타임라인에서 재생 가능한 구간, 선택된 시점, 이벤트 발생 지점을 구분해 표시해야 한다.
- **FR-007**: 사용자는 이벤트 목록 또는 이벤트 마커를 선택해 해당 녹화 시점으로 이동할 수 있어야 한다.
- **FR-008**: 시스템은 선택한 녹화 구간과 관련된 카메라명, 공정/세부공정, 녹화 시각, 이벤트 요약을 함께 표시해야 한다.
- **FR-009**: 시스템은 녹화영상이 없거나 재생할 수 없는 상태를 사용자가 이해할 수 있게 표시해야 한다.
- **FR-010**: 시스템은 권한이 없는 카메라 또는 이벤트의 녹화 정보를 사용자에게 노출하지 않아야 한다.
- **FR-011**: 녹화영상 보기 화면은 003 화면 확대 보기의 실시간 감시 흐름을 방해하지 않아야 한다.

## 3. 제외 범위 *(필수)*

- MVP에서는 실제 Spring Boot 녹화 조회 API 구현을 제외한다.
- MVP에서는 DB migration과 녹화 이력 영속화 설계를 제외한다.
- MVP에서는 RTSP ingest, FFmpeg/transcoding, Media Server, 실제 영상 파일 저장소 연동을 제외한다.
- MVP에서는 서버 측 영상 overlay 생성과 AI inference 재처리를 제외한다.
- MVP에서는 영상 다운로드, 북마크 공유, 장기 보관 정책, 감사 로그를 제외한다.
- MVP에서는 여러 카메라 녹화영상을 동시에 동기 재생하는 멀티뷰를 제외한다.

## 4. UI/UX 요구사항

- **UX-001**: 화면의 첫 인상은 녹화영상 탐색과 재생이 중심임을 명확히 보여야 한다.
- **UX-002**: 카메라 선택, 기간 선택, 이벤트 조건은 재생 영역을 과도하게 침범하지 않는 위치에 배치되어야 한다.
- **UX-003**: 재생 영역은 화면에서 가장 큰 시각적 비중을 가져야 한다.
- **UX-004**: 타임라인은 재생 가능한 구간과 이벤트 위치를 한눈에 구분할 수 있어야 한다.
- **UX-005**: 이벤트 목록은 재생 중인 영상과 함께 확인할 수 있어야 하며, 선택 시 현재 재생 시점과 연결되어야 한다.
- **UX-006**: 녹화가 없는 기간, 카메라 미선택, 권한 없음, 재생 오류 상태는 서로 다른 빈 상태 또는 오류 상태로 구분되어야 한다.
- **UX-007**: theme1, theme2, theme3에서 타임라인, 이벤트 목록, 재생 상태, 빈 상태 메시지의 가독성이 유지되어야 한다.

## 5. 필요한 정보

- 사용자는 카메라명, 공정, 세부공정, 카메라 상태를 확인할 수 있어야 한다.
- 사용자는 조회 기간, 현재 선택된 재생 시각, 녹화 구간 시작/종료 시각을 확인할 수 있어야 한다.
- 사용자는 이벤트 종류, 심각도, 발생 시각, 관련 카메라, 재생 가능 여부를 확인할 수 있어야 한다.
- 시스템은 녹화영상 존재 여부, 로딩 상태, 빈 상태, 권한 없음, 재생 오류 상태를 구분해야 한다.
- 시스템은 003 화면 확대 보기와 동일한 카메라 표시명 정책을 따를 수 있어야 한다.

## 6. 사용자 시나리오 및 테스트 *(필수)*

### 사용자 스토리 1 - 녹화영상 화면 진입과 기본 조회 (우선순위: P1)

운영자는 사이드바에서 녹화 메뉴를 열고 카메라와 기간을 선택해 녹화영상 존재 여부를 확인한다.

**관련 기능 요구사항**: FR-001, FR-002, FR-003, FR-004, FR-009

**이 우선순위인 이유**: 녹화영상 보기의 기본 목적은 원하는 카메라와 시간대의 녹화 구간을 찾는 것이다.

**독립 테스트**: 사이드바에서 녹화 메뉴로 이동한 뒤 카메라와 기간을 선택하면 녹화 구간 또는 빈 상태가 표시되는지 확인한다.

**수용 시나리오**:

1. **Given** 사용자가 로그인 후 공통 앱 레이아웃을 보고 있다, **When** 사이드바에서 녹화 메뉴를 선택한다, **Then** 녹화영상 보기 화면이 표시된다.
2. **Given** 사용자가 녹화영상 보기 화면에 있다, **When** 카메라와 조회 기간을 선택한다, **Then** 해당 조건의 녹화 구간 또는 녹화 없음 상태가 표시된다.

---

### 사용자 스토리 2 - 녹화영상 재생과 타임라인 이동 (우선순위: P1)

운영자는 조회된 녹화 구간을 선택해 큰 재생 영역에서 영상을 보고 타임라인으로 시점을 이동한다.

**관련 기능 요구사항**: FR-005, FR-006, FR-008, FR-009

**이 우선순위인 이유**: 녹화영상 조회가 가치 있으려면 사용자가 실제로 구간을 재생하고 원하는 시점으로 이동할 수 있어야 한다.

**독립 테스트**: 녹화 구간을 선택하면 재생 영역과 타임라인의 현재 시점이 갱신되고, 타임라인 선택으로 재생 시점이 바뀌는지 확인한다.

**수용 시나리오**:

1. **Given** 조회된 녹화 구간이 있다, **When** 사용자가 구간을 선택한다, **Then** 해당 구간이 재생 영역에 표시되고 관련 정보가 함께 표시된다.
2. **Given** 녹화영상이 재생 가능한 상태다, **When** 사용자가 타임라인의 다른 시점을 선택한다, **Then** 재생 시점이 선택한 위치로 이동한다.

---

### 사용자 스토리 3 - 이벤트 기반 녹화 탐색 (우선순위: P2)

운영자는 녹화 구간 안의 이벤트 목록이나 마커를 선택해 이상 상황이 발생한 시점으로 바로 이동한다.

**관련 기능 요구사항**: FR-006, FR-007, FR-008

**이 우선순위인 이유**: 운영자는 전체 녹화영상을 처음부터 보는 것보다 이벤트 발생 시점으로 빠르게 이동해야 하는 경우가 많다.

**독립 테스트**: 이벤트 목록 또는 타임라인 이벤트 마커를 선택하면 해당 이벤트 시점으로 이동하고 이벤트 요약이 표시되는지 확인한다.

**수용 시나리오**:

1. **Given** 선택한 기간에 이벤트가 있다, **When** 사용자가 이벤트 목록의 항목을 선택한다, **Then** 녹화 재생 시점이 해당 이벤트 발생 시각으로 이동한다.
2. **Given** 타임라인에 이벤트 마커가 있다, **When** 사용자가 이벤트 마커를 선택한다, **Then** 선택한 이벤트의 요약 정보가 표시된다.

---

### 사용자 스토리 4 - 제한 상태와 오류 상태 확인 (우선순위: P3)

운영자는 녹화영상이 없거나 권한이 없거나 재생에 실패한 경우에도 현재 상태를 명확히 이해한다.

**관련 기능 요구사항**: FR-009, FR-010, FR-011

**이 우선순위인 이유**: 녹화영상은 카메라, 기간, 권한, 외부 시스템 상태에 따라 비어 있거나 실패할 수 있으므로 사용자 혼란을 줄여야 한다.

**독립 테스트**: 빈 기간, 권한 없는 카메라, 재생 오류 상태를 각각 표시하고 기존 라이브/화면 확대 보기 흐름이 유지되는지 확인한다.

**수용 시나리오**:

1. **Given** 선택한 기간에 녹화영상이 없다, **When** 조회가 완료된다, **Then** 녹화 없음 상태가 표시된다.
2. **Given** 사용자가 권한 없는 카메라를 조회하려 한다, **When** 결과가 표시된다, **Then** 제한된 녹화 정보와 이벤트 정보는 노출되지 않는다.
3. **Given** 녹화영상 재생에 실패했다, **When** 오류가 발생한다, **Then** 사용자는 재시도 가능 여부와 현재 선택 조건을 확인할 수 있다.

### 엣지 케이스

- 카메라를 선택하지 않은 상태에서는 재생 영역 대신 카메라 선택 안내가 표시되어야 한다.
- 조회 기간이 너무 넓으면 사용자가 범위를 좁혀야 함을 알 수 있어야 한다.
- 녹화 구간은 있지만 해당 시점의 영상 재생이 불가능하면 타임라인과 이벤트 정보는 가능한 경우 유지되어야 한다.
- 이벤트는 있지만 녹화영상이 없는 경우에는 이벤트 정보와 녹화 없음 상태를 함께 구분해 표시해야 한다.
- Rename된 카메라 제목이 있으면 녹화영상 보기에서도 같은 표시명을 사용해야 한다.

## 7. 성공 기준 *(필수)*

### 측정 가능한 결과

- **SC-001**: 사용자는 로그인 후 2번 이하의 조작으로 녹화영상 보기 화면에 진입할 수 있다.
- **SC-002**: 사용자는 카메라와 기간을 선택한 뒤 3초 이내에 녹화 구간 또는 빈 상태를 확인할 수 있다.
- **SC-003**: 사용자는 녹화 구간 선택 후 현재 재생 카메라, 재생 시각, 재생 가능 상태를 별도 설명 없이 식별할 수 있다.
- **SC-004**: 사용자는 이벤트 목록 또는 타임라인 마커를 통해 2번 이하의 조작으로 이벤트 시점으로 이동할 수 있다.
- **SC-005**: theme1, theme2, theme3에서 재생 상태, 타임라인, 이벤트 목록, 빈 상태 메시지가 읽을 수 있게 표시된다.
- **SC-006**: 권한이 없는 녹화 정보는 화면에 표시되지 않는다.

## 8. 가정 및 미정 사항

### 가정

- MVP는 mock 데이터 기준으로 진행한다.
- 실제 녹화영상 URL은 opaque URL로 취급하며 frontend가 영상 저장소 내부 구조를 해석하지 않는다.
- 녹화영상 보기는 사이드바의 `/playback` 메뉴에 대응하는 독립 화면이다.
- 003 화면 확대 보기의 녹화 모드와 동일한 카메라 표시명, 이벤트 요약, 권한 경계를 따른다.
- 초기 초안에서는 단일 카메라 녹화영상 탐색과 재생만 다룬다.

### 미정 사항

- 실제 운영에서 필요한 녹화 보관 기간, 조회 가능 최대 기간, 영상 다운로드 권한은 후속 명세에서 확정한다.
