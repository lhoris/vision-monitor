# 구현 계획: 알람 확인 취소

**입력 명세**: [spec.md](spec.md)

## 1. 구현 요약

기존 알람 로그 조회·확인 API에 현재 사용자 기준 전체 이력 조회와 확인 취소 API를 추가한다. 공동 확인 알람은 기존 확인 처리와 동일한 알람 그룹 판정 규칙을 재사용해 그룹 전체의 확인 상태를 되돌린다. 알람 화면은 서버 이력을 로드하고 확인 완료 상태에서 `확인 취소`를 제공하며, 성공 시 Redux 알람 상태와 상단 벨을 즉시 갱신한다.

## 2. 요구사항 추적

| 요구사항 | 계획 반영 |
|---|---|
| FR-001 | 현재 사용자 대상 알람 이력 조회와 프론트 초기 로드 |
| FR-002 | 기존 상태 필터 유지 및 서버 이력 포함 |
| FR-003~FR-005 | 확인 취소 API, 확인 창, 화면·벨 상태 갱신 |
| FR-006 | 공동 확인 그룹 전체 복원 |
| FR-007~FR-008 | 대상 검증, 오류 응답, 중복 요청 방지 |

## 3. 기술 컨텍스트

- Backend: Java 21, Spring Boot, Spring Data JPA
- Frontend: React, TypeScript, Redux Toolkit, 기존 공통 확인 창·토스트
- 저장소: 기존 `TB_M26_ALARM_LOG`와 `ALARM_GROUP_ID`, `ACKNOWLEDGED_STATUS` 사용
- 테스트: 백엔드 Maven 테스트, 프론트 TypeScript/Vite 빌드 및 관련 컴포넌트 테스트

## 4. 변경 범위

### Backend

- `AlarmLogRepository`: 현재 사용자 전체 이력 조회 파생 쿼리 추가
- `AlarmController`: 전체 이력 조회와 `/alarms/{alarmId}/unacknowledge` 추가
- 확인 취소는 현재 사용자 레코드를 먼저 검증하고, 공동 확인이면 같은 그룹의 활성 레코드를 모두 `N`으로 복원

### Frontend

- `alarmService`: 전체 이력 조회와 확인 취소 호출 추가
- `eventSlice`: 알람 이력 로드·확인 취소 thunk 및 상태 갱신 추가
- `Events`: 서버 이력 로드, 확인 완료 행/상세의 `확인 취소`, 확인 창·토스트 연결
- `ko.json`, `en.json`: 버튼·확인 창·성공/실패 메시지 추가

## 5. 검증 계획

- 공동 확인 알람의 확인 취소가 그룹 전체에 적용되는지 백엔드 테스트
- 단일 알람 확인 취소 API의 응답과 상태 검증
- 알람 화면에서 확인 완료 필터와 `확인 취소` 버튼 표시 검증
- 프론트 빌드 및 백엔드 테스트 실행
