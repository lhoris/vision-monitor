# 알람 확인 취소

**기능 브랜치**: `030-alarm-unacknowledge`
**작성일**: 2026-11-23
**상태**: 초안

## 1. 기능 개요

알람 화면에서 확인 완료된 알람을 다시 미확인 상태로 되돌릴 수 있게 한다. 사용자는 확인 완료 알람을 필터링하고, 대상 알람을 선택한 뒤 `확인 취소`를 실행할 수 있다. 되돌린 알람은 우측 상단 알람 벨의 미확인 목록에 다시 나타나야 한다.

공동 확인으로 설정된 알람은 한 건을 확인 취소할 때 같은 알람 그룹에 속한 수신자별 알람도 함께 미확인으로 복원한다.

## 2. 기능 요구사항

- **FR-001**: 시스템은 현재 로그인 사용자의 알람 이력을 확인 상태와 무관하게 조회할 수 있어야 한다.
- **FR-002**: 알람 화면은 `전체`, `미확인`, `확인 완료` 상태 필터를 제공해야 한다.
- **FR-003**: 사용자는 확인 완료 알람을 선택하고 `확인 취소`를 실행할 수 있어야 한다.
- **FR-004**: 확인 취소 전에는 대상 알람을 식별할 수 있는 확인 창을 보여줘야 하며, 취소하면 상태 변경을 수행하지 않아야 한다.
- **FR-005**: 확인 취소가 완료되면 대상 알람은 미확인 상태로 표시되고 우측 상단 알람 벨의 미확인 건수와 목록에 반영되어야 한다.
- **FR-006**: 공동 확인 알람은 동일 그룹의 관련 수신 알람을 함께 미확인으로 복원해야 한다.
- **FR-007**: 이미 삭제되었거나 현재 사용자에게 속하지 않는 알람을 확인 취소하려는 요청은 처리하지 않고 사용자에게 실패 사유를 알려야 한다.
- **FR-008**: 확인 취소 처리 중에는 중복 요청을 막고, 성공·실패 결과를 사용자에게 토스트로 알려야 한다.

## 3. 범위 제외

- 알람 기준 관리 화면의 구조 개편은 포함하지 않는다.
- 알람 자체의 삭제, 보존 기간 변경, 수신 채널 설정 변경은 포함하지 않는다.
- 확인 이력의 별도 감사 화면은 포함하지 않는다.

## 4. 사용자 시나리오

### 사용자 스토리 1 - 확인 완료 알람 복원 (P1)

관리자는 확인 완료 알람을 다시 미확인으로 돌려 재검토하고 싶다.

1. 사용자가 알람 화면에서 `확인 완료` 필터를 선택한다.
2. 시스템은 확인 완료 알람만 보여준다.
3. 사용자가 알람을 선택하고 `확인 취소`를 누른다.
4. 시스템은 확인 창을 보여준다.
5. 사용자가 확인하면 알람 상태가 미확인으로 바뀌고, 알람 벨에 다시 나타난다.

### 사용자 스토리 2 - 공동 확인 알람 복원 (P1)

공동 확인 알람을 다시 확인해야 하는 경우 그룹 전체가 동일하게 복원되어야 한다.

1. 사용자가 공동 확인으로 처리된 알람을 확인 취소한다.
2. 시스템은 같은 알람 그룹의 수신 알람을 함께 미확인으로 복원한다.
3. 각 수신자는 다음 로그인 또는 알람 갱신 시 해당 알람을 미확인으로 확인할 수 있다.

## 5. 예외 및 경계 조건

- 선택된 알람이 없으면 `확인 취소` 동작은 비활성화한다.
- 미확인 알람에 대해서는 `확인 취소` 동작을 제공하지 않는다.
- 공동 확인 그룹의 일부 레코드가 이미 비활성화된 경우 활성 레코드만 복원한다.
- 서버 처리 실패 시 화면의 확인 상태와 알람 벨 상태를 성공으로 바꾸지 않는다.

## 6. 성공 기준

- 사용자는 확인 완료 필터에서 대상 알람을 3번 이내의 클릭으로 미확인 상태로 되돌릴 수 있다.
- 확인 취소 성공 후 1초 이내에 해당 알람이 알람 벨 미확인 목록에 나타난다.
- 공동 확인 알람 확인 취소 시 같은 그룹의 활성 수신 레코드가 모두 미확인 상태가 된다.
- 확인 취소 취소 또는 실패 시 알람 상태가 변경되지 않는다.

## 7. 가정

- 알람 수신자별 확인 상태는 기존 알람 로그 레코드의 상태 컬럼으로 관리한다.
- 공동 확인 여부와 그룹 식별자는 기존 알람 기준 및 알람 로그의 값을 사용한다.
- 일반 알람은 선택한 사용자 레코드만 미확인으로 복원한다.
