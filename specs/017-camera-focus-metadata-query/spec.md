# 기능 명세서: 영상 소스별 동적 메타데이터 조회

**기능 브랜치**: `017-camera-focus-metadata-query`

**작성일**: 2026-09-18

**마지막 개정일**: 2026-09-18

**상태**: 초안

**입력**: 화면 확대 보기의 영상 소스별 메타데이터를 컴포넌트와 Query ID 기반으로 동적으로 구성하고 주기적으로 갱신하려는 사용자 요구사항

## 1. 기능 개요

영상 소스마다 화면 확대 보기 오른쪽 메타데이터 영역을 다르게 구성할 수 있어야 한다. 관리자는 섹션의 제목, 표시 순서, 위젯 형태, 데이터 Query ID, 조회 주기를 설정하고, 운영자는 해당 설정에 따라 텍스트·그리드·차트 형태의 정보를 확인한다.

Query SQL은 시스템 DB에서 관리하는 것을 목표로 하되, MVP에서는 실제 DB 실행 없이 허용 Query ID와 mock 결과를 사용한다. 실제 연동에서는 읽기 전용 Query만 실행하고 파라미터를 바인딩해야 한다.

## Clarifications

### Session 2026-09-18

- Q: 섹션 개수 정책은 어떻게 정할 것인가? A: 영상 소스마다 고정된 섹션 개수 없이 자유롭게 구성한다. 이미지의 텍스트 1개와 그리드 2개 구성은 예시 프로파일이다.
- Q: 섹션 구성 변경 권한은 누구에게 있는가? A: 모든 사용자가 영상 소스별 섹션 구성을 추가·제거·수정할 수 있다.
- Q: 영상 소스별 섹션 구성의 저장 범위는 무엇인가? A: 사용자별·영상 소스별 구성으로 저장하며 다른 사용자의 구성에는 영향을 주지 않는다.
- Q: Query SQL 관리 권한은 어떻게 정할 것인가? A: 사용자는 등록된 Query ID만 선택하고 SQL text는 개발·배포 영역에서만 관리한다.
- Q: Query 결과와 위젯 필드는 어떻게 연결할 것인가? A: Query 결과 schema를 정의하고 섹션 설정에서 표시 필드를 매핑한다.
- Q: 텍스트 섹션은 Query와 label/value 필드를 반드시 가져야 하는가? A: 아니다. Query 없이 정적 기본 텍스트만 표시할 수 있고, Query를 연결하더라도 기본 텍스트와 label/value 필드는 선택적으로 설정한다. 결과가 없거나 조회에 실패하면 기본 텍스트를 fallback으로 표시한다.

## 2. 기능 요구사항

### 메타데이터 섹션 구성

- **FR-001**: 시스템은 영상 소스별 메타데이터 섹션 구성을 관리할 수 있어야 한다.
- **FR-002**: 하나의 영상 소스는 0개 이상의 메타데이터 섹션을 가질 수 있어야 한다.
- **FR-003**: 메타데이터 섹션은 `텍스트`, `그리드`, `차트` 위젯 형태를 지원해야 한다.
- **FR-031**: MVP는 `텍스트`와 `그리드` 위젯 형태를 필수로 제공해야 한다.
- **FR-032**: 시스템은 이미지 예시와 같은 텍스트 요약 섹션, 설정 현황 그리드 섹션, 이벤트 발생 현황 그리드 섹션 조합을 하나의 구성 프로파일로 제공할 수 있어야 한다.
- **FR-033**: 이벤트 그리드 섹션은 이벤트 행의 재생 동작 또는 화면 확대 보기의 녹화 시점 이동과 연결할 수 있어야 한다.
- **FR-004**: 각 섹션은 고유 ID, 제목, 위젯 형태, 표시 순서, 표시 여부, Query ID를 가져야 한다.
- **FR-005**: 사용자는 화면 확대 보기에서 영상 소스에 설정된 섹션을 설정된 순서로 확인할 수 있어야 한다.
- **FR-006**: 사용자는 섹션을 드래그앤드롭으로 재배치할 수 있어야 한다.
- **FR-007**: 섹션 순서 변경은 해당 사용자와 영상 소스 조합의 개인화 설정으로 저장할 수 있어야 한다.
- **FR-008**: 사용자는 개인화된 순서를 기본 설정으로 초기화할 수 있어야 한다.
- **FR-025**: 사용자는 영상 소스의 개인 메타데이터 구성에 새 섹션을 추가할 수 있어야 한다.
- **FR-026**: 사용자는 섹션 추가 시 제목, 위젯 형태, Query ID, 조회 주기, 표시 옵션을 설정할 수 있어야 한다.
- **FR-027**: 사용자는 자신의 영상 소스별 메타데이터 구성에서 섹션을 제거할 수 있어야 한다.
- **FR-028**: 섹션 제거는 Query 정의나 다른 영상 소스의 섹션을 삭제하지 않고 해당 사용자의 현재 영상 소스 구성에서만 제외해야 한다.
- **FR-029**: 사용자는 제거된 섹션을 자신의 현재 영상 소스 구성에 다시 추가할 수 있어야 한다.
- **FR-030**: 사용자는 자신의 영상 소스별 구성에 포함된 섹션을 숨김 처리하거나 다시 표시할 수 있어야 한다.
- **FR-034**: 사용자별·영상 소스별 메타데이터 구성은 다른 사용자의 동일 영상 소스 구성과 독립적으로 저장되어야 한다.
- **FR-035**: 사용자가 영상 소스의 메타데이터 구성을 변경해도 다른 사용자의 화면 구성에는 영향을 주지 않아야 한다.
- **FR-036**: 사용자는 임의 SQL을 입력하거나 수정하지 않고 시스템에 등록된 Query ID만 선택해야 한다.
- **FR-037**: Query 결과 schema는 반환 필드명과 타입을 정의해야 하며, 섹션 설정은 schema에 정의된 필드만 위젯에 매핑할 수 있어야 한다.
- **FR-038**: 하나의 Query 정의는 여러 영상 소스와 여러 위젯 섹션에서 재사용할 수 있어야 한다.

### Query 기반 데이터 조회

- **FR-009**: 각 섹션은 연결된 Query ID를 기준으로 데이터를 조회해야 한다.
- **FR-010**: Query SQL과 Query ID는 시스템 DB에서 관리할 수 있어야 한다.
- **FR-011**: 실제 Query 실행은 읽기 전용 Query로 제한해야 하며, 임의 DDL·DML 실행을 허용하지 않아야 한다.
- **FR-012**: Query 파라미터에는 영상 소스 ID, 카메라 ID, 조회 시각 범위 등 시스템이 허용한 값만 전달해야 한다.
- **FR-013**: 시스템은 섹션별 데이터 조회 주기를 설정할 수 있어야 한다.
- **FR-014**: 데이터 조회 주기는 기본적으로 5초, 10초, 30초, 60초 중 하나를 선택할 수 있어야 한다.
- **FR-015**: 화면 확대 보기가 활성 상태일 때만 주기적 조회를 수행해야 한다.
- **FR-016**: 이전 Query 요청이 완료되지 않은 상태에서는 같은 섹션의 중복 요청을 실행하지 않아야 한다.
- **FR-017**: 섹션별 Query 오류는 해당 섹션 안에 표시하고 다른 섹션의 표시를 중단하지 않아야 한다.
- **FR-018**: Query 결과가 비어 있으면 해당 위젯에 빈 상태를 표시해야 한다.
- **FR-019**: 각 섹션은 마지막 성공 조회 시각 또는 데이터 미수신 상태를 표시할 수 있어야 한다.

### 위젯 표시

- **FR-020**: 텍스트 위젯은 Query 결과의 지정된 필드를 label/value 형태로 표시해야 한다.
- **FR-039**: 텍스트 위젯은 Query ID 없이 정적 기본 텍스트만 표시할 수 있어야 한다.
- **FR-040**: 텍스트 위젯은 Query ID를 연결하더라도 기본 텍스트, label field, value field를 선택적으로 설정할 수 있어야 한다.
- **FR-041**: 텍스트 위젯은 Query 결과가 없거나 조회에 실패하면 설정된 기본 텍스트를 표시해야 한다.
- **FR-021**: 그리드 위젯은 Query 결과의 여러 행과 컬럼을 표 형태로 표시해야 한다.
- **FR-022**: 차트 위젯은 Query 결과를 시계열 또는 범주형 데이터로 표시해야 한다.
- **FR-023**: 차트 위젯은 단위, 범례, 최대 표시 데이터 개수 같은 표시 옵션을 지원해야 한다.
- **FR-024**: 위젯 컴포넌트는 동일한 로딩, 오류, 빈 상태 표현을 공유해야 한다.

## 3. UI/UX 요구사항

- **UX-001**: 메타데이터 섹션은 영상 소스별 설정에 따라 표시되며, 모든 영상 소스가 동일한 섹션 구성을 강제받지 않아야 한다.
- **UX-014**: 기본 텍스트 섹션은 제목과 여러 줄의 label/value 정보 또는 정적 기본 텍스트를 세로로 읽기 쉽게 표시해야 한다.
- **UX-015**: 기본 그리드 섹션은 컬럼 제목, 행 데이터, 숫자/문자 정렬을 구분해 표시해야 한다.
- **UX-016**: 이벤트 그리드의 재생 동작은 별도 컬럼의 아이콘 또는 명확한 버튼으로 제공해야 한다.
- **UX-002**: 섹션 제목은 위젯 형태와 관계없이 동일한 헤더 규칙으로 표시해야 한다.
- **UX-003**: 섹션 순서 변경은 드래그 핸들과 드래그 대상 강조로 조작 가능 여부를 명확히 보여야 한다.
- **UX-004**: Query 갱신 중에도 기존 데이터가 있으면 기존 데이터를 유지하고 갱신 상태를 보조적으로 표시해야 한다.
- **UX-005**: Query 실패가 전체 화면을 검은 화면이나 빈 화면으로 만들지 않아야 한다.
- **UX-006**: 차트와 그리드는 작은 화면에서 가로 스크롤 또는 반응형 축소로 내용을 확인할 수 있어야 한다.
- **UX-007**: 관리자는 섹션을 숨김 처리하거나 기본 순서를 복원할 수 있어야 한다.
- **UX-012**: 섹션 구성 화면은 현재 영상 소스에 포함된 섹션과 추가 가능한 섹션을 구분해서 보여야 한다.
- **UX-013**: 섹션 제거 전에는 대상 영상 소스와 섹션 제목을 확인할 수 있어야 하며, 제거 후에도 다시 추가할 수 있어야 한다.

## 4. 제외 범위

- MVP에서는 실제 DB Query 실행과 SQL 관리용 Spring Boot API를 구현하지 않는다.
- MVP에서는 임의 SQL 입력 화면을 제공하지 않는다.
- Query SQL의 실행 계획 분석, 자동 최적화, SQL 버전 배포는 제외한다.
- Query 결과에 대한 수정, 삭제, 확인 처리 기능은 제외한다.
- 차트의 고급 분석, 다운로드, 장기 이력 저장은 제외한다.
- WebSocket/SSE 기반 push는 제외하며, MVP는 주기적 조회 mock으로 동작한다.

## 5. 사용자 시나리오 및 테스트

### 사용자 스토리 1 - 영상 소스별 섹션 구성 확인 (우선순위: P1)

운영자는 영상 소스에 설정된 메타데이터 섹션을 확인한다.

**독립 테스트**: 서로 다른 영상 소스에 서로 다른 섹션 구성과 위젯 형태를 설정하고 화면에 각각 다르게 표시되는지 확인한다.

**수용 시나리오**:

1. **Given** 영상 소스 A에는 텍스트·그리드·차트 섹션이 설정되어 있다, **When** 화면 확대 보기를 연다, **Then** 세 섹션이 설정된 순서와 형태로 표시된다.
2. **Given** 영상 소스 B에는 연결 상태 텍스트 섹션만 설정되어 있다, **When** 영상 소스 B로 전환한다, **Then** 영상 소스 A의 섹션이 남지 않고 B의 설정만 표시된다.

### 사용자 스토리 2 - Query 주기별 데이터 갱신 (우선순위: P1)

운영자는 섹션별로 설정된 주기에 따라 최신 데이터를 확인한다.

**독립 테스트**: 5초와 10초 주기를 가진 mock Query 섹션이 각각 설정된 주기로 조회되는지 확인한다.

**수용 시나리오**:

1. **Given** 연결 상태 섹션의 주기가 5초다, **When** 화면 확대 보기가 활성 상태다, **Then** 해당 섹션은 5초 주기로 데이터를 갱신한다.
2. **Given** 차트 섹션의 이전 요청이 아직 끝나지 않았다, **When** 다음 조회 주기가 도래한다, **Then** 같은 섹션의 중복 요청을 만들지 않는다.
3. **Given** 화면 확대 보기를 벗어났다, **When** 다음 조회 주기가 도래한다, **Then** 해당 화면의 주기적 조회를 중단한다.

### 사용자 스토리 3 - 위젯별 Query 결과 표시 (우선순위: P1)

운영자는 같은 Query 기반 데이터라도 설정된 위젯 형태에 맞게 정보를 확인한다.

**독립 테스트**: 텍스트, 그리드, 차트 mock Query 결과가 각 위젯에 맞게 표시되는지 확인한다.

**수용 시나리오**:

1. **Given** 텍스트 섹션 Query가 label/value 결과를 반환한다, **When** 조회가 완료된다, **Then** 텍스트 위젯에 필드명이 표시된다.
2. **Given** 그리드 섹션 Query가 여러 행을 반환한다, **When** 조회가 완료된다, **Then** 컬럼과 행이 표 형태로 표시된다.
3. **Given** 차트 섹션 Query가 시간과 값의 배열을 반환한다, **When** 조회가 완료된다, **Then** 추이 차트로 표시된다.

### 사용자 스토리 7 - 기본 메타데이터 구성 확인 (우선순위: P1)

운영자는 영상 소스에서 진행 상태 텍스트, 설정 현황 그리드, 이벤트 발생 현황 그리드를 확인한다.

**독립 테스트**: 예시 구성 프로파일이 적용된 mock 영상 소스에 텍스트·표·이벤트 재생 동작을 각각 확인한다.

**수용 시나리오**:

1. **Given** 영상 소스에 예시 구성 프로파일이 적용되어 있다, **When** 화면 확대 보기를 연다, **Then** 진행 상태 텍스트 섹션이 표시된다.
2. **Given** 설정 현황 Query가 여러 행을 반환한다, **When** 조회가 완료된다, **Then** 냉각 코드·기존 속도·증속 속도·유지 시간 컬럼을 가진 그리드가 표시된다.
3. **Given** 이벤트 발생 현황 Query가 여러 이벤트를 반환한다, **When** 조회가 완료된다, **Then** 구분·규격·사이즈·이벤트 시간·재생 컬럼을 가진 그리드가 표시된다.
4. **Given** 이벤트 행에 재생 가능한 기록이 있다, **When** 사용자가 재생 동작을 선택한다, **Then** 해당 이벤트의 녹화 시점으로 이동한다.

### 사용자 스토리 4 - Query 상태 확인 (우선순위: P1)

운영자는 섹션별 데이터 정상 여부를 확인한다.

**수용 시나리오**:

1. **Given** 한 섹션의 Query가 실패한다, **When** 다른 섹션은 정상 응답한다, **Then** 실패한 섹션에 오류가 표시되고 다른 섹션은 계속 표시된다.
2. **Given** Query 결과가 없다, **When** 조회가 완료된다, **Then** 해당 섹션에 빈 상태가 표시된다.

### 사용자 스토리 5 - 섹션 순서 개인화 (우선순위: P2)

운영자는 영상 소스별 메타데이터 섹션 순서를 업무 흐름에 맞게 조정한다.

**수용 시나리오**:

1. **Given** 세 개의 섹션이 표시되어 있다, **When** 사용자가 섹션을 드래그한다, **Then** 화면의 섹션 순서가 변경된다.
2. **Given** 사용자가 소스 A의 순서를 변경했다, **When** 소스 A를 다시 열거나 새로고침한다, **Then** 저장된 순서가 복원된다.
3. **Given** 사용자가 개인화 순서를 사용 중이다, **When** 기본 순서를 선택한다, **Then** 소스 기본 설정 순서로 복원된다.

### 사용자 스토리 6 - 영상 소스별 섹션 구성 관리 (우선순위: P1)

사용자는 영상 소스마다 필요한 메타데이터 섹션을 추가하거나 제거한다.

**독립 테스트**: 사용자가 새 섹션을 추가하고 기존 섹션을 제거한 뒤, 같은 영상 소스를 보는 다른 사용자의 화면에는 영향이 없는지 확인한다.

**수용 시나리오**:

1. **Given** 사용자가 영상 소스 A의 개인 메타데이터 구성을 편집하고 있다, **When** 텍스트 위젯과 Query ID를 설정해 섹션을 추가한다, **Then** 해당 사용자의 영상 소스 A 구성에 새 섹션이 추가된다.
2. **Given** 영상 소스 A에 차트 섹션이 포함되어 있다, **When** 사용자가 해당 섹션을 제거한다, **Then** 영상 소스 A의 화면 확대 보기에서 해당 섹션이 표시되지 않는다.
3. **Given** 사용자가 영상 소스 A에서 섹션을 제거했다, **When** 사용자가 추가 가능한 섹션에서 해당 섹션을 다시 선택한다, **Then** 자신의 영상 소스 A 구성에 섹션이 복원된다.
4. **Given** 사용자 A가 영상 소스 A의 섹션 구성을 변경했다, **When** 사용자 B가 영상 소스 A를 확인한다, **Then** 사용자 B의 구성은 영향을 받지 않는다.

## 6. 엣지 케이스

- Query ID가 존재하지 않으면 설정 오류를 표시하고 해당 섹션을 안전한 빈 상태로 표시해야 한다.
- Query 결과 컬럼이 위젯 설정과 일치하지 않으면 오류 원인과 함께 표시해야 한다.
- Query 응답이 주기보다 오래 걸리면 다음 요청을 중복 실행하지 않아야 한다.
- 하나의 섹션이 실패해도 다른 섹션의 조회와 렌더링은 계속되어야 한다.
- 저장된 개인화 순서가 현재 섹션 구성과 일치하지 않으면 유효한 섹션만 유지하고 새 섹션은 기본 순서에 추가해야 한다.
- 섹션을 제거해도 해당 섹션의 Query 정의와 다른 영상 소스 설정은 보존되어야 한다.
- 모든 섹션을 제거한 영상 소스는 명확한 빈 상태와 섹션 추가 진입점을 표시해야 한다.
- 화면 확대 보기의 영상 소스가 바뀌면 이전 영상 소스의 polling이 남지 않아야 한다.

## 7. 성공 기준

- **SC-001**: 관리자는 영상 소스별로 다른 메타데이터 구성을 확인할 수 있다.
- **SC-002**: 설정된 조회 주기에 따라 각 섹션의 mock 데이터가 갱신된다.
- **SC-003**: 한 섹션의 Query 실패가 다른 섹션의 표시를 중단시키지 않는다.
- **SC-004**: 텍스트·그리드·차트 위젯이 각 데이터 형태에 맞게 표시된다.
- **SC-005**: 화면 확대 보기를 벗어난 뒤 해당 화면의 주기적 조회가 중단된다.
- **SC-006**: 사용자가 변경한 영상 소스별 섹션 순서와 구성 변경이 다음 진입에서도 복원된다.
- **SC-007**: 실제 DB 연동 전에도 mock Query Registry로 전체 화면 흐름을 검증할 수 있다.
- **SC-008**: 사용자는 영상 소스별로 섹션을 추가·제거·복원할 수 있고, 사용자의 변경이 다른 사용자의 동일 영상 소스에 영향을 주지 않는다.
- **SC-009**: 영상 소스별로 서로 다른 개수와 조합의 메타데이터 섹션을 구성하고 표시할 수 있다.

## 8. 데이터 모델

### MetadataLayoutProfile

- `userId`: 구성 소유 사용자 식별자
- `sourceId`: 영상 소스 식별자
- `sections`: 영상 소스의 섹션 설정 목록

### MetadataSectionConfig

- `id`: 섹션 식별자
- `title`: 화면 표시명
- `type`: `text` | `grid` | `chart`
- `order`: 기본 표시 순서
- `visible`: 표시 여부
- `queryId`: 연결된 Query 식별자. 텍스트 섹션에서는 생략할 수 있다.
- `refreshIntervalSec`: `5` | `10` | `30` | `60`
- `mapping`: Query 결과와 위젯 필드의 매핑 설정
- `defaultText`: Query 결과가 없거나 정적 텍스트만 사용할 때 표시할 기본 텍스트
- `options`: 위젯 표시 옵션
- `sourceProfileStatus`: 영상 소스 기본 구성에서 `included` 또는 `excluded`

### MetadataQueryDefinition

- `queryId`: Query 식별자
- `sqlText`: 서버가 관리하는 읽기 전용 SQL
- `allowedParameters`: 허용 파라미터 목록
- `resultSchema`: 반환 컬럼과 타입 정의
- `enabled`: 사용 여부

## 9. 가정 및 후속 범위

- MVP는 frontend mock Query Registry와 mock polling으로 구현한다.
- 실제 Query SQL은 backend와 DB에서 관리하고 frontend는 Query ID만 사용한다.
- 실제 연동 시 SQL은 읽기 전용으로 제한하고, 파라미터 바인딩과 권한 검증을 거친다.
- Query 편집·활성화·비활성화 관리 화면은 관리자 기능으로 별도 정의할 수 있다.
- Query 결과의 표준 응답 형식과 차트 데이터 schema는 plan 단계에서 계약으로 구체화한다.
