# 기능 명세서: 화면 확대 보기

**기능 브랜치**: `003-camera-focus-view`

**작성일**: 2026-08-16

**상태**: 초안

**변경 추적**: 문서 변경 이력은 Git 커밋 이력을 기준으로 한다.

**입력**: BMAD 산출물과 사용자 대화에서 정리된 화면 확대 보기 요구사항

> 이 문서는 한국어로 작성한다. 기술 용어, API 이름, 파일 경로, 코드 식별자는 원문 또는 영문 표기를 유지할 수 있다.
> 기능 명세서는 "무엇을 제공해야 하는가"를 정의한다. 구현 방식, 컴포넌트 구조, DTO/API 세부사항, 파일 경로는 plan.md 또는 contracts/에서 다룬다.

> **기능 개요 - Agent 요약**
>
> 화면 확대 보기는 운영자가 카메라 그리드에서 특정 카메라를 선택해 큰 화면으로 실시간 영상 또는 녹화 영상을 확인하는 기능이다. 확대 화면에서는 진입 전 그리드의 카메라 목록 맥락을 유지하고, 영상 옆에는 카메라/이벤트/알람 관련 정보를 함께 표시한다. MVP는 frontend mock service와 fixture를 기준으로 구현하며, 실제 Spring Boot API, RTSP ingest, AI inference, Media Server 직접 구현은 후속 범위로 분리한다. 알람/경고는 영상 시야를 과도하게 방해하지 않는 위치에 표시하고, 사용자가 클릭으로 자연스럽게 닫을 수 있어야 한다.

## 2. 기능 요구사항 *(필수)*

### 기능 요구사항

- **FR-001**: 사용자는 카메라 그리드에서 특정 카메라를 화면 확대 보기로 열 수 있어야 한다.
- **FR-002**: 화면 확대 보기는 진입 전 공정/세부공정 그리드에 표시되던 카메라 목록만 전환 대상으로 제공해야 한다.
- **FR-003**: 사용자는 화면 확대 보기에서 실시간 영상과 녹화 영상을 전환할 수 있어야 한다.
- **FR-004**: 녹화 화면에서는 타임라인, 이벤트 마커, 이벤트 목록을 확인하고 이벤트 선택으로 관련 시점으로 이동할 수 있어야 한다.
- **FR-005**: 화면 확대 보기에는 선택한 카메라의 메타데이터, 이벤트 정보, 활성 알람 정보를 영상과 함께 확인할 수 있어야 한다.
- **FR-006**: 알람/경고 메시지는 영상 시야를 과도하게 방해하지 않는 위치에 표시되고, 사용자가 마우스 클릭으로 닫을 수 있어야 한다.
- **FR-007**: 카메라 타일에서 Rename한 제목은 그리드와 화면 확대 보기에서 일관되게 표시되어야 한다.
- **FR-008**: 영상 제목, 온라인 상태, 확대 버튼 등 메타데이터성 UI는 영상 자체를 침범하지 않도록 배치되어야 한다.
- **FR-009**: theme1, theme2, theme3에서 제목, Rename dialog, 알람/경고, 녹화 UI의 글자와 상태 표시가 명확하게 보여야 한다.
- **FR-010**: 영상, 메타데이터, 이벤트, 알람 중 일부가 실패해도 성공한 영역은 계속 사용할 수 있어야 한다.
- **FR-011**: 권한 없음 상태에서는 제한된 카메라/이벤트 메타데이터가 노출되지 않아야 한다.

## 3. 제외 범위 *(필수)*

- MVP에서는 실제 Spring Boot controller/service/repository/entity 구현을 제외한다.
- MVP에서는 DB migration과 서버 영속화를 제외한다.
- MVP에서는 RTSP ingest, FFmpeg/transcoding, Media distribution 직접 구현을 제외한다.
- MVP에서는 AI inference, server-side overlay, 원본 영상 저장/보관을 제외한다.
- MVP에서는 PTZ control과 다중 카메라 비교 보기를 제외한다.
- 서버 ACK 기반 알람 워크플로우와 WebSocket/SSE push는 후속 범위로 분리한다.

## 4. UI/UX 요구사항

- **UX-001**: 화면 확대 보기의 상단 카메라 전환 목록은 진입 전 그리드의 카메라 목록 맥락을 유지해야 한다.
- **UX-002**: 카메라 타이틀과 온라인 상태는 영상 영역 바깥의 헤더에 배치되어야 한다.
- **UX-003**: 확대 버튼은 기본 상태에서 시선을 과도하게 끌지 않고, 마우스 오버 시 명확하게 드러나야 한다.
- **UX-004**: Add Camera 영역은 실제 영상 타일과 같은 크기 체계를 유지해야 한다.
- **UX-005**: Rename 팝업은 모든 테마에서 입력 글자가 명확하게 보여야 한다.
- **UX-006**: 알람/경고 토스트는 화면 확대 보기에서 영상 시야를 방해하지 않는 중앙 상단/중앙 근처 위치에 표시되어야 한다.
- **UX-007**: 알람/경고 토스트는 등장과 사라짐 모두 자연스러운 toast-like motion을 가져야 한다.
- **UX-008**: 테스트 알람은 별도 dialog에서 메시지를 입력해 수동 생성할 수 있어야 한다.
- **UX-009**: 녹화 타임라인과 이벤트 목록은 theme2/theme3에서도 충분한 대비를 유지해야 한다.

## 5. 필요한 정보

- 사용자는 카메라명, Rename된 표시명, 공정/세부공정, 온라인 상태를 확인할 수 있어야 한다.
- 사용자는 실시간 영상 재생 가능 여부와 녹화 영상 재생 가능 여부를 구분할 수 있어야 한다.
- 사용자는 이벤트 종류, 심각도, 발생 시각, 관련 카메라, 재생 위치를 확인할 수 있어야 한다.
- 사용자는 활성 알람 메시지, 발생 위치, 관련 이벤트, 발생 시각을 확인할 수 있어야 한다.
- 시스템은 오류, 빈 상태, 권한 없음, 로딩 상태를 영역별로 구분해 표시해야 한다.

## 6. 사용자 시나리오 및 테스트 *(필수)*

### 사용자 스토리 1 - 그리드에서 화면 확대 보기 진입 (우선순위: P1)

운영자는 카메라 그리드에서 특정 카메라를 선택해 큰 화면으로 실시간 영상을 확인한다.

**관련 기능 요구사항**: FR-001, FR-002, FR-003, FR-008

**이 우선순위인 이유**: 화면 확대 보기의 핵심 진입 흐름이며, 이 흐름 없이는 나머지 메타데이터/녹화/알람 기능도 사용할 수 없다.

**독립 테스트**: 카메라 그리드에서 확대 버튼을 선택하면 해당 카메라의 화면 확대 보기로 이동하고, 진입 전 그리드의 카메라 목록만 상단 전환 목록에 표시되는지 확인한다.

**수용 시나리오**:

1. **Given** 사용자가 특정 공정/세부공정의 카메라 그리드를 보고 있다, **When** 특정 카메라의 확대 동작을 실행한다, **Then** 해당 카메라의 화면 확대 보기로 이동한다.
2. **Given** 사용자가 Production Line B의 특정 세부탭에서 카메라 2개가 있는 그리드에서 진입했다, **When** 화면 확대 보기가 열린다, **Then** 상단 카메라 목록에는 그 2개 카메라만 표시된다.

---

### 사용자 스토리 2 - 실시간/녹화 영상 전환과 이벤트 탐색 (우선순위: P2)

운영자는 화면 확대 보기에서 실시간 영상과 녹화 영상을 전환하고, 녹화 이벤트를 선택해 관련 시점으로 이동한다.

**관련 기능 요구사항**: FR-003, FR-004, FR-005, FR-010

**이 우선순위인 이유**: 화면 확대 보기의 운영 가치를 실시간 감시에서 이벤트 기반 원인 확인까지 확장한다.

**독립 테스트**: 화면 확대 보기에서 녹화 모드로 전환한 뒤 이벤트를 선택하면 타임라인/이벤트 목록/재생 위치가 함께 갱신되는지 확인한다.

**수용 시나리오**:

1. **Given** 사용자가 화면 확대 보기에 있다, **When** 녹화 모드를 선택한다, **Then** 녹화 영상, 타임라인, 이벤트 목록이 표시된다.
2. **Given** 녹화 이벤트 목록이 표시되어 있다, **When** 사용자가 이벤트를 선택한다, **Then** 해당 이벤트 시점으로 이동하고 관련 메타데이터가 표시된다.

---

### 사용자 스토리 3 - 알람/경고 확인과 닫기 (우선순위: P3)

운영자는 화면 확대 보기에서 활성 알람/경고를 확인하고, 확인 버튼 없이 마우스 클릭으로 자연스럽게 닫는다.

**관련 기능 요구사항**: FR-005, FR-006, FR-009

**이 우선순위인 이유**: 알람/경고는 긴급성을 가져야 하지만 영상 감시를 방해하지 않아야 한다.

**독립 테스트**: 테스트 알람 dialog에서 메시지를 입력해 알람을 표시하고, 토스트를 클릭하면 자연스럽게 사라지는지 확인한다.

**수용 시나리오**:

1. **Given** 사용자가 화면 확대 보기에 있다, **When** 테스트 알람 메시지를 입력해 생성한다, **Then** 입력한 메시지로 경고 토스트가 표시된다.
2. **Given** 경고 토스트가 표시되어 있다, **When** 사용자가 토스트를 클릭한다, **Then** 토스트가 자연스럽게 사라진다.

---

### 사용자 스토리 4 - 카메라 제목 Rename 일관성 (우선순위: P3)

운영자는 카메라 타일 제목을 Rename하고, 변경된 제목을 그리드와 화면 확대 보기에서 일관되게 확인한다.

**관련 기능 요구사항**: FR-007, FR-009

**이 우선순위인 이유**: 운영자가 현장 명칭에 맞게 카메라를 식별해야 하며, 화면 전환 후 제목이 달라지면 혼란이 발생한다.

**독립 테스트**: 그리드에서 카메라 제목을 Rename한 뒤 화면 확대 보기로 진입하면 상단 카메라 목록, 영상 헤더, 메타데이터에서 같은 제목이 표시되는지 확인한다.

**수용 시나리오**:

1. **Given** 사용자가 그리드에서 카메라 제목을 변경했다, **When** 해당 카메라의 화면 확대 보기에 진입한다, **Then** 변경된 제목이 화면 확대 보기에서도 표시된다.

### 엣지 케이스

- 진입한 source grid context가 없으면 전체 카메라 목록이 아니라 합리적인 fallback 목록을 표시해야 한다.
- 카메라 영상 로딩이 실패해도 메타데이터/이벤트 패널은 가능한 경우 계속 표시되어야 한다.
- 권한 없음 응답에서는 제한된 메타데이터가 DOM에 노출되지 않아야 한다.
- Rename 제목이 비어 있거나 너무 길면 UI가 깨지지 않아야 한다.
- 알람이 닫힌 뒤 같은 route session에서는 다시 튀어나오지 않아야 한다.

## 7. 성공 기준 *(필수)*

### 측정 가능한 결과

- **SC-001**: 사용자는 카메라 그리드에서 2번 이하의 조작으로 화면 확대 보기에 진입할 수 있다.
- **SC-002**: 화면 확대 보기 진입 후 사용자는 현재 카메라명, 온라인 상태, 실시간/녹화 모드를 별도 설명 없이 식별할 수 있다.
- **SC-003**: 사용자는 진입 전 세부탭의 카메라 목록과 화면 확대 보기의 카메라 목록이 일치함을 확인할 수 있다.
- **SC-004**: theme1, theme2, theme3에서 제목, dialog, 알람/경고, 녹화 UI의 핵심 텍스트가 읽을 수 있게 표시된다.
- **SC-005**: 영상, 메타데이터, 이벤트, 알람 중 하나의 mock 요청이 실패해도 다른 성공 영역은 계속 사용할 수 있다.
- **SC-006**: 전체 frontend 테스트와 production build가 통과한다.

## 8. 가정 및 미정 사항

### 가정

- MVP는 frontend mock service/mock adapter 기준으로 진행한다.
- 기존 카메라 그리드와 React/Vite frontend 구조를 유지한다.
- 화면 확대 보기의 사용자-facing 명칭은 "화면 확대 보기"를 우선 사용한다.
- 실제 영상 URL은 opaque URL로 취급하며 frontend가 업무 로직으로 해석하지 않는다.
