# 기능 명세서: 영상 모델 추가

**기능 브랜치**: `010-video-model-create`

**작성일**: 2026-08-17

**상태**: 초안

**변경 추적**: 문서 변경 이력은 Git 커밋 이력을 기준으로 한다.

**입력**: 왼쪽 사이드바 관리자 메뉴 순서에 따라 "영상 모델 추가" 기능명세서 작성

> **기능 개요 - Agent 요약**
>
> 영상 모델 추가는 관리자 권한 사용자가 신규 영상 분석 모델을 등록하기 위한 기본 정보를 입력하고 등록 전 검토하는 기능이다. 관리자는 모델명, 적용 목적, 대상 공정/카메라, 버전, 설명, 사용 여부를 입력하고 기존 모델과 혼동되지 않게 관리할 수 있어야 한다. MVP에서는 등록 화면과 입력 검증, mock 저장 흐름만 정의하며 실제 모델 파일 업로드, 배포, 추론 연결은 후속 범위로 둔다.

## 1. 참고 이미지 및 원문 자료

| 상태 | 자료 | 설명 | 비고 |
|------|------|------|------|
| active | 제공된 원문 자료 없음 | 영상 모델 추가 전용 화면 스케치는 아직 제공되지 않음 | 메뉴명과 운영 맥락 기준 초안 |

## 2. 기능 요구사항 *(필수)*

### 기능 요구사항

- **FR-001**: 관리자 권한 사용자는 영상 모델 추가 화면에 진입할 수 있어야 한다.
- **FR-002**: 관리자 권한이 없는 사용자는 해당 메뉴와 화면에 접근할 수 없어야 한다.
- **FR-003**: 시스템은 신규 모델 등록에 필요한 입력 화면을 제공해야 한다.
- **FR-004**: 사용자는 모델명, 모델 목적, 대상 공정/카메라, 버전, 설명, 사용 여부를 입력할 수 있어야 한다.
- **FR-005**: 시스템은 필수 입력값 누락을 저장 전에 표시해야 한다.
- **FR-006**: 시스템은 모델명과 버전 조합이 기존 모델과 충돌하는 경우 사용자에게 알려야 한다.
- **FR-007**: 사용자는 입력 내용을 저장 전 검토할 수 있어야 한다.
- **FR-008**: 사용자는 등록을 취소하고 이전 상태로 돌아갈 수 있어야 한다.
- **FR-009**: 시스템은 등록 성공, 실패, 처리 중 상태를 구분해 표시해야 한다.
- **FR-010**: 시스템은 모델 등록이 곧바로 실제 추론 배포를 의미하지 않음을 표시해야 한다.
- **FR-011**: 시스템은 등록 후 모델 재가동 또는 배포가 필요한 경우 후속 조치가 필요함을 안내해야 한다.

## 3. 제외 범위 *(필수)*

- 실제 모델 파일 업로드와 저장은 제외한다.
- 실제 모델 배포, 추론 연결, 서버 반영은 제외한다.
- 모델 학습, 성능 평가, 버전 비교는 제외한다.
- 승인 워크플로우와 배포 예약 기능은 제외한다.

## 4. UI/UX 요구사항

- **UX-001**: 입력 항목은 기본 정보, 적용 대상, 운영 상태로 구분되어야 한다.
- **UX-002**: 필수 입력 오류는 해당 입력 영역 근처에 표시되어야 한다.
- **UX-003**: 저장 전 검토 화면은 사용자가 등록 대상을 다시 확인할 수 있어야 한다.
- **UX-004**: 취소 동작은 입력 중인 내용 손실 가능성을 알 수 있어야 한다.
- **UX-005**: theme1, theme2, theme3에서 입력값과 오류 메시지가 읽을 수 있어야 한다.

## 5. 필요한 정보

- 모델명, 모델 목적, 모델 버전
- 대상 공정과 대상 카메라
- 모델 설명과 사용 여부
- 중복 여부와 등록 처리 상태
- 관리자 권한 여부

## 6. 사용자 시나리오 및 테스트 *(필수)*

### 사용자 스토리 1 - 신규 모델 정보 입력 (우선순위: P1)

관리자는 신규 영상 모델의 기본 정보를 입력한다.

**관련 기능 요구사항**: FR-001, FR-002, FR-003, FR-004, FR-005

**이 우선순위의 이유**: 모델 추가 기능의 핵심은 올바른 기본 정보를 빠짐없이 입력하는 것이다.

**독립 테스트**: 필수 입력값과 오류 표시, 비관리자 접근 제한을 확인한다.

**허용 시나리오**:

1. **Given** 관리자 권한 사용자가 로그인되어 있다, **When** 영상 모델 추가 메뉴를 선택한다, **Then** 신규 모델 입력 화면이 표시된다.
2. **Given** 필수 입력값이 비어 있다, **When** 사용자가 저장을 시도한다, **Then** 누락된 입력값 오류가 표시된다.

### 사용자 스토리 2 - 중복 검토와 저장 (우선순위: P2)

관리자는 입력한 모델 정보가 기존 모델과 충돌하지 않는지 확인하고 저장한다.

**관련 기능 요구사항**: FR-006, FR-007, FR-009, FR-010, FR-011

**이 우선순위의 이유**: 모델명/버전 충돌은 운영 혼선을 만들 수 있다.

**독립 테스트**: 중복 표시, 저장 전 검토, 저장 결과 메시지를 확인한다.

**허용 시나리오**:

1. **Given** 기존 모델과 같은 모델명/버전이 입력되어 있다, **When** 저장을 시도한다, **Then** 충돌 안내가 표시된다.
2. **Given** 입력값이 유효하다, **When** 사용자가 저장 전 검토를 완료하고 등록한다, **Then** 등록 성공 상태가 표시된다.

### 사용자 스토리 3 - 등록 취소 (우선순위: P3)

관리자는 모델 등록을 취소하고 이전 화면으로 돌아간다.

**관련 기능 요구사항**: FR-008

**이 우선순위의 이유**: 입력 도중 잘못 진입했거나 등록이 필요 없어진 경우 안전하게 빠져나갈 수 있어야 한다.

**독립 테스트**: 취소 시 입력 손실 안내와 이전 상태 복귀를 확인한다.

**허용 시나리오**:

1. **Given** 사용자가 입력을 시작했다, **When** 취소를 선택한다, **Then** 입력 손실 가능성이 표시되고 사용자가 확정하면 이전 상태로 돌아간다.

### 엣지 케이스

- 긴 모델명과 설명이 레이아웃을 깨뜨리지 않아야 한다.
- 대상 카메라가 선택되지 않은 경우 명확한 오류를 표시해야 한다.
- 등록 실패 후 입력값은 유지되어야 한다.

## 7. 성공 기준 *(필수)*

### 측정 가능한 결과

- **SC-001**: 관리자는 2번 이하의 조작으로 영상 모델 추가 화면에 진입할 수 있다.
- **SC-002**: 필수 입력 누락은 저장 전에 1초 이내 표시된다.
- **SC-003**: 중복 모델명/버전은 등록 전에 식별된다.
- **SC-004**: 등록 성공/실패/처리 중 상태가 명확히 표시된다.
- **SC-005**: 비관리자는 메뉴와 화면 내용을 볼 수 없다.

## 8. 가정 및 미정 사항

### 가정

- MVP는 mock 저장 흐름으로 진행한다.
- 실제 모델 파일과 배포는 후속 기능에서 다룬다.

### 미정 사항

- 모델 목적과 대상 공정의 최종 분류는 운영 정책 확정 후 조정한다.
