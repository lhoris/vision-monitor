# 기능 명세서: 모델 재가동

**기능 브랜치**: `009-model-restart`

**작성일**: 2026-08-17

**상태**: 초안

**변경 추적**: 문서 변경 이력은 Git 커밋 이력을 기준으로 한다.

**입력**: 왼쪽 사이드바 관리자 메뉴 순서에 따라 "모델 재가동" 기능명세서 작성

> **기능 개요 - Agent 요약**
>
> 모델 재가동은 관리자 권한 사용자가 영상 분석 모델의 현재 상태를 확인하고, 필요한 경우 특정 모델의 재가동을 요청하는 운영 기능이다. 관리자는 모델명, 적용 공정/카메라, 상태, 마지막 재가동 시각을 확인하고, 재가동 대상과 영향 범위를 이해한 뒤 조작해야 한다. MVP에서는 재가동 요청 화면과 상태 흐름을 mock으로 정의하며, 실제 모델 프로세스 제어는 후속 범위로 둔다.

## 1. 참고 이미지 및 원문 자료

| 상태 | 자료 | 설명 | 비고 |
|------|------|------|------|
| active | 제공된 원문 자료 없음 | 모델 재가동 전용 화면 스케치는 아직 제공되지 않음 | 메뉴명과 운영 맥락 기준 초안 |

## 2. 기능 요구사항 *(필수)*

### 기능 요구사항

- **FR-001**: 관리자 권한 사용자는 모델 재가동 화면에 진입할 수 있어야 한다.
- **FR-002**: 관리자 권한이 없는 사용자는 해당 메뉴와 화면에 접근할 수 없어야 한다.
- **FR-003**: 시스템은 재가동 가능한 영상 모델 목록을 표시해야 한다.
- **FR-004**: 시스템은 모델명, 적용 공정/카메라, 현재 상태, 마지막 재가동 시각을 표시해야 한다.
- **FR-005**: 사용자는 상태, 공정, 모델 종류 조건으로 모델 목록을 필터링할 수 있어야 한다.
- **FR-006**: 사용자는 특정 모델을 선택해 상세 상태와 영향 범위를 확인할 수 있어야 한다.
- **FR-007**: 사용자는 선택한 모델의 재가동을 요청할 수 있어야 한다.
- **FR-008**: 시스템은 재가동 요청 전 확인 절차를 제공해야 한다.
- **FR-009**: 시스템은 재가동 요청 중, 성공, 실패 상태를 구분해 표시해야 한다.
- **FR-010**: 시스템은 이미 재가동 중인 모델에 중복 재가동 요청을 허용하지 않아야 한다.
- **FR-011**: 시스템은 재가동 영향으로 일시적으로 감지가 중단될 수 있음을 표시해야 한다.
- **FR-012**: 시스템은 재가동 이력을 최근순으로 확인할 수 있게 표시해야 한다.

## 3. 제외 범위 *(필수)*

- 실제 모델 프로세스 제어와 서버 재시작은 제외한다.
- 모델 배포, 버전 교체, 학습 기능은 제외한다.
- 자동 재가동 정책 설정은 제외한다.
- 모델 성능 리포트와 상세 추론 로그 분석은 제외한다.

## 4. UI/UX 요구사항

- **UX-001**: 재가동 버튼은 대상과 영향 범위를 확인한 뒤 실행되도록 구성해야 한다.
- **UX-002**: 재가동 중 상태는 목록과 상세 영역에서 모두 명확해야 한다.
- **UX-003**: 위험한 조작이므로 확인 메시지는 짧고 구체적이어야 한다.
- **UX-004**: 실패 상태는 재시도 가능 여부와 함께 표시되어야 한다.
- **UX-005**: theme1, theme2, theme3에서 상태와 확인 메시지가 읽을 수 있어야 한다.

## 5. 필요한 정보

- 모델명, 모델 종류, 적용 공정/카메라
- 현재 상태와 마지막 재가동 시각
- 재가동 영향 범위와 예상 중단 대상
- 최근 재가동 이력
- 관리자 권한 여부

## 6. 사용자 시나리오 및 테스트 *(필수)*

### 사용자 스토리 1 - 모델 상태 확인 (우선순위: P1)

관리자는 모델 목록과 현재 상태를 확인한다.

**관련 기능 요구사항**: FR-001, FR-002, FR-003, FR-004, FR-005

**이 우선순위의 이유**: 재가동 전 모델 상태와 대상 식별이 먼저 필요하다.

**독립 테스트**: 관리자에게 모델 목록과 필터가 표시되고 비관리자는 접근할 수 없는지 확인한다.

**허용 시나리오**:

1. **Given** 관리자 권한 사용자가 로그인되어 있다, **When** 모델 재가동 메뉴를 선택한다, **Then** 모델 목록과 현재 상태가 표시된다.
2. **Given** 모델 목록이 표시되어 있다, **When** 사용자가 상태 필터를 선택한다, **Then** 조건에 맞는 모델만 표시된다.

### 사용자 스토리 2 - 모델 재가동 요청 (우선순위: P1)

관리자는 특정 모델의 영향 범위를 확인한 뒤 재가동을 요청한다.

**관련 기능 요구사항**: FR-006, FR-007, FR-008, FR-009, FR-011

**이 우선순위의 이유**: 모델 재가동은 운영 영향이 있으므로 확인 절차와 상태 피드백이 필수다.

**독립 테스트**: 상세 확인, 확인 절차, 요청 중/성공/실패 표시가 동작하는지 확인한다.

**허용 시나리오**:

1. **Given** 모델 상세가 표시되어 있다, **When** 사용자가 재가동을 요청한다, **Then** 영향 범위와 확인 메시지가 표시된다.
2. **Given** 사용자가 재가동을 확정했다, **When** 요청이 처리된다, **Then** 요청 중 상태와 완료 결과가 표시된다.

### 사용자 스토리 3 - 중복 요청 방지와 이력 확인 (우선순위: P2)

관리자는 재가동 중인 모델에 중복 요청하지 않고 최근 이력을 확인한다.

**관련 기능 요구사항**: FR-010, FR-012

**이 우선순위의 이유**: 중복 재가동은 운영 혼선을 만들 수 있다.

**독립 테스트**: 재가동 중 모델의 요청 제한과 이력 표시를 확인한다.

**허용 시나리오**:

1. **Given** 모델이 재가동 중이다, **When** 사용자가 재가동 버튼을 확인한다, **Then** 중복 요청이 불가능한 상태로 표시된다.
2. **Given** 재가동 이력이 있다, **When** 상세 영역을 확인한다, **Then** 최근 이력이 표시된다.

### 엣지 케이스

- 모델 목록이 비어 있으면 빈 상태를 표시해야 한다.
- 재가동 실패 시 실패 이유와 재시도 가능성을 표시해야 한다.
- 영향 범위가 없는 모델은 영향 범위 없음으로 명확히 표시해야 한다.

## 7. 성공 기준 *(필수)*

### 측정 가능한 결과

- **SC-001**: 관리자는 2번 이하의 조작으로 모델 재가동 화면에 진입할 수 있다.
- **SC-002**: 관리자는 3초 이내에 재가동 대상 모델 상태를 파악할 수 있다.
- **SC-003**: 재가동 요청 전 영향 범위가 반드시 표시된다.
- **SC-004**: 재가동 중 모델은 중복 요청이 차단된다.
- **SC-005**: 비관리자는 메뉴와 화면 내용을 볼 수 없다.

## 8. 가정 및 미정 사항

### 가정

- MVP는 mock 요청과 mock 상태 변경으로 진행한다.
- 실제 모델 재가동은 운영 안전 검토 후 후속 기능에서 구현한다.

### 미정 사항

- 실제 재가동 권한 세분화와 승인 절차는 후속 권한 정책에서 정한다.
