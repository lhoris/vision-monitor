# 기능 명세서: 역할 관리

**기능 브랜치**: `012-role-management`

**작성일**: 2026-08-17

**상태**: 초안

**변경 추적**: 문서 변경 이력은 Git 커밋 이력을 기준으로 한다.

**입력**: 왼쪽 사이드바 관리자 메뉴 순서에 따라 "역할 관리" 기능명세서 작성

> **기능 개요 - Agent 요약**
>
> 역할 관리는 관리자 권한 사용자가 사용자에게 부여할 역할의 목록과 기본 속성을 관리하는 기능이다. 관리자는 관리자, 운영자, 조회자 같은 역할을 확인하고 역할명, 설명, 사용 여부, 연결된 사용자 수를 관리할 수 있어야 한다. 실제 메뉴별 권한 세부 설정은 권한 정책 관리로 분리하고, 이 기능은 역할 자체의 정의와 상태 관리에 집중한다.

## 1. 참고 이미지 및 원문 자료

| 상태 | 자료 | 설명 | 비고 |
|------|------|------|------|
| active | 제공된 원문 자료 없음 | 역할 관리 전용 화면 스케치는 아직 제공되지 않음 | 일반적인 RBAC 운영 화면 기준 초안 |

## 2. 기능 요구사항 *(필수)*

### 기능 요구사항

- **FR-001**: 관리자 권한 사용자는 역할 관리 화면에 진입할 수 있어야 한다.
- **FR-002**: 관리자 권한이 없는 사용자는 해당 메뉴와 화면에 접근할 수 없어야 한다.
- **FR-003**: 시스템은 역할 목록을 표시해야 한다.
- **FR-004**: 시스템은 역할명, 설명, 사용 여부, 연결된 사용자 수를 표시해야 한다.
- **FR-005**: 사용자는 역할명과 사용 여부 조건으로 목록을 필터링할 수 있어야 한다.
- **FR-006**: 관리자는 역할 상세 정보를 확인할 수 있어야 한다.
- **FR-007**: 관리자는 신규 역할을 추가할 수 있어야 한다.
- **FR-008**: 관리자는 기존 역할의 이름과 설명을 수정할 수 있어야 한다.
- **FR-009**: 관리자는 더 이상 사용하지 않는 역할을 비활성화할 수 있어야 한다.
- **FR-010**: 시스템은 이미 사용자에게 연결된 역할의 비활성화 위험을 경고해야 한다.
- **FR-011**: 시스템은 중복 역할명과 필수값 누락을 저장 전에 표시해야 한다.
- **FR-012**: 시스템 기본 역할은 삭제하거나 위험하게 변경하지 못하도록 보호해야 한다.

## 3. 제외 범위 *(필수)*

- 메뉴별 권한 세부 부여는 권한 정책 관리 범위로 분리한다.
- 실제 인증/인가 엔진 연동은 제외한다.
- 역할 변경 감사 로그와 승인 워크플로우는 제외한다.
- 조직 단위별 역할 상속 정책은 제외한다.

## 4. UI/UX 요구사항

- **UX-001**: 역할 목록은 역할명, 사용 여부, 연결 사용자 수를 빠르게 비교할 수 있어야 한다.
- **UX-002**: 기본 역할과 사용자 정의 역할은 구분되어야 한다.
- **UX-003**: 연결 사용자가 있는 역할 변경은 영향 안내가 표시되어야 한다.
- **UX-004**: 역할 추가/수정 입력 오류는 입력 영역 근처에 표시되어야 한다.
- **UX-005**: theme1, theme2, theme3에서 역할명과 상태가 읽을 수 있어야 한다.

## 5. 필요한 정보

- 역할명, 설명, 사용 여부
- 연결된 사용자 수
- 기본 역할 여부
- 중복 역할명 여부
- 관리자 권한 여부

## 6. 사용자 시나리오 및 테스트 *(필수)*

### 사용자 스토리 1 - 역할 목록 조회 (우선순위: P1)

관리자는 현재 정의된 역할 목록과 사용 상태를 확인한다.

**관련 기능 요구사항**: FR-001, FR-002, FR-003, FR-004, FR-005

**이 우선순위의 이유**: 역할 정책을 관리하려면 먼저 역할 정의를 파악해야 한다.

**독립 테스트**: 관리자만 역할 목록을 볼 수 있고 필터가 동작하는지 확인한다.

**허용 시나리오**:

1. **Given** 관리자 권한 사용자가 로그인되어 있다, **When** 역할 관리 메뉴를 선택한다, **Then** 역할 목록이 표시된다.
2. **Given** 역할 목록이 표시되어 있다, **When** 사용자가 사용 여부 필터를 선택한다, **Then** 조건에 맞는 역할만 표시된다.

### 사용자 스토리 2 - 역할 추가와 수정 (우선순위: P2)

관리자는 신규 역할을 추가하거나 기존 역할 설명을 수정한다.

**관련 기능 요구사항**: FR-006, FR-007, FR-008, FR-011

**이 우선순위의 이유**: 운영 조직 변화에 따라 역할 정의가 변경될 수 있다.

**독립 테스트**: 역할 추가/수정, 중복 역할명, 필수값 오류를 확인한다.

**허용 시나리오**:

1. **Given** 역할 추가 화면이 열려 있다, **When** 필수 정보를 입력하고 저장한다, **Then** 새 역할이 추가 가능한 상태로 표시된다.
2. **Given** 중복 역할명이 입력되어 있다, **When** 저장을 시도한다, **Then** 중복 오류가 표시된다.

### 사용자 스토리 3 - 역할 비활성화와 보호 (우선순위: P2)

관리자는 역할을 비활성화하되 기본 역할과 사용 중인 역할의 위험을 확인한다.

**관련 기능 요구사항**: FR-009, FR-010, FR-012

**이 우선순위의 이유**: 역할 변경은 사용자 접근 범위에 영향을 준다.

**독립 테스트**: 연결 사용자 경고와 기본 역할 보호가 동작하는지 확인한다.

**허용 시나리오**:

1. **Given** 연결 사용자가 있는 역할이 선택되어 있다, **When** 비활성화를 시도한다, **Then** 영향 경고가 표시된다.
2. **Given** 기본 역할이 선택되어 있다, **When** 위험한 변경을 시도한다, **Then** 보호 안내가 표시된다.

### 엣지 케이스

- 모든 관리자 역할이 비활성화되는 상황은 허용되지 않아야 한다.
- 역할명이 길어도 목록이 깨지지 않아야 한다.
- 권한 정책이 연결된 역할은 영향 범위가 표시되어야 한다.

## 7. 성공 기준 *(필수)*

### 측정 가능한 결과

- **SC-001**: 관리자는 2번 이하의 조작으로 역할 관리 화면에 진입할 수 있다.
- **SC-002**: 관리자는 3초 이내에 사용 중인 역할과 비활성 역할을 구분할 수 있다.
- **SC-003**: 중복 역할명은 저장 전에 표시된다.
- **SC-004**: 기본 역할은 위험한 변경으로부터 보호된다.
- **SC-005**: 비관리자는 메뉴와 화면 내용을 볼 수 없다.

## 8. 가정 및 미정 사항

### 가정

- MVP는 mock 역할 목록과 mock 저장 흐름으로 진행한다.
- 역할별 세부 권한은 013 권한 정책 관리에서 다룬다.

### 미정 사항

- 기본 역할 목록과 보호 수준은 운영 정책 확정 후 조정한다.
