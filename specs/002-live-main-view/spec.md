# 기능 명세서: 라이브 메인 화면

**기능 브랜치**: `002-live-main-view`

**작성일**: 2026-08-16

**상태**: 초안

**변경 추적**: 문서 변경 이력은 Git 커밋 이력을 기준으로 한다.

**입력**: 현재 구현된 라이브 모니터링 화면과 사용자 대화에서 정리된 공정탭, 세부공정탭, 영상 그리드 요구사항

> 이 문서는 한국어로 작성한다. 기술 용어, API 이름, 파일 경로, 코드 식별자는 원문 또는 영문 표기를 유지할 수 있다.
> 기능 명세서는 "무엇을 제공해야 하는가"를 정의한다. 구현 방식, 컴포넌트 구조, DTO/API 세부사항, 파일 경로는 plan.md 또는 contracts/에서 다룬다.

> **기능 개요 - Agent 요약**
>
> 라이브 메인 화면은 운영자가 공정탭과 세부공정탭을 전환하면서 여러 CCTV 영상을 그리드 형태로 확인하고 배치하는 기본 감시 화면이다. 사용자는 그리드 크기를 선택하고, 빈 셀에 카메라 목록의 카메라를 추가하거나 직접 영상 주소를 입력해 카메라 목록에 없는 임시 영상도 추가할 수 있어야 한다. 카메라 타일을 이동/삭제/Rename하고, 필요한 경우 특정 카메라를 화면 확대 보기로 열 수 있어야 한다. 카메라 제목과 온라인 상태는 영상 영역을 침범하지 않는 타일 헤더에 표시되어야 하며, 확대 버튼은 영상 감시를 방해하지 않도록 마우스 오버나 포커스 상태에서 명확하게 드러나야 한다. MVP는 frontend mock layout과 mock camera fixture를 기준으로 하며, 실제 backend 저장, RTSP ingest, media distribution 직접 구현은 후속 범위로 분리한다.

## 2. 기능 요구사항 *(필수)*

### 기능 요구사항

- **FR-001**: 사용자는 라이브 메인 화면에서 공정탭 목록을 확인하고 원하는 공정탭으로 전환할 수 있어야 한다.
- **FR-002**: 사용자는 선택한 공정탭 아래의 세부공정탭 목록을 확인하고 원하는 세부공정탭으로 전환할 수 있어야 한다.
- **FR-003**: 사용자는 공정탭과 세부공정탭을 추가, 삭제, 순서 변경할 수 있어야 한다.
- **FR-004**: 시스템은 선택한 세부공정탭의 그리드 설정에 맞춰 영상 셀을 일정한 비율로 표시해야 한다.
- **FR-005**: 사용자는 그리드 크기 옵션을 선택해 현재 세부공정탭의 영상 배치 행/열을 변경할 수 있어야 한다.
- **FR-006**: 사용자는 빈 그리드 셀에서 카메라 선택 창을 열고 사용 가능한 카메라를 추가할 수 있어야 한다.
- **FR-007**: 카메라 선택 창은 이미 현재 세부공정탭에 배치된 카메라를 중복 선택 대상으로 보여주지 않아야 한다.
- **FR-008**: 사용자는 카메라 타일을 다른 셀로 드래그해 위치를 변경할 수 있어야 하며, 점유된 셀로 이동하면 기존 카메라와 위치를 교환할 수 있어야 한다.
- **FR-009**: 사용자는 카메라 타일의 우클릭 메뉴에서 카메라를 제거할 수 있어야 한다.
- **FR-010**: 사용자는 카메라 타일의 우클릭 메뉴에서 표시 제목을 Rename할 수 있어야 한다.
- **FR-011**: Rename된 카메라 제목은 라이브 메인 화면의 해당 카메라 타일에 즉시 반영되어야 한다.
- **FR-012**: 카메라 타일은 카메라 제목과 온라인 상태 표시를 영상 영역 바깥의 헤더에 표시해야 한다.
- **FR-013**: 온라인 상태 문구는 녹색 상태점과 중복 표시되지 않아야 한다.
- **FR-014**: 확대 버튼은 상시 시선을 끌지 않고, 마우스 오버 또는 키보드 포커스 시 사용할 수 있어야 한다.
- **FR-015**: 사용자는 카메라 타일에서 화면 확대 보기로 진입할 수 있어야 하며, 이때 현재 공정/세부공정과 카메라 목록 맥락이 함께 전달되어야 한다.
- **FR-016**: 레이아웃 데이터 로딩 실패 또는 미존재 상태에서는 사용자가 이해할 수 있는 빈 상태 또는 fallback 레이아웃을 제공해야 한다.
- **FR-017**: theme1, theme2, theme3에서 탭, 타일 헤더, Rename dialog, Add Camera 셀의 주요 텍스트가 명확하게 보여야 한다.
- **FR-018**: 사용자는 Add Camera 동작에서 카메라 목록 선택 모드와 직접 영상 주소 입력 모드를 토글로 전환할 수 있어야 한다.
- **FR-019**: 직접 영상 주소 입력 모드에서는 WebRTC, RTSP, HLS 중 영상 주소 유형을 선택할 수 있어야 하며, 기본 선택값은 WebRTC여야 한다.
- **FR-020**: 직접 영상 주소 입력 모드에서는 선택한 주소 유형에 맞는 URL을 입력해야 하며, 빈 값·지원하지 않는 형식·잘못된 URL은 저장 전에 안내되어야 한다.
- **FR-021**: 사용자가 유효한 영상 주소를 등록하면 해당 주소가 카메라 목록에 없어도 현재 세부공정탭의 빈 셀에 영상 타일로 추가되어야 한다.
- **FR-022**: 직접 추가한 영상 타일은 카메라 목록에서 선택한 카메라와 구분되는 임시 영상임을 표시해야 한다.
- **FR-023**: 같은 세부공정탭에 동일한 직접 영상 주소를 중복 추가하려는 경우 중복 상태를 안내하고 추가하지 않아야 한다.
- **FR-024**: 직접 추가한 영상은 연결 중, 재생 중, 재생 실패 상태를 구분해 표시해야 하며, 재생 실패 시 사용자가 주소와 유형을 수정하거나 타일을 제거할 수 있어야 한다.
- **FR-025**: 직접 추가한 영상의 표시 제목은 사용자가 입력할 수 있어야 하며, 입력하지 않으면 영상 주소 유형을 포함한 기본 제목을 표시해야 한다.

## 3. 제외 범위 *(필수)*

- MVP에서는 실제 Spring Boot layout persistence API 구현을 제외한다.
- MVP에서는 DB migration과 서버 저장을 제외한다.
- MVP에서는 RTSP ingest, transcoding, media distribution 직접 구현을 제외한다.
- MVP에서는 AI inference, server-side overlay, 영상 분석 결과 생성 기능을 제외한다.
- 003 화면 확대 보기의 상세 메타데이터/녹화/알람 UI 구현은 이 기능 범위에서 제외하고 route 진입 계약만 다룬다.
- 로그인/권한 체계는 001 기능으로 분리하고, 이 기능에서는 인증 화면을 새로 정의하지 않는다.

## 4. UI/UX 요구사항

- **UX-001**: 공정탭은 라이브 메인 화면의 상단 첫 번째 탐색 축으로 보여야 한다.
- **UX-002**: 세부공정탭은 선택된 공정탭 아래 두 번째 탐색 축으로 보여야 한다.
- **UX-003**: 공정탭과 세부공정탭은 클릭 가능한 요소로 인식되어야 하며, 드래그 가능한 표시가 필요할 때도 기본 포인터는 손가락 형태로 보여야 한다.
- **UX-004**: 활성 탭은 비활성 탭과 명확히 구분되어야 한다.
- **UX-005**: 영상 타일과 Add Camera 셀은 같은 크기 체계를 유지해야 한다.
- **UX-006**: 카메라 타일 헤더는 영상 판독 영역을 침범하지 않아야 한다.
- **UX-007**: 카메라 타이틀은 긴 이름에서도 줄바꿈이나 말줄임으로 레이아웃을 깨지 않아야 한다.
- **UX-008**: Rename dialog는 모든 테마에서 입력 글자와 버튼 상태가 명확해야 한다.
- **UX-009**: 확대 버튼은 hover/focus 상태에서 드러나되 키보드 접근성으로도 실행 가능해야 한다.
- **UX-010**: Add Camera 셀은 빈 영역임을 명확히 보여주되 실제 영상 타일보다 과도하게 커 보이지 않아야 한다.
- **UX-011**: 영상 주소와 표시 제목 입력칸은 모든 테마에서 입력 텍스트, placeholder, caret, focus 상태가 명확히 보여야 한다.

## 5. 필요한 정보

- 사용자는 공정명, 세부공정명, 현재 선택된 공정/세부공정 상태를 확인할 수 있어야 한다.
- 사용자는 현재 그리드 크기와 변경 가능한 그리드 옵션을 확인할 수 있어야 한다.
- 사용자는 각 셀의 카메라명, 위치 정보, 온라인 상태, 영상 표시 상태를 확인할 수 있어야 한다.
- 사용자는 Add Camera에서 카메라 목록 기반 추가와 직접 영상 주소 기반 추가 중 현재 모드를 확인할 수 있어야 한다.
- 직접 영상 주소 추가 시 사용자는 주소 유형(WebRTC/RTSP/HLS), 영상 URL, 표시 제목을 입력할 수 있어야 한다.
- 직접 추가한 영상은 카메라 목록에 등록된 카메라와 구분되는 출처와 재생 상태를 확인할 수 있어야 한다.
- 시스템은 각 세부공정탭의 카메라 배치 정보와 그리드 설정을 유지해야 한다.
- 시스템은 화면 확대 보기 진입 시 선택 카메라, 현재 공정탭, 현재 세부공정탭, 현재 세부공정탭의 카메라 목록, Rename 제목 정보를 전달해야 한다.

## 6. 사용자 시나리오 및 테스트 *(필수)*

### 사용자 스토리 1 - 공정/세부공정별 영상 그리드 보기 (우선순위: P1)

운영자는 라이브 메인 화면에서 공정탭과 세부공정탭을 선택해 해당 설비 또는 구역의 카메라 영상을 한 화면에서 확인한다.

**관련 기능 요구사항**: FR-001, FR-002, FR-004, FR-012, FR-013, FR-017

**이 우선순위인 이유**: 라이브 메인 화면의 기본 가치이며, 이 흐름이 안정적이어야 카메라 배치와 화면 확대 보기로 이어질 수 있다.

**독립 테스트**: 사용자가 공정탭과 세부공정탭을 전환하면 선택된 탭의 그리드와 카메라 타일이 표시되고, 타이틀/상태 표시가 영상 바깥에 있는지 확인한다.

**수용 시나리오**:

1. **Given** 사용자가 라이브 메인 화면에 진입했다, **When** 공정탭을 선택한다, **Then** 해당 공정의 세부공정탭과 기본 그리드가 표시된다.
2. **Given** 세부공정탭에 카메라가 배치되어 있다, **When** 사용자가 해당 세부공정탭을 선택한다, **Then** 배치된 카메라 영상 타일이 일정한 비율로 표시된다.
3. **Given** 카메라 타일이 표시되어 있다, **When** 사용자가 타일을 본다, **Then** 카메라 제목과 온라인 상태점은 영상 바깥 헤더에서 확인된다.

---

### 사용자 스토리 2 - 그리드 구성과 카메라 배치 편집 (우선순위: P2)

운영자는 세부공정별로 그리드 크기를 바꾸고 빈 셀에 카메라를 추가하거나 기존 카메라 위치를 바꾼다.

**관련 기능 요구사항**: FR-005, FR-006, FR-007, FR-008, FR-016

**이 우선순위인 이유**: 운영 현장마다 감시해야 하는 카메라 수와 배치가 다르므로, 그리드 편집은 메인 화면을 실제 업무에 맞추는 핵심 기능이다.

**독립 테스트**: 사용자가 그리드 크기를 변경하고 빈 셀에 카메라를 추가한 뒤 드래그로 위치를 변경하면 선택된 세부공정탭의 배치만 변경되는지 확인한다.

**수용 시나리오**:

1. **Given** 사용자가 특정 세부공정탭을 보고 있다, **When** 그리드 크기를 3x3으로 변경한다, **Then** 해당 세부공정탭의 셀 수와 배치 영역이 3x3 기준으로 갱신된다.
2. **Given** 빈 셀이 표시되어 있다, **When** 사용자가 Add Camera를 선택하고 카메라를 고른다, **Then** 선택한 카메라가 해당 셀에 표시된다.
3. **Given** 이미 배치된 카메라가 있다, **When** 사용자가 다른 셀로 드래그한다, **Then** 카메라 위치가 변경되고 점유 셀인 경우 기존 카메라와 위치가 교환된다.

---

### 사용자 스토리 3 - 직접 영상 주소로 임시 영상 추가 (우선순위: P2)

운영자는 카메라 목록에 등록되지 않은 영상도 영상 주소와 주소 유형을 직접 입력해 현재 세부공정탭에서 임시로 확인한다.

**관련 기능 요구사항**: FR-018, FR-019, FR-020, FR-021, FR-022, FR-023, FR-024, FR-025, FR-017

**이 우선순위인 이유**: 현장 점검이나 외부 영상 확인처럼 카메라 관리 목록에 등록하기 전에도 영상을 확인해야 하는 업무를 지원하며, 기존 카메라 선택 흐름과 독립적으로 검증할 수 있다.

**독립 테스트**: Add Camera 모드를 직접 영상 주소 입력으로 바꾸고 WebRTC, RTSP, HLS 유형과 URL을 입력해 타일을 추가한 뒤, 잘못된 주소·중복 주소·재생 실패 상태를 확인한다.

**수용 시나리오**:

1. **Given** 빈 그리드 셀이 표시되어 있다, **When** 사용자가 Add Camera를 누르고 직접 영상 주소 입력 모드로 전환한다, **Then** 카메라 목록 대신 주소 유형 선택과 URL 입력 영역이 표시된다.
2. **Given** 직접 영상 주소 입력 모드가 열려 있다, **When** 사용자가 WebRTC, RTSP 또는 HLS 유형과 유효한 URL을 입력해 추가한다, **Then** 카메라 목록에 없는 영상이 현재 빈 셀에 임시 영상 타일로 표시된다.
3. **Given** 직접 영상 주소가 추가되어 있다, **When** 사용자가 같은 세부공정탭에 동일한 URL을 다시 추가한다, **Then** 중복 추가가 차단되고 기존 타일을 안내한다.
4. **Given** 직접 추가한 영상 URL을 재생할 수 없다, **When** 영상 타일이 재생 실패 상태가 된다, **Then** 실패 상태와 함께 주소 수정 또는 타일 제거 동작을 제공한다.

---

### 사용자 스토리 4 - 탭과 카메라 타일 관리 (우선순위: P3)

운영자는 공정탭/세부공정탭을 추가, 삭제, 순서 변경하고 카메라 타일의 표시 제목을 현장 용어에 맞게 변경한다.

**관련 기능 요구사항**: FR-003, FR-009, FR-010, FR-011, FR-017

**이 우선순위인 이유**: 운영자가 화면을 자신의 현장 구조에 맞추는 기능이며, 기본 감시와 배치 기능 위에서 독립적으로 검증할 수 있다.

**독립 테스트**: 탭 추가/삭제/순서 변경과 카메라 Rename/Remove를 수행해 화면 상태가 즉시 반영되고 마지막 탭 삭제 같은 위험 동작은 방지되는지 확인한다.

**수용 시나리오**:

1. **Given** 공정탭이 여러 개 있다, **When** 사용자가 탭 순서를 변경한다, **Then** 탭 순서가 바뀌고 활성 탭 상태가 유지된다.
2. **Given** 카메라 타일이 표시되어 있다, **When** 사용자가 우클릭 메뉴에서 Rename을 실행해 제목을 저장한다, **Then** 타일 제목이 즉시 변경된다.
3. **Given** 카메라 타일이 표시되어 있다, **When** 사용자가 우클릭 메뉴에서 Remove를 실행한다, **Then** 해당 카메라가 현재 세부공정탭에서 제거된다.

---

### 사용자 스토리 5 - 화면 확대 보기로 연결 (우선순위: P3)

운영자는 라이브 메인 화면에서 특정 카메라를 더 자세히 보기 위해 화면 확대 보기로 이동한다.

**관련 기능 요구사항**: FR-014, FR-015

**이 우선순위인 이유**: 002 라이브 메인 화면과 003 화면 확대 보기의 연결 계약이며, 확대 화면의 카메라 목록 오류를 방지하는 핵심 경계이다.

**독립 테스트**: 특정 세부공정탭에서 확대 버튼을 실행하면 선택 카메라와 현재 세부공정탭의 카메라 목록만 화면 확대 보기 진입 정보로 전달되는지 확인한다.

**수용 시나리오**:

1. **Given** 사용자가 Production Line B의 세부공정탭에서 카메라 2개가 있는 그리드를 보고 있다, **When** 특정 카메라의 확대 버튼을 실행한다, **Then** 화면 확대 보기에는 해당 2개 카메라 목록만 전환 대상으로 전달된다.
2. **Given** 사용자가 카메라 제목을 Rename했다, **When** 확대 버튼을 실행한다, **Then** Rename된 제목 정보가 화면 확대 보기 진입 정보에 포함된다.

### 엣지 케이스

- 마지막 공정탭 또는 마지막 세부공정탭 삭제는 방지되어야 한다.
- 빈 세부공정탭에서는 Add Camera 셀이 영상 타일과 같은 크기로 표시되어야 한다.
- 현재 세부공정탭에 이미 사용 중인 카메라는 카메라 선택 창에 `이미 추가됨` 상태로 표시하고 중복 선택을 막아야 한다.
- 그리드 크기 변경으로 기존 카메라 위치가 화면 밖이 될 수 있는 경우, 사용자가 이해할 수 있는 방식으로 배치가 유지되거나 정리되어야 한다.
- Rename 제목이 비어 있으면 저장되지 않아야 하며, 긴 제목은 레이아웃을 깨지 않아야 한다.
- 영상 로딩 실패가 있어도 탭과 그리드 조작은 계속 가능해야 한다.
- 직접 입력 URL이 비어 있거나 주소 유형과 맞지 않으면 추가 버튼을 실행할 수 없어야 한다.
- WebRTC, RTSP, HLS 중 선택한 유형을 현재 재생 방식이 지원하지 않는 경우 명확한 지원 불가 또는 재생 실패 상태를 보여야 한다.
- 직접 추가한 영상 타일을 삭제해도 카메라 목록의 원본 카메라 데이터에는 영향을 주지 않아야 한다.
- 직접 추가한 영상의 URL에 공백이나 민감한 인증 정보가 포함된 경우 화면 표시 정책을 명확히 적용해야 한다.

## 7. 성공 기준 *(필수)*

### 측정 가능한 결과

- **SC-001**: 사용자는 라이브 메인 화면 진입 후 3초 이내에 현재 공정, 세부공정, 영상 그리드 상태를 파악할 수 있다.
- **SC-002**: 사용자는 2번 이하의 조작으로 공정탭 또는 세부공정탭을 전환할 수 있다.
- **SC-003**: 사용자는 3번 이하의 조작으로 빈 셀에 카메라를 추가할 수 있다.
- **SC-004**: 사용자는 카메라 타일에서 2번 이하의 조작으로 화면 확대 보기로 진입할 수 있다.
- **SC-005**: theme1, theme2, theme3에서 타일 제목, Rename dialog, Add Camera 셀, 탭 텍스트가 육안으로 명확하게 구분된다.
- **SC-006**: 현재 세부공정탭의 카메라 수와 화면 확대 보기로 전달되는 카메라 목록 수가 일치한다.
- **SC-007**: 사용자는 Add Camera 모드 전환 후 4번 이하의 조작으로 직접 영상 주소 타일을 추가할 수 있다.
- **SC-008**: 유효한 직접 영상 주소는 카메라 목록 등록 여부와 관계없이 현재 세부공정탭의 빈 셀에 추가된다.
- **SC-009**: 잘못된 URL, 중복 URL, 재생 실패는 추가·재생 과정에서 사용자가 원인을 구분할 수 있는 상태로 표시된다.

## 8. 가정 및 미정 사항

### 가정

- MVP에서는 frontend mock layout과 mock camera fixture를 사용한다.
- 로그인 기능은 001에서 별도로 정의되며, 002는 로그인 이후 접근 가능한 운영 화면으로 본다.
- 화면 확대 보기 상세 기능은 003에서 정의하고, 002에서는 진입 정보 전달까지만 책임진다.
- 탭/그리드 설정의 장기 저장은 후속 backend 연동 전까지 mock 또는 frontend state 기준으로 검증한다.
- 직접 추가 영상의 장기 저장 여부는 MVP에서 확정하지 않으며, 우선 현재 세부공정탭에서 확인 가능한 임시 타일로 취급한다.
- 영상 주소의 실제 네트워크 연결과 프로토콜별 브라우저 재생 지원은 실행 환경에 따라 달라질 수 있으므로, MVP에서는 연결 중·재생 실패·지원 불가 상태를 명확히 표시하는 것을 기본 동작으로 본다.

### 미정 사항

- 없음. 현재 구현과 사용자 대화를 기준으로 기본 동작을 확정한다.
