# 화면 단계별 온보딩 안내 기능

**기능 브랜치**: `024-guided-onboarding`

**작성일**: 2026-11-05

**상태**: 초안

## 1. 기능 개요

Vision Monitor의 핵심 화면 기능과 기본 사용 흐름을 단계별로 안내한다. 안내는 사용자의 업무를 방해하지 않고, 현재 화면에서 실제로 수행할 수 있는 행동을 중심으로 제공한다.

온보딩 대상은 초기 범위에서 로그인 화면과 라이브 대시보드로 제한한다. 우측 상단 계정 정보 옆에 도움말 아이콘을 제공하며, 사용자가 도움말을 선택하면 현재 화면이 온보딩 대상인지 판단해 안내를 시작하거나 안내 대상이 아님을 메시지로 알려준다.

## Clarifications

### Session 2026-11-05

- Q: 도움말 아이콘은 지원 화면에만 표시할 것인가, 모든 화면에 표시할 것인가? → A: 모든 화면에 표시하고, 로그인·라이브 대시보드 외 화면에서는 안내 메시지만 표시한다.
- Q: 온보딩을 첫 방문이나 가입 승인 직후 자동 실행할 것인가? → A: 초기 구현은 도움말 아이콘을 클릭했을 때만 실행하고, 자동 실행 트리거는 후속 요구사항으로 추가할 수 있도록 확장 가능하게 둔다.

## 2. 핵심 철학

- 업무 화면을 가리지 않으며 사용자가 언제든 건너뛸 수 있어야 한다.
- 기능 목록을 나열하기보다 사용자의 실제 업무 흐름에 따라 짧은 단계로 안내한다.
- 온보딩은 화면 안내 기능이며 로그인, 영상 재생, 알람, 사용자 관리 등 기존 업무 로직에 영향을 주지 않는다.
- 한 번 본 안내를 매번 강제로 반복하지 않으며, 도움말 아이콘으로 언제든 다시 실행할 수 있어야 한다.
- 한국어 사용 환경에서는 한글 안내를 우선 제공하고 영어 환경에서는 영어 안내를 제공한다.
- 화면 크기, 키보드 조작, 색상 대비를 고려해 누구나 안내를 완료할 수 있어야 한다.

## 3. 기능 요구사항

### 기능 요구사항

- **FR-001**: 시스템은 모든 화면에서 도움말 아이콘을 제공해야 하며, 로그인 화면과 라이브 대시보드에서는 온보딩을 시작하고 그 외 화면에서는 안내 대상이 아니라는 메시지를 표시해야 한다.
- **FR-002**: 라이브 대시보드의 도움말 아이콘은 우측 상단 계정 정보 영역 옆에 제공하고, 로그인 화면의 도움말 아이콘은 로그인 카드 우측 상단에 제공해야 한다.
- **FR-003**: 사용자가 도움말 아이콘을 선택하면 현재 화면이 온보딩 대상인지 판단해야 하며, 초기 구현에서는 도움말 선택 외의 자동 실행을 수행하지 않아야 한다.
- **FR-004**: 로그인 화면에서는 로그인, 회원가입, 비밀번호 입력 등 핵심 기능을 사용 순서에 맞춰 안내해야 한다.
- **FR-005**: 라이브 대시보드에서는 공정 선택, 영상 추가, 그리드 배치, 화면 확대, 알람 확인 등 핵심 기능을 사용 순서에 맞춰 안내해야 한다.
- **FR-006**: 온보딩은 현재 화면의 안내 대상 요소를 강조하고 각 요소에 설명을 제공해야 한다.
- **FR-007**: 사용자는 다음 단계, 이전 단계, 건너뛰기, 완료 동작을 수행할 수 있어야 한다.
- **FR-008**: 온보딩 완료 또는 건너뛰기 이후 동일한 화면에 진입할 때 안내가 자동으로 반복되지 않아야 한다.
- **FR-009**: 사용자가 도움말 아이콘을 다시 선택하면 완료하거나 건너뛴 온보딩도 다시 실행할 수 있어야 한다.
- **FR-010**: 로그인 화면과 라이브 대시보드 외 화면에서 도움말 아이콘을 선택하면 온보딩을 시작하지 않고 현재 화면은 안내 대상이 아니라는 안내 메시지를 표시해야 한다.
- **FR-011**: 온보딩 문구와 안내 메시지는 현재 언어 설정에 맞게 표시되어야 한다.
- **FR-012**: 온보딩은 대상 요소가 아직 표시되지 않았거나 현재 상태에서 사용할 수 없는 경우 사용자를 존재하지 않는 요소로 이동시키지 않아야 한다.
- **FR-013**: 온보딩 중 사용자가 화면을 이동하거나 로그아웃하면 안내가 안전하게 종료되어야 한다.

## 4. 제외 범위

- 초기 구현에서 로그인 화면과 라이브 대시보드 외 화면의 단계별 온보딩은 제공하지 않는다.
- 온보딩을 위한 별도 관리자 콘텐츠 관리 화면은 제공하지 않는다.
- 온보딩 진행 상태를 여러 기기에서 공유하기 위한 서버 저장은 초기 범위에 포함하지 않는다.
- 온보딩이 기존 업무 기능의 실행 순서를 강제하거나 실제 업무 데이터를 변경하도록 만들지 않는다.
- 동영상, 실시간 알람, 영상 스트리밍 자체의 동작 변경은 포함하지 않는다.

## 5. UI/UX 요구사항

- 라이브 대시보드의 도움말 아이콘은 계정 정보와 시각적으로 구분되지만 동일한 헤더 영역의 일관된 스타일을 사용해야 한다.
- 로그인 화면의 도움말 아이콘은 로그인 카드 우측 상단에 배치하고, 로그인 카드의 다른 조작 요소와 겹치지 않아야 한다.
- 안내 팝오버는 강조 대상 요소를 가리지 않는 위치에 표시되어야 한다.
- 각 단계에는 현재 진행 위치를 알 수 있는 정보와 다음 행동이 명확히 표시되어야 한다.
- 건너뛰기와 완료 동작은 사용자가 쉽게 찾을 수 있어야 한다.
- 도움말 아이콘은 모든 화면에서 접근 가능해야 하며, 대상 화면이 아니면 짧고 명확한 안내 메시지를 표시한 뒤 화면을 방해하지 않아야 한다.
- 작은 화면에서도 안내 내용과 조작 버튼이 화면 밖으로 잘리지 않아야 한다.
- 키보드만으로 단계 이동과 완료가 가능해야 하며, 강조 상태가 시각적으로 구분되어야 한다.

## 6. 사용자 시나리오 및 테스트

### 시나리오 1 - 로그인 화면 온보딩 시작 (P1)

사용자는 처음 로그인 화면을 방문한 뒤 도움말 아이콘을 선택해 로그인과 회원가입의 기본 흐름을 이해한다.

**검증 시나리오**:

1. **Given** 사용자가 로그인 화면에 있고 온보딩을 완료하지 않은 상태에서, **When** 도움말 아이콘을 선택하면, **Then** 로그인 화면의 첫 안내 단계가 표시된다.
2. **Given** 로그인 화면 온보딩이 표시된 상태에서, **When** 다음 단계와 이전 단계로 이동하면, **Then** 각 단계의 대상 요소와 설명이 올바르게 변경된다.
3. **Given** 사용자가 온보딩을 건너뛴 상태에서, **When** 로그인 화면을 다시 방문하면, **Then** 온보딩이 자동으로 다시 표시되지 않는다.

### 시나리오 2 - 라이브 대시보드 업무 흐름 안내 (P1)

사용자는 라이브 대시보드에서 공정 선택부터 영상 및 알람 확인까지의 기본 업무 흐름을 단계적으로 이해한다.

**검증 시나리오**:

1. **Given** 사용자가 라이브 대시보드에 있고 도움말 아이콘을 선택하면, **Then** 공정 선택 단계부터 안내가 시작된다.
2. **Given** 라이브 온보딩이 진행 중일 때, **When** 다음 단계로 이동하면, **Then** 영상 추가, 그리드 배치, 확대 보기, 알람 확인 순서로 안내된다.
3. **Given** 사용자가 온보딩 중 실제 화면의 다른 기능을 확인하면, **Then** 온보딩은 업무 데이터를 변경하지 않고 안전하게 유지되거나 종료된다.

### 시나리오 3 - 안내 대상이 아닌 화면 (P2)

사용자는 사용자 관리 등 아직 온보딩을 제공하지 않는 화면에서 도움말 아이콘을 선택한다.

**검증 시나리오**:

1. **Given** 사용자가 온보딩 대상이 아닌 화면에 있을 때, **When** 도움말 아이콘을 선택하면, **Then** 단계별 안내 대신 현재 화면은 안내 대상이 아니라는 메시지가 표시된다.
2. **Given** 안내 대상이 아닌 화면에서 메시지가 표시된 상태에서, **When** 사용자가 화면을 계속 사용하면, **Then** 메시지는 업무 동작을 막지 않고 사라진다.

### 시나리오 4 - 언어 및 접근성 (P2)

사용자는 한국어 또는 영어 환경에서 키보드와 다양한 화면 크기로 온보딩을 이용한다.

**검증 시나리오**:

1. **Given** 언어가 한국어로 설정된 상태에서, **When** 온보딩을 실행하면, **Then** 단계 제목과 설명이 한국어로 표시된다.
2. **Given** 언어가 영어로 설정된 상태에서, **When** 온보딩을 실행하면, **Then** 단계 제목과 설명이 영어로 표시된다.
3. **Given** 사용자가 키보드만 사용하는 상태에서, **When** 온보딩을 실행하면, **Then** 단계 이동과 종료를 키보드로 수행할 수 있다.

## 7. 성공 기준

- **SC-001**: 신규 사용자는 로그인 화면 온보딩을 통해 로그인과 회원가입의 위치를 별도 도움 없이 2분 이내에 파악할 수 있다.
- **SC-002**: 신규 사용자는 라이브 대시보드 온보딩을 완료한 뒤 공정 선택, 영상 추가, 화면 확대, 알람 확인 기능의 위치를 모두 식별할 수 있다.
- **SC-003**: 도움말 아이콘 선택 후 온보딩 시작 또는 안내 대상 아님 메시지 표시까지 사용자가 인지할 수 있는 지연이 없어야 한다.
- **SC-004**: 온보딩을 건너뛰거나 완료한 사용자의 다음 화면 진입 시 안내가 자동 반복되지 않아야 한다.
- **SC-005**: 온보딩 사용 중 기존 로그인, 영상, 알람 업무 기능의 성공률과 동작 흐름이 변경되지 않아야 한다.
- **SC-006**: 지원하는 화면 크기에서 안내 팝오버의 텍스트와 조작 버튼이 잘리지 않아야 한다.

## 8. 가정 및 결정 사항

- 초기 온보딩 대상은 로그인 화면과 라이브 대시보드로 한정한다.
- 도움말 아이콘은 모든 화면에서 접근 가능하도록 제공한다. 라이브 대시보드는 계정 정보 옆, 로그인 화면은 로그인 카드 우측 상단에 배치하며, 그 외 화면은 공통 헤더 영역에 배치한다. 화면별 안내 정의는 해당 화면의 사용자 흐름을 기준으로 관리한다.
- 온보딩 완료 여부는 초기 구현에서 현재 브라우저와 사용자 환경에 한정해 저장한다.
- 온보딩은 업무 기능을 자동 실행하지 않고 사용자가 직접 조작할 수 있도록 안내만 제공한다.
- 초기 구현은 도움말 아이콘을 통한 수동 실행만 지원하며, 향후 첫 방문·가입 승인 등의 자동 실행 조건을 추가할 수 있는 구조로 계획한다.
- 시각적 단계 안내를 제공하는 클라이언트 라이브러리 도입 여부와 구체적인 컴포넌트 설계는 plan.md에서 결정한다.
