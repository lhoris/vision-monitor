# 기술 조사: 화면 단계별 온보딩 안내 기능

## Driver.js 도입

- Decision: `driver.js`를 frontend 의존성으로 도입하고 React 컴포넌트에서 직접 제어한다.
- Rationale: 기존 React/Vite 구조에 별도 React wrapper 없이 사용할 수 있고, DOM 요소 강조·단계 이동·건너뛰기·완료·키보드 상호작용을 제공한다. 서버 API나 업무 데이터 모델을 추가하지 않아 기존 업무 로직과 결합이 낮다.
- Alternatives considered: 직접 구현한 overlay는 위치 계산, 포커스, 반응형, 키보드 접근성을 직접 관리해야 하므로 유지보수 위험이 더 크다.

## 화면별 진입점

- Decision: 공통 온보딩 실행기를 만들고, 로그인 화면과 인증 후 공통 `Header`에서 각각 도움말 버튼을 연결한다.
- Rationale: 미지원 화면에서도 동일한 도움말 아이콘과 안내 메시지를 제공해야 한다. 투어 정의와 화면별 버튼 위치를 분리하면 로그인 템플릿 변경이 온보딩 엔진에 영향을 주지 않는다.
- Alternatives considered: 화면별로 Driver.js를 직접 초기화하면 중복과 정리 누락 가능성이 커진다.

## 진행 상태

- Decision: 초기 구현은 도움말 클릭으로만 시작하고, 완료·건너뛰기 상태는 자동 실행 조건으로 사용하지 않는다. 향후 자동 실행을 추가할 수 있도록 화면별 투어 식별자를 분리한다.
- Rationale: 사용자의 업무를 방해하지 않으며 승인일·첫 방문·기기별 상태를 판단하는 저장소 변경을 피한다.
- Alternatives considered: 가입 승인일 기반 자동 실행은 반복 노출과 다중 기기 불일치가 발생할 수 있어 후속 범위로 미룬다.
