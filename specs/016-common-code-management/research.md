# 설계 조사 및 결정

## 결정 1: 로그인 응답에 공통코드를 직접 넣지 않는다

로그인 응답은 인증 정보에 집중시키고, 로그인 성공 직후 별도의 bootstrap 조회를 실행한다. 인증 응답이 커지지 않고, 코드 갱신을 위해 재로그인하지 않아도 된다.

## 결정 2: Redux 메모리 캐시를 사용한다

일반적인 SPA 백오피스 패턴처럼 코드 목록은 전역 메모리 저장소에 정규화해 보관한다. localStorage에 저장하면 사용자 권한·코드 변경 후 오래된 값이 남을 수 있으므로 영구 저장하지 않는다.

## 결정 3: 전체 bootstrap과 부분 조회를 함께 제공한다

코드 수가 많지 않은 로그인 직후에는 전체 bootstrap이 가장 단순하고 요청 수가 적다. 특정 화면에서 신규 코드가 추가되거나 bootstrap을 선택적으로 운영할 필요가 있을 때는 `names` 부분 조회와 단일 코드 조회를 사용한다.

## 결정 4: 논리 비활성화와 서비스 검증

기존 M26 테이블의 `DATA_END_STATUS`를 사용해 참조 이력을 보존한다. DB 제약조건을 추가하지 않는 프로젝트 원칙에 따라 중복과 필수값은 서비스에서 정규화·검증한다.
