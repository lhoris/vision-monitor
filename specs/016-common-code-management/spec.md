# 공통코드 관리

기능 브랜치: `016-common-code-management`

## 개요

관리자는 공통코드 관리 화면에서 시스템 전반에서 재사용할 코드 그룹과 코드값을 등록·수정·비활성화한다. 일반 사용 화면은 공통코드 조회 API를 통해 활성 코드만 받아 애플리케이션 메모리에 보관하고, 화면의 선택 목록과 상태 표시 등에 재사용한다.

공통코드는 `TB_M26_CODE`의 마스터와 `TB_M26_CODE_DETAIL`의 상세값으로 구성한다. 데이터베이스의 관계 제약조건에 의존하지 않고, 서비스 검증으로 코드 식별자와 상세값의 유효성을 보장한다.

## 기능 요구사항

- FR-001: 관리자 권한 사용자는 관리자 메뉴에서 공통코드 관리 화면에 진입할 수 있어야 한다.
- FR-002: 화면은 공통코드 마스터 목록과 선택된 마스터의 상세 코드값 목록을 함께 제공해야 한다.
- FR-003: 관리자는 코드 식별자, 코드명, 설명, 코드 유형을 입력해 공통코드 마스터를 등록할 수 있어야 한다.
- FR-004: 관리자는 선택된 공통코드에 코드값, 표시명, 설명, 정렬순서, 기본값을 입력해 상세 코드값을 등록할 수 있어야 한다.
- FR-005: 관리자는 공통코드와 상세 코드값을 수정할 수 있어야 한다.
- FR-006: 삭제 요청은 물리 삭제 대신 `DATA_END_STATUS`를 종료 상태로 변경하는 논리 비활성화로 처리해야 한다.
- FR-007: 시스템은 공통코드 식별자, 상세 코드값, 필수 입력값의 중복·누락·형식 오류를 저장 전에 안내해야 한다.
- FR-008: 일반 조회 API는 종료 상태가 아닌 공통코드와 상세값만 반환해야 한다.
- FR-009: 로그인 성공 후 클라이언트는 활성 공통코드 전체를 bootstrap 조회 API로 가져와 메모리 저장소에 적재해야 한다.
- FR-010: 코드가 필요한 화면은 메모리 저장소를 우선 사용하고, 아직 적재되지 않은 코드만 부분 조회 API로 보충해야 한다.
- FR-011: 공통코드 관리자가 값을 변경하면 클라이언트 메모리 저장소는 bootstrap 재조회 또는 변경 결과 반영으로 최신 상태가 되어야 한다.
- FR-012: 메모리 공통코드는 브라우저 영구 저장소에 저장하지 않아야 하며 로그아웃 시 비워야 한다.
- FR-013: 공통코드 테이블에는 PK 외의 데이터베이스 제약조건을 추가하지 않아야 한다.

## 사용자 시나리오

### 공통코드 마스터와 상세값 등록

관리자가 공통코드 관리 화면에서 새 코드 그룹을 등록한다. 저장된 마스터를 선택하면 상세 영역이 활성화되고, 관리자는 여러 코드값을 추가·수정해 저장한다.

### 공통코드 비활성화

관리자가 더 이상 사용하지 않는 코드 그룹 또는 코드값을 비활성화한다. 이후 일반 조회 API와 화면의 선택 목록에는 해당 값이 나타나지 않는다.

### 로그인 후 공통코드 사용

사용자가 로그인하면 클라이언트는 공통코드 bootstrap API를 한 번 호출한다. 이후 여러 화면은 네트워크를 반복 호출하지 않고 메모리 저장소의 코드명과 코드값을 사용한다.

### 지연 조회와 갱신

화면이 bootstrap에 없는 특정 코드 그룹을 요구하면 해당 그룹만 조회한다. 관리자가 코드를 변경한 뒤 새로고침하면 메모리 저장소가 최신 목록으로 교체된다.

## 데이터 모델

### 공통코드 마스터

`TB_M26_CODE`에 코드 식별자, 이름, 설명, 유형, 비고, 공통 감사정보, `DATA_END_STATUS`를 저장한다. 논리 활성 상태는 `DATA_END_STATUS='N'`이다.

### 공통코드 상세

`TB_M26_CODE_DETAIL`에 마스터 식별자, 코드값, 표시명, 설명, 정렬순서, 기본값, 비고, 공통 감사정보, `DATA_END_STATUS`를 저장한다. 상세값은 마스터 식별자를 애플리케이션 데이터로 연결한다.

## API 원칙

- 관리자 API: 마스터와 상세값의 CRUD 및 논리 비활성화
- 일반 API: `GET /api/common-codes/bootstrap` 전체 활성 코드 조회
- 일반 API: `GET /api/common-codes/{codeName}` 단일 코드 그룹 조회
- 일반 API: `GET /api/common-codes?names=...` 필요한 코드 그룹 부분 조회
- 일반 API 응답은 화면에서 바로 사용할 수 있도록 코드 식별자, 표시명, 정렬순서, 기본값을 포함한다.

## 제외 범위

권한 정책 자체, 다국어 번역 관리, 코드값별 별도 업무 로직, 데이터베이스 FK·UNIQUE·CHECK 제약조건 추가, 서버 프로세스 간 분산 캐시는 이번 기능에 포함하지 않는다.

## 성공 기준

- 관리자는 마스터 등록 후 같은 화면에서 상세 코드값을 등록할 수 있다.
- 비활성화된 코드와 상세값은 일반 조회 결과에서 즉시 제외된다.
- 로그인 이후 동일 코드의 반복 조회가 메모리 캐시로 대체된다.
- 코드가 없는 신규 화면도 부분 조회 API만으로 필요한 목록을 얻을 수 있다.
- 코드 변경 후 새로고침하면 변경된 표시명과 정렬순서가 모든 사용 화면에 반영된다.
