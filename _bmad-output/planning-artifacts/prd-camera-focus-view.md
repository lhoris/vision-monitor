# Vision Monitor Brownfield PRD Section: 카메라 집중 보기 / 확대 보기

작성일: 2026-08-15  
문서 유형: Brownfield PRD 섹션  
대상 기능: 카메라 집중 보기 / 확대 보기

## 1. 배경 및 목표

현재 Vision Monitor의 Live 화면은 여러 카메라 영상을 Grid 형태로 보여주는 PoC 수준의 화면을 제공한다. 그러나 운영자가 특정 카메라를 선택해 대형 화면으로 실시간 영상 또는 녹화 영상을 집중 확인하고, 해당 카메라 및 이벤트 메타데이터를 함께 조회하는 기능은 아직 없다.

본 기능의 목표는 운영자가 관심 카메라를 빠르게 확대하고, 영상 맥락과 이벤트 정보를 한 화면에서 확인하며, 알람/경고 발생 시 즉시 상황을 파악하고 대응 상태를 조회할 수 있도록 하는 것이다.

## 2. 제품 경계

Vision Monitor는 다음 기능을 직접 구현하지 않는다.

- RTSP ingest
- AI inference
- Media distribution
- Server-side overlay
- 영상 인코딩/트랜스코딩
- 원본 영상 저장 및 보관

Vision Monitor는 외부 VMS, AI 시스템, Media Server가 제공하는 `streamUrl`, `playbackUrl`, 이벤트 메타데이터, 알람 상태를 받아 브라우저 UI에 표시한다.

## 3. 사용자 시나리오

### UJ-1. 실시간 카메라 집중 확인

운영자는 Live Grid 화면에서 특정 카메라를 클릭한다. 시스템은 해당 카메라의 확대 보기 화면으로 이동하거나 패널을 연다. 운영자는 좌측 대형 영상 영역에서 실시간 영상을 확인하고, 우측 메타데이터 패널에서 카메라명, 공정 구역, 설비/라인 정보, 현재 상태, 최근 이벤트 정보를 함께 확인한다.

### UJ-2. 공정 탭 기반 카메라 탐색

운영자는 상단 공정 탭 `ALL`, `가열`, `압연`, `냉각`, `시험`, `정정` 중 하나를 선택한다. 시스템은 선택된 공정에 해당하는 카메라 목록 또는 현재 확대 대상 카메라 컨텍스트를 갱신한다. 운영자는 동일 화면에서 다른 공정 카메라로 전환할 수 있다.

### UJ-3. 녹화 영상 및 이벤트 재생 확인

운영자는 확대 보기 화면에서 하위 탭을 `녹화`로 전환한다. 시스템은 해당 카메라의 녹화 영상 재생 UI, 타임라인, 이벤트 발생 목록을 표시한다. 운영자는 이벤트 목록에서 특정 이벤트를 선택해 해당 시점의 녹화 영상을 재생한다.

### UJ-4. 알람/경고 발생 시 집중 대응

특정 카메라 또는 공정에서 알람/경고가 발생하면 확대 화면 상단에 노란색 경고 배너가 표시된다. 예: `[경고!] Entry Zone 치입불 발생 중`. 우측 패널에는 제어 대응 현황, 소재 정보, 냉각 코드, 속도, 유지 시간 등 이벤트 관련 메타데이터가 표시된다. 운영자는 영상과 데이터를 함께 보고 상황을 판단한 뒤 닫기 버튼으로 경고 팝업 또는 배너를 종료할 수 있다.

### UJ-5. 이벤트 확인 후 화면 복귀

운영자는 확대 보기에서 이벤트 확인을 마친 뒤 Grid 화면으로 복귀하거나 다른 카메라를 선택한다. 시스템은 이전 Live 화면의 필터/공정 탭 상태를 가능한 범위에서 유지한다.

## 4. Functional Requirements

### FR-1. 카메라 확대 보기 진입

- FR-1.1 Live Grid의 각 카메라 카드 또는 영상 타일은 확대 보기 진입 액션을 제공해야 한다.
- FR-1.2 사용자가 카메라를 선택하면 해당 카메라의 상세 보기 화면으로 이동하거나 확대 보기 상태를 표시해야 한다.
- FR-1.3 확대 보기 진입 시 선택된 카메라의 `cameraId`를 기준으로 실시간 영상 URL과 메타데이터를 조회해야 한다.
- FR-1.4 영상 URL 또는 메타데이터 조회 실패 시 사용자가 이해할 수 있는 오류 상태를 표시해야 한다.

### FR-2. 확대 보기 화면 레이아웃

- FR-2.1 화면 상단에는 공정 탭 `ALL`, `가열`, `압연`, `냉각`, `시험`, `정정`을 표시해야 한다.
- FR-2.2 공정 탭 아래에는 하위 탭 `실시간`, `녹화`를 표시해야 한다.
- FR-2.3 좌측 또는 주 영역에는 선택된 카메라의 대형 영상 영역을 표시해야 한다.
- FR-2.4 우측에는 선택된 카메라 및 이벤트 메타데이터 패널을 표시해야 한다.
- FR-2.5 화면은 데스크톱 운영 환경 기준으로 대형 영상 확인에 충분한 비율을 유지해야 한다.

### FR-3. 실시간 보기

- FR-3.1 `실시간` 탭 선택 시 외부 Media Server가 제공한 `streamUrl`을 사용해 실시간 영상을 표시해야 한다.
- FR-3.2 실시간 영상 상태는 로딩, 재생 중, 끊김, 오류, 권한 없음 상태를 구분해 표시해야 한다.
- FR-3.3 실시간 보기 중 우측 패널에는 카메라 기본 정보와 현재 상태, 최근 이벤트 요약을 표시해야 한다.
- FR-3.4 사용자는 동일 공정 내 다른 카메라로 전환할 수 있어야 한다.

### FR-4. 녹화 보기

- FR-4.1 `녹화` 탭 선택 시 해당 카메라의 녹화 재생 UI를 표시해야 한다.
- FR-4.2 시스템은 외부 Media Server 또는 VMS가 제공한 `playbackUrl`을 사용해 녹화 영상을 재생해야 한다.
- FR-4.3 녹화 탭에는 타임라인을 표시해야 한다.
- FR-4.4 타임라인에는 이벤트 발생 시점이 시각적으로 표시되어야 한다.
- FR-4.5 이벤트 목록에는 이벤트명, 발생 시각, 심각도, 상태, 관련 공정/구역 정보를 표시해야 한다.
- FR-4.6 사용자가 이벤트를 선택하면 해당 이벤트 시각 또는 지정된 pre-roll 시점으로 녹화 영상을 이동해야 한다.

### FR-5. 알람/경고 표시

- FR-5.1 선택된 카메라 또는 연관 공정에 활성 알람/경고가 존재하면 확대 화면 상단에 경고 배너를 표시해야 한다.
- FR-5.2 경고 배너는 경고 등급, 메시지, 발생 위치, 발생 상태를 포함해야 한다.
- FR-5.3 예시 메시지 형식은 `[경고!] Entry Zone 치입불 발생 중`을 지원해야 한다.
- FR-5.4 경고 발생 시 우측 패널은 관련 이벤트 상세 정보로 갱신되어야 한다.
- FR-5.5 사용자는 닫기 버튼으로 경고 배너 또는 팝업을 닫을 수 있어야 한다.
- FR-5.6 닫힌 경고가 여전히 활성 상태인 경우, 시스템은 재표시 정책을 정의해야 한다. MVP에서는 동일 화면 세션 내 수동 닫기 상태를 유지한다.

### FR-6. 우측 메타데이터 패널

- FR-6.1 패널은 카메라 기본 정보, 공정 정보, 현재 영상 상태를 표시해야 한다.
- FR-6.2 이벤트 발생 시 패널은 이벤트 상세 정보를 표시해야 한다.
- FR-6.3 이벤트 상세에는 제어 대응 현황, 소재 정보, 냉각 코드, 속도, 유지 시간 등 제공 가능한 필드를 표시해야 한다.
- FR-6.4 외부 시스템이 특정 필드를 제공하지 않는 경우 빈 값 대신 `-` 또는 `정보 없음` 상태를 표시해야 한다.
- FR-6.5 패널은 실시간 탭과 녹화 탭에서 서로 다른 정보 우선순위를 가질 수 있어야 한다.

### FR-7. 상태 동기화 및 URL

- FR-7.1 확대 보기 화면은 `cameraId`, 탭 상태, 선택 이벤트 ID를 URL 또는 라우팅 상태로 표현할 수 있어야 한다.
- FR-7.2 사용자가 새로고침해도 가능한 경우 동일 카메라와 탭 상태가 복원되어야 한다.
- FR-7.3 Grid 화면에서 진입한 경우 뒤로가기 동작은 이전 Grid 화면으로 돌아가야 한다.

## 5. Non-functional Requirements

- NFR-1. 확대 보기 화면 최초 진입 후 주요 UI는 2초 이내 표시되어야 한다. 영상 재생 시작 시간은 외부 Media Server 성능에 의존하되 로딩 상태를 즉시 표시해야 한다.
- NFR-2. UI는 영상 URL, 이벤트 메타데이터, 카메라 정보 API 실패를 독립적으로 처리해야 한다.
- NFR-3. 영상 재생 실패가 우측 메타데이터 조회를 막아서는 안 된다.
- NFR-4. 알람/경고 배너는 운영자가 즉시 인지할 수 있도록 일반 상태와 명확히 구분되어야 한다.
- NFR-5. 화면은 최소 1920x1080 운영 모니터 환경에서 최적화되어야 하며, 1366x768에서도 핵심 정보가 접근 가능해야 한다.
- NFR-6. API 응답에는 권한 및 접근 제어 결과가 반영되어야 하며, UI는 권한 없음 상태를 명확히 표시해야 한다.
- NFR-7. 브라우저는 외부 영상 URL을 직접 표시하되, 인증 토큰 또는 서명 URL이 노출될 경우 만료 시간이 짧아야 한다.
- NFR-8. 이벤트 메타데이터는 서버 기준 시각을 포함해야 하며, UI는 표시 시각의 기준을 일관되게 유지해야 한다.
- NFR-9. 기능은 향후 다중 카메라 비교 보기, PTZ 제어, AI overlay 확장을 방해하지 않는 구조여야 한다.

## 6. Backend / API 계약 요구사항

### API-1. 카메라 상세 조회

`GET /api/cameras/{cameraId}`

필수 응답 필드:

- `cameraId`
- `cameraName`
- `processType`
- `zoneName`
- `lineName`
- `status`
- `streamUrl`
- `capabilities`

요구사항:

- API는 선택된 카메라의 실시간 재생에 필요한 `streamUrl`을 제공해야 한다.
- `streamUrl`은 브라우저에서 재생 가능한 형식이어야 한다.
- 카메라가 비활성, 점검, 권한 없음 상태일 경우 명확한 상태 코드를 제공해야 한다.

### API-2. 녹화 재생 정보 조회

`GET /api/cameras/{cameraId}/playback?from={from}&to={to}`

필수 응답 필드:

- `cameraId`
- `playbackUrl`
- `availableFrom`
- `availableTo`
- `timelineSegments`

요구사항:

- API는 요청 시간 범위 내 재생 가능한 녹화 URL 또는 세그먼트 정보를 제공해야 한다.
- 녹화 영상이 없는 구간은 UI가 표시할 수 있도록 명시해야 한다.

### API-3. 이벤트 목록 조회

`GET /api/cameras/{cameraId}/events?from={from}&to={to}`

필수 응답 필드:

- `eventId`
- `cameraId`
- `eventType`
- `severity`
- `title`
- `occurredAt`
- `status`
- `metadata`

요구사항:

- 이벤트 목록은 녹화 타임라인과 동기화 가능한 발생 시각을 포함해야 한다.
- `metadata`는 이벤트 유형별 확장 필드를 허용해야 한다.

### API-4. 활성 알람/경고 조회

`GET /api/cameras/{cameraId}/alerts/active`

필수 응답 필드:

- `alertId`
- `severity`
- `message`
- `location`
- `startedAt`
- `status`
- `relatedEventId`
- `metadata`

요구사항:

- 활성 알람이 없을 경우 빈 목록을 반환해야 한다.
- 활성 알람이 있을 경우 UI가 배너와 우측 패널을 구성할 수 있는 메시지와 메타데이터를 제공해야 한다.

### API-5. 이벤트 확인 처리

`POST /api/events/{eventId}/acknowledge`

요구사항:

- 운영자가 이벤트를 확인했음을 기록할 수 있어야 한다.
- MVP에서는 확인 처리 API가 선택 사항이며, UI 표시 전용으로 시작할 수 있다.
- 확인 기능을 제공하는 경우 `acknowledgedBy`, `acknowledgedAt`, `status`를 반환해야 한다.

## 7. Frontend 상태 및 화면 구성 요구사항

### 화면 상태

Frontend는 최소 다음 상태를 관리해야 한다.

- 선택된 공정 탭
- 선택된 카메라 ID
- 선택된 하위 탭: `실시간` 또는 `녹화`
- 영상 로딩/재생/오류 상태
- 선택된 이벤트 ID
- 활성 알람 목록
- 경고 배너 닫힘 상태
- 녹화 타임라인의 현재 재생 시각
- 우측 패널 표시 모드: 카메라 정보 / 이벤트 상세 / 알람 상세

### 화면 구성

- 상단: 공정 탭
- 하위 상단: 실시간/녹화 탭
- 좌측 주 영역: 대형 영상 플레이어
- 우측 패널: 카메라/이벤트/알람 메타데이터
- 녹화 탭 하단 또는 영상 하단: 타임라인
- 녹화 탭 보조 영역: 이벤트 발생 목록
- 알람 발생 시 최상단: 노란색 경고 배너와 닫기 버튼

## 8. MVP 범위

MVP에 포함한다.

- Live Grid에서 특정 카메라 확대 보기 진입
- 실시간 탭
- 녹화 탭
- 대형 영상 영역 표시
- 우측 메타데이터 패널
- 활성 알람/경고 배너 표시
- 경고 배너 닫기
- 녹화 타임라인 기본 표시
- 이벤트 목록 표시
- 이벤트 선택 시 녹화 재생 위치 이동
- API 실패/영상 실패 상태 표시

MVP에서 제외한다.

- RTSP ingest 직접 구현
- AI inference 직접 구현
- Media Server 구현
- 서버 사이드 overlay
- PTZ 제어
- 다중 카메라 동시 확대 비교
- 프레임 단위 정밀 분석
- 이벤트 편집/삭제
- 알람 워크플로 승인/전파
- 장기 영상 보관 정책 관리

## 9. 후속 범위

- 다중 카메라 비교 보기
- PTZ 제어 연동
- AI detection overlay 표시
- 이벤트 북마크 및 코멘트
- 이벤트 확인/조치 이력 관리
- 알람 우선순위 및 재표시 정책 고도화
- 공정별 맞춤 메타데이터 템플릿
- 키보드 단축키 기반 운영 UX
- 운영자별 화면 레이아웃 저장
- 외부 VMS deep link 연동
- WebSocket 또는 SSE 기반 실시간 알람 push

## 10. Acceptance Criteria

### AC-1. Grid에서 확대 보기 진입

Given 운영자가 Live Grid 화면을 보고 있을 때  
When 특정 카메라 타일을 클릭하면  
Then 해당 카메라의 확대 보기 화면이 열리고  
And 좌측 대형 영상 영역에 해당 카메라의 실시간 영상 로딩 상태가 표시되고  
And 우측 패널에 해당 카메라 메타데이터가 표시된다.

### AC-2. 실시간 탭 표시

Given 확대 보기 화면에 진입했을 때  
When `실시간` 탭이 선택되어 있으면  
Then 시스템은 `streamUrl`을 사용해 실시간 영상 플레이어를 표시하고  
And 영상 상태가 로딩, 재생 중, 오류 중 하나로 표시된다.

### AC-3. 녹화 탭 전환

Given 확대 보기 화면에서  
When 운영자가 `녹화` 탭을 선택하면  
Then 시스템은 `playbackUrl` 기반 녹화 플레이어를 표시하고  
And 타임라인과 이벤트 발생 목록을 함께 표시한다.

### AC-4. 이벤트 선택 재생

Given 녹화 탭에 이벤트 목록이 표시되어 있을 때  
When 운영자가 특정 이벤트를 선택하면  
Then 녹화 플레이어는 해당 이벤트 발생 시각으로 이동하고  
And 우측 패널은 선택된 이벤트 상세 정보로 갱신된다.

### AC-5. 활성 경고 배너 표시

Given 선택된 카메라에 활성 경고가 존재할 때  
When 확대 보기 화면이 표시되면  
Then 화면 상단에 노란색 경고 배너가 표시되고  
And 배너에는 경고 메시지와 발생 위치가 표시되고  
And 우측 패널에는 관련 이벤트 메타데이터가 표시된다.

### AC-6. 경고 배너 닫기

Given 경고 배너가 표시되어 있을 때  
When 운영자가 닫기 버튼을 클릭하면  
Then 경고 배너는 화면에서 사라지고  
And 동일 화면 세션에서는 사용자가 닫은 배너가 자동으로 다시 열리지 않는다.

### AC-7. API 실패 처리

Given 카메라 상세, 영상 URL, 이벤트 목록 중 하나의 API 호출이 실패했을 때  
When 확대 보기 화면이 표시되면  
Then 실패한 영역에는 오류 상태가 표시되고  
And 나머지 성공한 데이터 영역은 계속 표시된다.

### AC-8. 권한 없음 처리

Given 운영자에게 특정 카메라 접근 권한이 없을 때  
When 해당 카메라 확대 보기를 열면  
Then 영상 영역에는 권한 없음 상태가 표시되고  
And 제한된 메타데이터는 표시되지 않아야 한다.

### AC-9. 새로고침 상태 복원

Given 운영자가 특정 카메라의 확대 보기 화면을 보고 있을 때  
When 브라우저를 새로고침하면  
Then 시스템은 가능한 경우 동일 `cameraId`와 선택 탭 상태를 복원한다.

### AC-10. 제품 경계 준수

Given 확대 보기 기능이 구현될 때  
When 영상 또는 이벤트 데이터가 필요하면  
Then Vision Monitor는 외부 VMS/AI/Media Server가 제공한 URL과 메타데이터를 사용해야 하며  
And RTSP ingest, AI inference, media distribution, server-side overlay를 직접 구현하지 않는다.
